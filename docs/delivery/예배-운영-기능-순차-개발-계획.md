# 예배 운영 기능 순차 개발 계획

2026-10-16 · [설계 인덱스](../design/worship/README.md) · 설계 작성 완료 후 조건부 구현 승인

## 실행 권한과 선행 조건

사용자 지시: 7개 기능의 상세 설계가 완료되고 다른 세션의 앱 자동 업데이트 개발이 완료되면 순차 개발한다. 기능별 검증을 수행하고 UI는 심플함과 사용 편의성을 우선한다. 추가 구현 승인을 반복 요청하지 않는다. 커밋·푸시·배포는 이 지시에 포함되지 않는다.

선행 세션은 `앱 자동 업데이트 버튼 구현`(threadId `01a1402b-1c65-7a41-b19d-b9cf52d2ef64`, host local)이다. 앱 코드에 대한 개발 착수 조건은 다음과 같다.

1. 이 설계 묶음의 문서·링크·정합성 검토가 완료되어 있다.
2. 선행 세션의 최종 결과에서 자동 업데이트 구현과 로컬 검증 완료를 확인한다. idle/오래된 요약/파일 존재만으로 완료를 추정하지 않는다. 미완료·실패·사용자 확인 대기이면 앱 코드 변경은 대기한다.
3. 현재 checkout·diff·schema·공유 파일 상태를 다시 읽어 새 기준을 기록한다. 선행 세션의 변경을 덮어쓰거나 되돌리지 않는다. 기존 자동 업데이트 제한(예배 진행 중 설치 등)과 새 ServiceSession을 연결한다.
4. 선행 결과에 잔여 작업이 있으면 그 작업이 배포 외부 조건인지 개발 미완료인지 구분한다. 실제 서명/공개 서버 수용 대기만으로 로컬 완료를 부정하지 않되 핵심 설치/검증 실패를 성공으로 간주하지 않는다.

다른 세션에 메시지를 보내는 것은 별도 사용자 지시가 없는 한 하지 않는다. 상태 조회로 조건을 확인한다. 대기가 다음 실행까지 이어지면 이 채팅의 후속 자동 실행에서 같은 조건을 다시 확인한다.

## 공통 UI 수용 원칙

- 기존 콘티 화면을 중심으로 확장한다. 새 상위 메뉴 7개를 만들지 않는다.
- 기본 화면에는 제목·현재/다음 순서·핵심 실행만 표시한다. 메모·타이머·화면 정책은 펼침 상세에 둔다.
- 선택/준비/송출은 문구·위치·상태로 구분한다. 색상만으로 구분하지 않는다.
- 하나의 주 동작 버튼에 실제 결과를 쓴다. 성공·오류·저장 중 상태를 버튼과 가까이 표시한다.
- 1024×768, 1280×800, 1920×1080에서 한국어 긴 제목·빈 상태·최대 내용·오류·포커스를 확인한다. 좁은 화면은 세로 상세로 접고 중요한 동작을 가리지 않는다.
- 키보드/IME/모달의 키 소유권과 현재 앱의 송출 단축키 보호를 유지한다.
- 디자인 확인은 스크린샷과 실제 조작으로 수행한다. DOM 존재 검사만으로 UI 수용을 대체하지 않는다.

## 검증·증거와 중단 조건

각 기능의 변경에 맞는 의미 있는 단위/계약 검사를 추가한다. 테스트는 구현 코드를 그대로 재현하는 대신 불변식·실패·경합·사용자 결과를 검증한다. Electron 실행 전 임시 PROPRE_TEST_USER_DATA와 실제 app.getPath('userData') 일치를 검증하고 사용자 workspace를 입력으로 쓰지 않는다.

단계 중 lint/typecheck/관련 tests·관련 Electron·화면 확인을 수행한다. 공통 저장·출력 경로 변경 또는 최종 단계에서는 전체 회귀·build:app·bundle 검사를 수행한다. 동일 변경 없이 전체 검사를 반복하지 않는다. 실패하면 다음 기능으로 넘어가지 않고 원인을 수정한다. 실장비·실제 인쇄·서명/배포가 불가능한 경우 자동 결과와 미검증을 분리해 다음 로컬 개발을 이어갈 수 있다.

출력·저장에 회귀가 있으면 신규 기능은 숨기고 원인 수정 후 진행한다. 다른 세션이 다시 공유 코드를 편집하면 최신 diff를 비교해 겹치는 수정만 조정한다. 전체 revert/stash/reset으로 기존 변경을 제거하지 않는다. 앱 업데이트 설치가 새 ServiceSession 진행 중에 허용되지 않도록 기존 guard와 통합하는 회귀 검사를 포함한다.

증거 문서는 날짜·기능별로 `docs/quality/verification-YYYY-MM-DD-worship-*.md`에 기록한다. 기준 commit + 해당 diff, 환경, 명령, 결과, UI 캡처, 한계, 다음 단계만 남긴다. 기능 상태의 기준은 설계 인덱스이며 실장비 증거 없는 항목을 '현장 검증 완료'로 바꾸지 않는다.

## 2026-10-16 착수 기록

자동 업데이트 세션의 completed 최종 결과를 확인했다. 해당 세션은 로컬 개발·검증을 완료했고 서명 배포·실제 업데이트 설치는 미실행이다. 공통 기반 첫 작업으로 shared/service-plan.ts와 tests/service-plan.test.ts를 추가했다. 타입·계약·곡 투영/재정렬·삭제 보존·계획 시각·명시 public projection을 구현했으며 실제 Repository/스키마 이전/화면 연결은 다음 작업이다. 체크포인트를 기능 완료로 해석하지 않는다.

이 채팅에 heartbeat `propre`를 등록했다. 15분 간격 후속 실행이 이 계획을 읽고 WSP-P0의 미완료 통합부터 계속한다. 기능별 단계 완료·실패·사용자 조치가 필요한 경우만 알리고, 전체 구현·검증·문서 완료 후 후속 실행을 종료한다.
