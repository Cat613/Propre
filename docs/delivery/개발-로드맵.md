# 개발 로드맵

작성일: 2026-10-04 · 갱신: 2026-10-16 · 상태: 코드 안정화 반영 / M2 운영 확인 대기 · 기준: [제품 범위](../product/프로프리-제품-기획서.md), [검토](../review/프로프리-전체-검토-보고서.md)

기존 Phase 1~3을 새 기능 체크리스트로 반복하지 않는다. 이미 존재하는 레이어·Look·요소 편집의 일관성과 검증을 먼저 완성한다. 인력·사용 장비·정책이 미정이므로 출시 날짜나 총 개발 기간을 확정하지 않는다.

## 현재 구현·검증 상태

M0/M1의 코드 개선과 창 구분·자동 저장을 반영했다. [68개 계약/단위·14개 네이티브 검사](../quality/2026-10-04-운영-개선-후속-검증.md)와 로컬 앱 생성까지 확인했다. 물리 장비·실 API·권리·서명 설치·장시간 기준은 M2와 백로그 검증 대기에서 관리한다. 다음 표는 초기 순서와 수용 목표를 보존한다.

## 처음 완료한 문서 작업

DOC 마일스톤: 전체 검토, 기획, 추적표, 설계, 개발·QA·운영·결정·위험·양식 작성. TASK-025 / REQ-030에 해당한다. 제품 코드 수정과 배포는 포함하지 않는다.

## M0 자료·송출·신뢰 경계 안정화

목표: 잘못된 자료 저장과 화면 상태 누락을 막을 기반을 갖춘다.

| 실행 묶음 | 작업 | 선행 판단 | 종료 조건 |
| --- | --- | --- | --- |
| 환경·검사 기반 | TASK-017, TASK-018 | Electron·Node·저장소 지원 조합 선정 | 타입·핵심 자동 검사·격리 실행 진입점 재현 가능 |
| 명령·신뢰 경계 | TASK-009, TASK-012 | IPC 역할·파일 validation 계약 | 허용하지 않은 요청·파일을 기존 자료 보존 상태로 거절 |
| 자료 식별·전환 | TASK-001 | 새 발표/추가/교체·dirty 정책 | 기존 발표를 의도 없이 덮는 재현 경로 해소 |
| 공통 발행·창 준비 | TASK-002, TASK-004 | 라이브 적용·버전 계약 | 편집 적용·삭제·정렬·재연결 뒤 최신 상태 수렴 |
| 긴급 중단·오디오 | TASK-003 | 일반 지우기·전체 중단·재생 주체 결정 | 지정 범위의 화면과 실제 재생을 함께 중단 |

M0 종료 검사: TC-001, TC-002, TC-006, TC-010~013, TC-017~019, TC-022, TC-024의 해당 범위. 정책 확정, 자동 검사, 네이티브 재현을 구분해서 기록한다. M0의 코드·로컬 회귀는 반영했으며, 물리 장비·설치·운영 수용은 M2에서 별도로 판단한다.

## M1 자료·렌더링·준비 흐름 통합

목표: 기존 파일과 현재 편집 방식, 성경·미디어·미리보기를 일관된 데이터로 묶는다.

| 묶음 | 작업 | 종료 조건 |
| --- | --- | --- |
| 창·무대·미리보기 | TASK-005, TASK-019 | 실제 표시 복원, 장비 상태와 Look·광고 미리보기 일치 |
| 텍스트·캔버스·취소 | TASK-006, TASK-008, TASK-023 | 기존 자료 마이그레이션과 편집→출력→Stage 의미 일치 |
| 성경·순서 | TASK-007, TASK-013 | 잘못된 권·장 해석 제거, 실패 시 보존, 원본·순서 참조 일치 |
| 저장·미디어 이동 | TASK-011, TASK-014 | 파일·스타일·에셋 round-trip과 누락 복구 |
| 키·AI·키보드 | TASK-010, TASK-015, TASK-020 | 보호 저장 정책·전송 검토·취소·모달 키 소유권 |

M1 종료 검사: TC-003~009, TC-014~016, TC-020, TC-021, TC-023, TC-028. 다양한 기존 `.ppros` 합성 샘플, 긴 한글 텍스트·여러 요소·누락 미디어를 사용한다.

## M2 실장비·운영·릴리즈 검증

목표: 실제 지원 환경에서 설치부터 준비·진행·복구·종료까지 증거를 갖춘다.

| 묶음 | 작업 | 종료 조건 |
| --- | --- | --- |
| 자료 배포 근거 | TASK-016 | 코드·제3자·성경 자료의 출처·허용 범위 기록 |
| 종료·장애 복구 | TASK-021 | Control 재개·Renderer 장애·저장 실패 복구 검증 |
| 제품·설치 | TASK-022 | 식별자·버전·지원 환경 확정, 설치·업그레이드·롤백 결과 |
| 측정·진단 | TASK-024 | 지정 장비의 성능 측정과 자료 없는 진단 확인 |
| 현장 리허설 | 모든 관련 작업 | Main·Stage·오디오 실제 장비 + 운영자 과제 수행 |

M2 종료 검사: TC-025~029와 앞 단계 핵심 회귀 검사. [릴리즈 체크리스트](../operations/릴리즈-운영-투입-기준.md)의 설치·장비·사용자·백업 증거가 필요하다. 번들 성공만으로 종료하지 않는다.

## M3 이후 별도 기획 후보

동시에 독립된 메인·방송·로비 출력, 화면별 스타일, 고급 도형·미디어 편집, 원격 제어는 이후 필요성을 확인한다. 앱 내 업데이트와 예배 진행 타이머는 2026-10-16 로컬 구현했으므로 이 후보 목록에서 제외한다. 범용 시계·타이머 레이어와 동시 다중 출력은 별도 범위다. 현재 확정된 개발 작업이나 출시 약속으로 기록하지 않는다.

## 의존성과 작업 분할

파일 형식·텍스트 정규화는 미디어 이동·프리뷰·Stage 검사의 기준이다. IPC·창 준비 계약은 송출 동기화의 기준이다. 오디오 주체를 정하기 전에는 출력 창 수를 확대하지 않는다.

각 TASK는 [백로그](개발-작업-백로그.md)의 선행 조건과 완료 기준을 따른다. 큰 작업은 기존 ID를 유지한 채 하위 작업을 추가하고, 정책 확정·구현·검증을 분리해 상태를 기록한다. 예상 크기는 S/M/L이며 실제 일정·담당자는 배정 후 추가한다.

## 다음 실행 단위

지정 Main·Stage·음향 장비 리허설, 실제 자료 설치/업그레이드·백업·롤백, 실 계정 AI, 자료 권리·서명/공증, 장시간 부하 수용을 수행한다. 범위는 [릴리즈 기준](../operations/릴리즈-운영-투입-기준.md)과 [구현 결과](../operations/2026-10-04-운영-개선-구현-결과.md)에 있다. 독립 다중 출력 등 M3는 별도 기획으로 유지한다.

## 후속 확장 상태

AI 연결·파일 찬양 준비·콘티 보관함·웹/PDF·업데이트와 예배 기능 7개의 로컬 구현을 반영했다. [백로그](개발-작업-백로그.md)의 TASK-029~040과 [예배 개발 계획](예배-운영-기능-순차-개발-계획.md)이 개별 상태를 관리한다. 최종 예배 기능 실행 근거는 [회귀 기록](../quality/2026-10-16-큐시트-PDF-인쇄와-최종-회귀.md)이며, 다음 실행은 실제 장비·60분 타이머/절전·실제 프린터·서명 업그레이드 등 M2 수용이다.
