# 음악 병행 기능 개발 계획

작성: 2026-10-17 · 상태: v1.2 로컬 구현·검증 완료 / 실제 외부 서비스·음향 수용 대기

사용자가 선택한 로컬 음원·유튜브 뮤직 병행 범위의 단계 계획이다. [설계 인덱스](../design/music/README.md)를 상태 기준점으로 삼는다. 이번 요청은 설계이며 아래 단계는 후속 구현 계획이다.

| 단계 | 변경 범위 | 선행 | 완료 조건 |
| --- | --- | --- | --- |
| MUS-P0 | 외부 Chrome 확장·native host의 최소 검증, 실제 정책/배포 조건 조사 | 설계 | 명시적 탭 연결·대상 확인·play/pause·실제 상태·stale·정지 실패·업데이트/경로 변경 결과 기록 |
| MUS-P1 | shared/music.ts 제안 모델, schema/repository, 예배/템플릿·백업 이전 | 설계 | v4→다음 버전, plan1→2, portable3→4, 독립 복제·에셋 정리 보호·원자 실패 복구 |
| MUS-P2 | MusicCoordinator, 단일 로컬 엔진, 기존 재생·웹·F2·Look 경로 통합 | P1 | prepare/active 분리, 구간/반복/페이드, 요청 경합, 단일 소스 전환·중단 확인 |
| MUS-P3 | 공통 음악 패널, 검증된 확장 연결 UX, 상태·수동 대체 | P0 성공, P2 | 실제 재생/일시정지·연결 끊김·다중 탭·좁은 화면·키보드 전체 흐름 |
| MUS-P4 | 순서 준비 연결, 사전 점검, 내보내기/템플릿 UI, 종료·업데이트 | P3 | 순서 선택 무음·진입 준비만·stop 결과 표시, 저장/파일 왕복, 종료 실패 복구 |
| MUS-P5 | 관련 회귀·장시간 실제 서비스·실음향 수용과 운영 안내 | P4 | 수용 테스트별 증거, 배포/설치 재검증, 미수용 범위 명시 |

P0는 외부 계정 인증이 필요한 지점을 실제 계정/로그인 환경 없이는 완료로 처리하지 않는다. 격리된 개발 프로필에서 운영자가 로그인하고 실제 결과를 확인한다. 개인 계정 비밀을 자동 수집하지 않는다. 서비스 사용 조건·확장 배포 요건에 해결되지 않은 문제가 있으면 직접 제어를 지원으로 표시하지 않는다.

P0 실패여도 로컬·저장 기반 작업을 독립 진행할 수 있지만 P3의 직접 제어 완료는 막힌다. 링크 열기는 대안이며 원래 목표 완료가 아니다. 구현 시작 전에 사용자가 승인한 목표를 임의로 축소하지 않고 결과와 대안을 문서로 제시한다.

## 단계별 검증

- P0: 실제 Chrome/확장/host 버전, macOS/패키지 경로, 테스트 날짜와 성공·실패 조건 기록. 서비스 재생 권한/광고/자동재생 상태는 환경 조건으로 분리한다.
- P1/P2: 스키마·원자 저장·상태 전환 단위 검사와 가짜 adapter의 계약 검사. 가짜 성공을 실서비스 증거로 쓰지 않는다.
- P3/P4: Playwright는 일회성 PROPRE_TEST_USER_DATA를 사용하고 기능 시작 전에 app.getPath('userData')가 그 경로인지 확인한다. 실제 작업공간·운영 브라우저 프로필을 테스트에 사용하지 않는다.
- P5: 관련 검사 후 npm run verify 등 저장소 필수 검사를 실행한다. 패키지/확장 설치 시험과 물리 음향 리허설은 별도로 기록한다.

각 단계에서 코드·문서·검사 결과·남은 위험을 함께 갱신한다. 테스트를 위해 서비스를 우회하지 않는다. 실제 사이트 정책·UI가 바뀌면 P0를 다시 수행한다.

## 사전 점검 항목

로컬 원본·구간·대체 에셋 유효성은 자동 검사, 외부 연결·최신 상태·탭 대상은 연결 검사, 물리 오디오 장치/믹서/스피커·광고 여부·실제 음량은 운영자 확인이다. 전용 헤드폰 미리듣기 기능이 없으므로 시험 재생은 실제 출력으로 들린다. 리허설 확인은 곡/파일/구간/연결 대상이 바뀌면 무효화하며 과거 수동 확인을 현재 재생 보장으로 쓰지 않는다.

## v1.1 착수 전 보완 조건

[검토 기록](../review/2026-10-17-음악-병행-설계-검토.md)의 MUS-R01~10을 반영한다. P0는 실제 대상 문맥·역순/늦은 play 차단·탭 교체 pause·host helper 설치/버전까지 검증한다. P1은 활성/준비 에셋 pin과 정리·독립 참조, P2는 준비/재생 세대 분리·현재/기본 음량·Look 정책 변경·정지 장벽을 구현한다. P3는 [UI·UX 추천안](../design/music/04-UI-UX-대안과-추천안.md)의 고정 바+펼침 목록+상태 복구, P4는 순서 연결과 저장 실패 동선을 적용한다. P5 수용은 MUS-T01~30과 관련 기존 회귀를 사용한다. 미지원/미확인 상태를 재생 성공으로 표시하지 않는다.

## v1.2 구현 추적

현재 UI 기준은 [미디어 통합·중앙 미리보기](../design/music/05-미디어-통합과-송출-미리보기-구현-설계.md)다. P1/P2/P4의 저장·로컬 음악·예배/파일/템플릿/점검, P3의 미디어 통합·최소 상태 바·오류/비활성 상태, P0의 연결 확장/native helper/앱 브리지 소스를 구현했다. P0 실제 Chrome 계정/서비스·설치와 P5 물리 음향/운영자 수용은 남아 있다. 조건부 외부 UI/코드 구현을 실서비스 수용 완료로 간주하지 않는다. 앞선 개발 순서는 의존성 제안이며 현재 완료 범위는 새 실행 기록을 따른다.
