# 로컬 음원·유튜브 뮤직 병행 설계 검토와 보완

검토: 2026-10-17 Asia/Seoul · 대상: 설계 v1 → v1.1 · 상태: 문서 보완 / 기능 미구현

## 검토 판단

병행 방향, 준비/재생 분리, 외부 소리 중단 확인, 수동 대체 원칙은 유지한다. 다만 v1에는 구현 시 오동작이나 오해를 일으킬 수 있는 수명·대상·UX 계약의 빈틈이 있었다. 아래를 보완해 구현 기준을 구체화했다. 실서비스 연동·정책 적합성·실제 성능은 문서 검토로 확정하지 않는다.

## 현재 코드와 대조한 근거

- src/components/ControlPanel.tsx: 상단 AudioPlayer, 3개 리사이즈 패널, 우측 PreviewPanel 아래 도구 탭이 있어 네 번째 상시 패널은 공간 비용이 크다.
- src/components/AudioPlayer.tsx: 단일 audio 요소가 Look audio.isVisible에 따라 play/pause하며 playing 의도를 유지한다. 따라서 Look 복원 후 무재개는 현행 유지가 아닌 변경이다.
- src/store/slices/mediaSlice.ts: audioRequest 토큰과 웹 음소거는 있지만 새 공통 MusicCoordinator·외부 binding·음악 목록은 아직 없다.
- 기존 workspace-v4/휴대용3·예배 plan1은 기준으로 유지하고 새 버전은 구현 시 재확인한다. 이전 저장과 백업을 그대로 수정하지 않는다.

## 검증 범위와 남은 결정

문서 링크, MUS 요구사항/단계/수용 ID 연결, v1 설명 충돌을 검사한다. UI 예시는 합성 상태의 조작 흐름 비교이며 앱 연결·음향 증거가 아니다. Chrome content script/native host/worker 공식 문서를 재확인해 보완했다. 계정·서비스 호환성, adapter에서 늦은 play 실행 차단, 배포 확장 ID/helper 설치, 60분 재생과 물리 중지 정확도는 MUS-P0/P5에서 남는다.

MUS-P0 성공 여부가 외부 직접 제어의 가장 큰 구현 불확실성이다. 링크 열기를 목표 완료로 바꾸지 않는다. UI 추천은 운영자 리허설 전 제안으로 두며 우측 패널·큰 버튼 모드를 필수 범위로 추가하지 않는다.

## 이번 실행 검사 결과

- 음악 설계·계획·검토 문서 9개에서 상대 링크 21개와 코드 블록 닫힘을 검사했다. 수용 ID MUS-T01~30의 누락·중복 범위 오류 없이 확인했다.
- 비교 예시의 세 배치 모두에서 목록 선택 후 현재 음악 유지, 로컬 전환, 일시정지 동작을 브라우저에서 검사했다. 예시 JavaScript 오류는 없었다.
- 별도 비교 예시 검사에서 1024/736/320px 폭마다 세 배치의 가로 넘침이 없음을 확인했다. 제품의 실제 지원 최소 창 크기는 기존 설계대로 1024×768이며, 320px 검사는 채팅 비교 화면의 반응형 확인이다.
- 외부 연결 끊김 상태를 주입해 전환 보류·수동 정지 확인 전 버튼 비활성·확인 후 대체 상태 전환을 세 배치에서 확인했다. 넓은 화면과 좁은 화면 캡처를 시각 확인했다.
- 렌더용 기본 Playwright Chromium 실행물이 없어 설치된 Chrome을 사용했다. 초기 실행 오류 뒤 Chrome으로 비교 예시 검사를 완료했다. 앱 Electron 검사·실제 브라우저 음악 제어·정책 수용·음향 측정은 실행하지 않았다.
