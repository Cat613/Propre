## 종합 판단

ProPre에는 가사·성경 준비, 라이브러리·순서 관리, 요소 편집, 레이어 송출, Main·Stage 창 제어의 기반이 있다. **기능 확대 전에 자료 식별·보존과 화면 상태 일치를 안정화해야 한다.** 타입 검사와 격리 번들 생성은 통과했지만, 상태 처리·성경 파싱 25개 표본 중 15개가 기대와 달랐다. 이는 전체 테스트 통과율이 아니라 특정 위험 경로를 확인한 결과다.

현재 코드를 안정적인 현장 배포 상태로 판단할 증거는 부족하다. 설치 패키지, 실제 Electron 창, 실장비 다중 모니터, 실제 운영자 리허설, 백업 복원은 이번에 확인하지 않았다. 상세 실행 결과는 [검증 기록](../quality/2026-10-04-검증-실행-기록.md)에 있다.

## 검토 범위와 증거

- 루트 문서 4개, 패키지·잠금·빌드 설정, Electron 메인·preload, 도메인 타입, Zustand 각 slice·동기화 helper, 성경·AI 서비스, 편집·송출·미디어·설정 UI의 구현을 검토했다.
- 소스의 동작과 데이터 흐름을 정적으로 대조하고, 위험 경로는 실제 소스를 메모리에서 실행해 확인했다. IPC·저장소는 합성 데이터로 대체했다.
- 앱·Electron 소스 묶음은 7,132줄이다. 성경 JSON·CSS·빌드 설정은 이 줄 수에서 제외했다. 성경 데이터는 31,089개 키, 5,119,699바이트다. 원문 정확성·완전성·배포 권리는 검사하지 않았다.
- 기존 `dist-electron`의 사용자 변경은 보존했다. 검증 빌드는 임시 사본에서 수행했다.
- 아래 `코드 확인`은 화면에서 재현했다는 뜻이 아니다. `격리 재현`도 실제 프로젝터·오디오 장비의 동작을 증명하지 않는다.

## REV-001 발표 식별 유지와 원본 덮어쓰기 — P0

코드 확인 + 격리 재현. [BiblePanel](../../src/components/BiblePanel.tsx)의 검색과 [LibraryPanel](../../src/components/LibraryPanel.tsx)의 단일 파일 가져오기는 `setSlides`만 호출한다. [editorSlice](../../src/store/slices/editorSlice.ts)의 L198은 발표 ID·제목을 바꾸지 않는다. [librarySlice](../../src/store/slices/librarySlice.ts)의 저장은 그 ID를 그대로 사용한다.

기존 발표를 연 상태에서 새 목록을 적용하고 저장하는 메모리 재현에서 `original` ID와 `Original` 제목으로 새 내용이 저장됐다. 현재 자료 종류와 이름이 서로 어긋나 원본을 덮을 수 있다. 미저장 플래그와 발표 교체·종료 보호도 확인되지 않았다.

새 자료/추가/교체를 별도 명령으로 구분하고 자료 식별·저장 결과·미저장 보호를 함께 처리한다. 관련: REQ-001, REQ-002, REQ-006 / TASK-001 / TC-001, TC-002, TC-006.

## REV-002 편집 액션별 송출 동기화 누락 — P0

격리 재현. `setActiveSlide`와 `batchDeleteSlides`는 Output 2회(Main·Chroma 설정 각각), Stage 1회 메시지를 보냈다. 단일 `deleteSlide`, `setSlides`, `reorderSlides`는 메시지를 보내지 않았고 `updateSlide`는 Output만 갱신했다. [editorSlice](../../src/store/slices/editorSlice.ts) L198~242가 근거다.

## REV-003 모두 지우기·오디오의 범위 불일치 — P0 정책·구현 과제

코드 확인 + 격리 재현. [mediaSlice](../../src/store/slices/mediaSlice.ts)의 `clearAll`은 `activeProps`를 유지한다. 고정 안내 1개를 넣은 뒤 모두 지우기를 실행해도 1개가 남았다. [AudioPlayer](../../src/components/AudioPlayer.tsx)는 Store의 `activeAudio`와 별개로 `<audio>`를 제어해 Store의 전체 지우기로 소리가 멈추는 경로가 없다. 미디어 탭에서 컴포넌트가 사라지는 수명도 재생과 연결된다.

고정 로고 유지가 의도인지 아직 미확정이다. 따라서 props 잔존은 정책 차이로 기록하며 무조건 삭제 버그로 단정하지 않는다. 다만 전체 화면·오디오 긴급 중단을 제공하려면 재생 주체와 버튼 범위를 명확히 해야 한다. 관련: REQ-011, REQ-012 / TASK-003 / TC-011, TC-012.

## REV-004 창 재생성 후 최신 상태 전달 없음 — P0

코드 확인. [main](../../electron/main.ts)의 창 생성·디스플레이 변경과 [OutputDisplay](../../src/components/OutputDisplay.tsx), [StageDisplay](../../src/components/StageDisplay.tsx)의 수신 등록 사이에 준비 확인·현재 스냅샷 요청·로드 완료 재발행이 없다. 메시지를 받을 준비가 되기 전 상태가 바뀌거나 창을 다시 열면 다음 사용자 액션 전까지 빈 화면 또는 오래된 상태가 될 가능성이 있다.

Main이 최신 상태를 보관하고 Renderer 준비 확인 뒤 전체 상태를 전달하도록 한다. 동작 재현은 네이티브 통합 검사로 보강해야 한다. 관련: REQ-013 / TASK-004 / TC-013.

## REV-005 Stage 활성 복원과 장비 누락 — P1

## REV-007 공백 없는 성경 검색의 권·장 오해석 — P1

격리 재현. [bibleParser](../../src/utils/bibleParser.ts)의 권 이름 정규식이 숫자까지 탐욕적으로 소비한다. `창10:1`은 권 null·장 0, `시119:1`은 권 null·장 9, **`요12:1`은 요한복음 12장이 아닌 `요1` 2장으로 해석됐다.** 공백을 넣은 표본은 통과했다.

장 0과 역방향 범위도 파서에서 유효한 권 ID를 반환한다. BiblePanel은 장 0을 추가로 거절하지만 역범위·존재하지 않는 장·절은 빈 목록으로 현재 자료를 바꿀 수 있다. 권 이름 해석과 범위·실제 존재 검증을 분리한다. 관련: REQ-007 / TASK-007 / TC-007.

## REV-008 Undo는 존재하지만 송출·히스토리 경계 검증 부족 — P1

격리 재현 + 코드 확인. [store](../../src/store.ts)에 Zundo와 50단계 히스토리가 있고 [useHotkeys](../../src/hooks/useHotkeys.ts)에 Undo/Redo가 있다. Undo로 내용이 `A`로 복원되어도 Output·Stage 메시지는 각각 0회였다.

히스토리는 `slides`, `globalSlideStyle`만 추적하고 발표 ID·선택·라이브 스냅샷을 함께 복구하지 않는다. 추가 검사에서 A 편집→B 전환→두 번 Undo를 실행하자 ID는 B인데 A의 슬라이드가 복원됐다. 선택 변경 51회 뒤에는 히스토리 50개가 모두 소비되어 50번 Undo를 해도 원래 내용 A로 돌아가지 못했다. 동등한 콘텐츠 상태를 건너뛰는 비교와 발표별 경계가 필요하다. 관련: REQ-004, REQ-010 / TASK-008 / TC-004.

## REV-009 Electron·IPC 신뢰 경계 미완성 — P0

코드 확인. [main](../../electron/main.ts) L39·87·140에서 `webSecurity: false`를 사용한다. [preload](../../electron/preload.ts)는 일부 send/on 채널을 제한하지만 범용 `invoke(channel, ...args)`는 제한하지 않는다. Main 핸들러에는 발신 창·프레임·역할 검증이 없다. [index.html](../../index.html)에 CSP가 없고 탐색·새 창 제한도 확인되지 않았다.

이는 경계 약화의 근거이며 실제 원격 공격·전체 파일시스템 유출을 재현했다는 뜻은 아니다. 로컬 파일 접근을 미디어 ID 허용 목록으로 제한하고 창 역할별 IPC 권한을 둔다. 경로를 그대로 붙이는 커스텀 프로토콜은 충분한 해결책이 아니다. Electron도 webSecurity 유지와 IPC 발신자 검증을 권고한다. [공식 보안 지침](https://www.electronjs.org/docs/latest/tutorial/security)

관련: REQ-016, REQ-018, REQ-019 / TASK-009 / TC-016, TC-018, TC-019.

## REV-010 키 암호화 도입 후에도 평문 fallback·권한 문제 — P1

코드 확인. [main](../../electron/main.ts) L399~425는 safeStorage 암호화를 사용하지만 보호 저장이 없으면 평문 fallback에 쓴다. 암호화 경로로 바뀔 때 기존 fallback을 지우는 로직도 없다. 같은 preload·Store가 모든 창에서 초기화되고 [settingsSlice](../../src/store/slices/settingsSlice.ts)는 키 원문을 가져온다.

키를 실제로 읽거나 노출하지 않았다. 보호 저장 불가 시 세션 사용을 안내하고 키 사용을 Main의 제한된 AI 명령으로 이동하는 방향을 제안한다. Linux에서는 저장 backend의 보호 의미도 확인해야 한다. [safeStorage 공식 문서](https://www.electronjs.org/docs/latest/api/safe-storage)

관련: REQ-020 / TASK-010 / TC-020.

## REV-011 내보내기·저장 범위와 복구 계약 부족 — P1

코드 확인. [LibraryPanel](../../src/components/LibraryPanel.tsx)의 단일 내보내기는 `{title, slides}`, 전체 내보내기는 `{type:'library', data:library}`다. 전역 스타일·프리셋·순서·미디어 파일을 함께 담지 않는다. 자료에는 로컬 절대 파일 URL이 들어갈 수 있다. [main](../../electron/main.ts)의 파일 저장은 대상에 직접 `writeFile`하며 실패 복원 절차가 없다.

앱 데이터로 복사하는 미디어 선택 기능은 있으나 다른 컴퓨터로 옮겨도 재생된다는 보장은 없다. 버전 있는 문서·미디어 목록·검증·원자적 교체·복원 범위를 정의한다. 관련: REQ-003, REQ-016 / TASK-011 / TC-003.

## REV-012 중첩 데이터·병합·실패 결과 검증 부족 — P1

코드 확인. electron-store schema는 라이브러리·순서의 배열 여부만 검증한다. 가져오기도 `Array.isArray` 중심이며 항목·요소·ID·URL은 검증하지 않는다. 동일 ID 병합은 기존 발표를 바로 바꾼다.

`importPresentations`는 오류를 잡고 정상 반환하므로 호출부가 성공 토스트를 추가할 수 있다. 저장 실패 시 생성된 발표 ID가 이미 바뀌고 순서는 먼저 UI를 변경한 뒤 저장하며 실패 복귀 처리가 없다. typed IPC는 런타임 검증을 대체하지 않는다. 관련: REQ-017, REQ-019 / TASK-012 / TC-017.

[MediaBin](../../src/components/MediaBin.tsx)에 외부 파일 드롭 핸들러는 확인되지 않았다. 파일 선택과 발표/슬라이드 D&D를 같은 기능으로 안내하면 안 된다. 미디어 종류·영속 목록·파일별 결과·누락 복구를 제공한다. 관련: REQ-015, REQ-016 / TASK-014 / TC-015, TC-016.

## REV-015 AI 설정 진입과 요청 수명 누락 — P1

코드 확인. [ControlToolbar](../../src/components/ControlToolbar.tsx)의 `onOpenSettings`가 빈 함수여서 키가 없는 AI 버튼은 설정을 열지 않는다. `useAIExtraction`(검토 당시 경로: `src/hooks/useAIExtraction.ts`, 현재 파일은 제거됨)은 취소·타임아웃·요청 대상 발표 확인 없이 외부 전송 후 일괄 편집을 연다. 파일 읽기 오류 처리와 전송 안내도 보완이 필요하다.

모델 설정은 `gemini-3-flash-preview`인데 SettingsModal의 문구는 Gemini 1.5 Pro다. 실제 API 가용성·과금·자료 처리 조건은 검사하지 않았다. 관련: REQ-021 / TASK-015 / TC-021.

## REV-016 코드·성경 데이터 권리 근거 미확인 — P1 릴리즈 조건

코드 확인 범위에서 별도의 LICENSE 파일과 성경 데이터 출처·배포 허락 문서는 찾지 못했다. 이전 README의 MIT 표기만으로 권리 확인 완료라 판단하지 않는다. 이 검토는 법률 판단이 아니라 배포 근거가 저장소에 기록되어 있는지의 확인이다.

권리 보유자·원본 출처·허용 범위·고지 의무를 확인하고 결과를 남긴다. 관련: REQ-026 / TASK-016 / TC-026.

## REV-017 런타임 지원 조건 불일치와 감사 항목 — P1

패키지 확인 + registry 감사. Electron 28.3.3의 내장 Node는 18.18.2인데 설치된 electron-store 11.0.2는 Node ≥20, 자체 README는 Electron ≥30을 요구한다. 호스트 Node 25.2.1에서의 타입·번들 성공은 이 지원 조건 불일치를 해소하지 않는다. 실제 앱 시작 실패를 이 검사로 단정하지 않는다.

`npm audit`는 전체 39개 패키지 항목(critical 2, high 30), `--omit=dev`는 7개(critical 1, high 4)를 보고했다. 개발 의존성인 Electron이 설치 앱 런타임을 구성하므로 dev 제외 결과만으로 운영 위험을 판단하면 안 된다. 실행 도달성과 호환성 검토 후 단계적으로 갱신한다. 강제 일괄 업데이트는 이번에 수행하지 않았다. 관련: REQ-024 / TASK-017 / TC-024.

## REV-018 실행 가능한 테스트·CI 체계 부족 — P1

코드 확인 + 명령 재현. package scripts에 test·lint·독립 타입 검사가 없고 추적된 CI 정의도 없다. 기존 `node test-run.js`는 존재하지 않는 `src/services/BibleService.js`를 가져오다 `ERR_MODULE_NOT_FOUND`로 종료했다.

실제 Store·parser·파일 계약·IPC·창 생명주기를 검증하는 자동 검사와 네이티브 점검을 구축한다. 이번 임시 메모리 검사는 저장소 테스트 인프라 구축을 뜻하지 않는다. 관련: REQ-022 / TASK-018 / TC-022.

## REV-019 미리보기와 최종 렌더링 불일치 — P2

코드 확인. [PreviewPanel](../../src/components/PreviewPanel.tsx)은 화면 Look, 크로마키 상태, announcement를 적용하지 않는다. OutputDisplay는 별도로 해당 상태를 렌더링한다. 메시지 글꼴·레이아웃도 별도 구현이다. `Active` 표시가 실제 출력 창 존재·준비를 뜻하지 않는다.

최종 출력 상태 계산과 공통 합성 렌더러를 사용하고 준비 상태를 별도 표시한다. 관련: REQ-008 / TASK-019 / TC-008.

## REV-020 모달·단축키·접근성 충돌 — P2

코드 확인. `isModalOpen` setter의 호출은 확인되지 않고 ControlPanel은 SlideGrid의 모달 콜백을 연결하지 않는다. 전역 Escape는 clearAll을 실행하고 SlideGrid는 선택 해제도 처리한다. `Ctrl/Cmd+S`는 모달·입력 확인보다 먼저 실행된다. 기존 README의 Space 진행은 hook에 없다.

모달의 최상위 키 소유권, 입력·IME 보호, 포커스 복귀, 상태 문구와 버튼 이름을 통일한다. 색상 대비와 실제 보조 기술 사용은 미검증이다. 관련: REQ-023 / TASK-020 / TC-023.

## REV-021 Control 종료·Renderer 오류 복구 부족 — P2

코드 확인. Output 또는 숨은 Stage가 남아 있으면 macOS `activate`의 모든 창 0개 조건이 성립하지 않아 Control 재개가 막힐 가능성이 있다. 루트 오류 경계, Renderer 장애 복구, 초안 복원·종료 보호 경로를 확인하지 못했다.

창 역할별 종료·재개 정책과 자료 보존을 정하고 네이티브 회복 시나리오를 검증한다. 관련: REQ-025 / TASK-021 / TC-025.

## REV-022 제품 식별·설치·릴리즈 증거 부족 — P2

코드 확인. 제품 버전 `0.0.0`, 예시 appId, 혼합 제품명, mac category 중심 설정이다. Windows·Linux 배포 대상·서명·업데이트·롤백 정책과 설치 증거는 없다. electron-builder의 기본 동작 가능성과 실제 검증된 지원 범위를 구분한다.

지원 환경과 앱 식별자를 확정하고 설치·갱신·제거·백업·복원을 검사한다. 관련: REQ-027 / TASK-022 / TC-027.

## REV-023 캔버스·영상·자동 맞춤 제약 — P2

코드 확인. ScaledSlide는 좌표 값이 100 이하이면 %, 초과하면 px로 추측한다. canvasWidth·canvasHeight와 달리 실제 캔버스는 1920×1080 고정이다. image·video 요소 모두 `<img>`로 렌더링하며 선 도형은 별도 렌더링이 없다.

자동 맞춤은 기존 `content` 기반 bible 슬라이드에만 적용되고 캔버스 전체 스케일은 window resize에 의존한다. 모든 텍스트·해상도에 자동 맞춤을 보장한다고 안내하면 안 된다. 관련: REQ-028 / TASK-023 / TC-028.

## REV-024 성능·진단 기준 부재 — P2

코드 확인 + 번들 확인. 성경 검색은 매번 31,089개 항목을 순회한다. 다수 컴포넌트가 전체 Store를 구독하고 번들 JS는 약 2.84 MB, gzip 약 1.55 MB였다. 실제 시작·검색·전환 지연, 메모리·GPU는 측정하지 않았다.

사용 장비에서 기준을 먼저 측정하고 검색 색인·구독·번들 분리를 필요에 따라 적용한다. 로그는 자료 원문·개인 경로·키를 포함하지 않게 한다. 관련: REQ-029 / TASK-024 / TC-029.

## REV-025 이전 문서와 현재 구현의 차이 — P2

문서 대조. 이전 개선 보고서의 Undo·토스트·schema·announcement 상태·요소 제목·중복 발송·항상 출력 창 생성 항목은 현재 코드와 다르다. 이미 도입된 기반과 남은 통합 문제를 구분해야 한다.

이번에 기준 문서·요구사항·백로그·검증·운영·결정 기록·양식을 Markdown으로 연결하고 루트 문서에 이전 기록 표시를 추가했다. 관련: REQ-030 / TASK-025 / TC-030. 문서 완료가 다른 REV의 해결을 뜻하지 않는다.
