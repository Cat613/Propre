# ProPre 설치하고 새 버전 올리기

**앱을 쓰는 사람은 설치 파일을 받아 교체하고, 배포하는 사람은 GitHub에 파일 두 개를 올리면 됩니다.** Apple 유료 개발자 가입은 필요 없습니다.

- 앱을 설치하거나 업데이트하려면 **1번**을 보세요.
- 다른 사람에게 새 버전을 나눠주려면 **2번**을 보세요.

**GitHub에 “There aren’t any releases here”라고 나오나요?** 아직 설치 파일을 한 번도 공개하지 않았다는 뜻입니다. 코드를 저장소에 올려도 설치 파일이 자동으로 생기지는 않습니다. 배포하는 사람은 **2번부터 진행**하세요. 첫 공개가 끝나면 사용자가 1번 순서로 받을 수 있습니다.

## 1. 앱을 설치하거나 업데이트하기

### 처음 설치할 때

1. [ProPre 배포 페이지](https://github.com/Cat613/Propre/releases)를 엽니다. 공개된 버전이 있어야 아래 설치 파일이 보입니다.
2. **Assets(첨부 파일)**에서 이름이 `.dmg`로 끝나는 파일을 받습니다. 예: `ProPre-0.1.1-arm64.dmg`.
3. 받은 파일을 두 번 클릭해 엽니다.
4. **ProPre 아이콘을 Applications(응용 프로그램) 폴더로 드래그**합니다.
5. 응용 프로그램 폴더에서 ProPre를 실행합니다.

`arm64`는 M 시리즈 칩이 있는 Mac용, `x64`는 Intel Mac용입니다. 자신의 Mac에 맞는 파일을 받으세요. `Source code`라고 적힌 파일은 설치 파일이 아닙니다. 설치 파일이 보이지 않으면 아직 공개 배포가 준비되지 않은 상태일 수 있습니다.

### 새 버전으로 바꿀 때

1. ProPre 화면 아래의 **업데이트 확인**을 누릅니다.
2. **v버전 다운로드**가 나타나면 누르고, 안내 창에서 **설치 파일 받기**를 누릅니다.
3. 브라우저에서 파일을 모두 받을 때까지 기다립니다.
4. **예배와 송출을 마친 뒤**, ProPre의 **자동 저장됨** 표시를 확인하고 앱을 종료합니다.
5. 받은 `.dmg`를 열고, ProPre를 응용 프로그램 폴더로 다시 드래그합니다. 기존 앱을 바꿀지 물으면 **대치**를 선택합니다.
6. ProPre를 다시 열고 화면 아래의 버전이 바뀌었는지 확인합니다.

기존 찬양·콘티·설정은 앱 파일과 다른 곳에 저장됩니다. **앱만 교체하고, 기존 자료 폴더는 삭제하지 마세요.** 자동 저장 실패가 표시되면 저장 문제를 해결하거나 백업한 뒤 종료하세요.

업데이트 버튼이 없는 구버전을 쓰고 있다면, 처음 설치할 때처럼 다운로드 페이지에서 새 파일을 받아 교체하면 됩니다.

### Mac에서 실행을 막으면

배포자가 제공한 원본 파일인지 확인한 뒤 다음 순서로 진행하세요.

1. ProPre를 한 번 실행해 봅니다.
2. Mac의 **시스템 설정 → 개인정보 보호 및 보안**을 엽니다.
3. ProPre에 대한 **그래도 열기**가 표시되면 누르고 안내에 따라 확인합니다.

Mac의 설정이나 관리 정책에 따라 이 버튼이 없을 수도 있습니다. [Apple의 실행 안내](https://support.apple.com/ko-kr/102445)를 참고하세요.

## 2. 다른 사람에게 새 버전 배포하기

**배포 파일 만들기 → GitHub에 파일 두 개 첨부하기 → 공개하기** 순서입니다. 코드를 저장소에 올리는 작업과 설치 파일을 공개하는 작업은 별개입니다.

### ① 배포 파일 준비하기

Codex에 다음처럼 요청해도 됩니다.

> ProPre 다음 버전의 무료 배포 파일을 만들어줘. 지금 배포된 버전보다 높은 번호로 준비하고, 업로드할 파일 위치를 알려줘. 아직 공개하지는 마.

준비가 끝나면 같은 폴더에서 아래 **두 파일**을 찾습니다. 아래 이름은 `0.1.0` 버전의 예시입니다.

| 올릴 파일 | 역할 |
| --- | --- |
| `ProPre-0.1.1-arm64.dmg` | 사용자가 받아서 설치할 파일 |
| `propre-update.json` | 앱이 새 버전이 나왔는지 확인하는 안내 파일 |

**두 파일을 함께 올리세요. 파일 이름과 내용은 그대로 둡니다.** 함께 만들어지는 ZIP 파일은 추가로 올려도 되지만, 위 두 파일이 있어야 현재 다운로드 안내가 작동합니다.

### ② GitHub에 두 파일 첨부하기

1. GitHub에 저장소를 관리하는 계정으로 로그인합니다.
2. **[새 릴리즈 작성 화면](https://github.com/Cat613/Propre/releases/new)**을 직접 엽니다. 배포 페이지에 버튼이 보이지 않으면 이 링크를 사용하세요. 저장소에 파일을 올릴 권한이 있는 계정이어야 합니다.
3. 아래 항목을 채웁니다. 예시의 버전 번호는 **실제로 만든 설치 파일의 버전**으로 바꾸세요.

   | GitHub 화면의 항목 | 입력할 내용 |
   | --- | --- |
   | Choose a tag | 예: `v0.1.0`을 입력하고 새 태그 만들기 선택 |
   | Target | `main` 선택 |
   | Release title | 예: `ProPre 0.1.0` |
   | Describe this release | 바뀐 내용을 짧게 입력. 예: “무료 업데이트 안내 추가” |

4. 화면 아래의 **파일 첨부 영역**에 `.dmg`와 `propre-update.json`을 끌어다 놓습니다.
5. **두 파일의 업로드가 모두 끝날 때까지 기다립니다.**

공개 전에 멈춰두려면 **Save draft**를 누르세요. 이 상태에서는 일반 사용자에게 새 버전이 공개되지 않습니다.

### ③ 공개하고 확인하기

공개 배포 전에는 [릴리즈 기준](릴리즈-운영-투입-기준.md)의 자료 이용 허락과 실제 Mac 동작 확인을 마쳐주세요.

1. **This is a pre-release**는 체크하지 않습니다.
2. **Set as latest release** 항목이 보이면 체크합니다.
3. **Publish release**를 누릅니다. 이때부터 다른 사람이 받을 수 있습니다.
4. 배포 페이지에서 `.dmg`를 직접 받아 열리는지 확인합니다.
5. 이전 버전의 ProPre에서 **업데이트 확인**을 눌러 새 버전 안내가 나오는지 확인합니다. 앱을 교체한 뒤에는 자료·콘티·설정도 확인하세요.

태그·제목·설치 파일의 버전은 맞춰주세요. 예를 들어 처음이 `0.1.0`이었다면 다음에는 `0.1.1`처럼 번호를 올려야 합니다. **같은 번호로 다시 올리면 앱은 새 버전으로 알리지 않습니다.**

GitHub 버튼의 공식 설명은 [릴리즈 만들기 안내](https://docs.github.com/en/repositories/releasing-projects-on-github/managing-releases-in-a-repository)를 참고하세요.

## 자주 막히는 곳

| 상황 | 확인할 것 |
| --- | --- |
| GitHub에 릴리즈나 설치 파일이 없어요 | 아직 첫 배포 전입니다. 위의 2번 순서로 설치 파일을 준비하고 새 릴리즈 작성 화면에서 두 파일을 첨부해 공개하세요. |
| 앱에 새 버전이 안 나타나요 | 기존보다 버전 번호가 높은지, 정식 최신 릴리즈로 공개했는지, `propre-update.json`도 첨부했는지 확인합니다. 앱에서 업데이트 확인을 다시 누릅니다. |
| 다운로드가 안 돼요 | 같은 릴리즈에 `.dmg`도 올렸는지, 파일 이름을 바꾸지 않았는지 확인합니다. |
| GitHub에 새 릴리즈 만드는 버튼이 없어요 | 저장소에 파일을 올릴 권한이 있는 GitHub 계정으로 로그인했는지 확인합니다. |
| 앱이 알아서 교체되지 않아요 | 현재 무료 방식은 다운로드 후 사용자가 앱을 종료하고 직접 교체하는 방식입니다. 위의 1번 순서를 따르세요. |

<summary>직접 터미널로 배포 파일을 만들고 싶다면</summary>

이 프로젝트 폴더의 터미널에서 실행합니다. 처음 한 번은 의존성을 설치해야 합니다.

```bash
npm ci
```

현재 버전 그대로 파일을 만들 때:

```bash
npm run package:free
```

다음 버전 번호를 올려서 만들 때:

```bash
npm version patch --no-git-tag-version
npm run package:free
```

완료되면 프로젝트의 `release/버전번호/` 폴더를 여세요. 예를 들어 `0.1.1`이면 `release/0.1.1/`입니다. 이 명령은 파일만 만들고 GitHub에 올리지는 않습니다.

현재 빌드한 Mac에 맞는 설치 파일이 만들어집니다. Intel Mac용 파일도 배포하려면 별도 빌드와 동작 확인이 필요합니다. 다른 다운로드 주소를 쓰는 설정 등은 [상세 설계](../engineering/프로프리-앱-업데이트-설계.md)를 참고하세요.

공개 배포용 확인 자료를 갖춘 뒤에는 `npm run release`로 자료 확인과 전체 검사를 거쳐 같은 무료 배포 파일을 만들 수 있습니다. 확인 자료는 [릴리즈 기준](릴리즈-운영-투입-기준.md)에 설명돼 있습니다.

</details>
