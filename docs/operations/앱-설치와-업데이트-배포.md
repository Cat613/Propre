# 앱 설치와 업데이트 배포

2026-10-16 · 현재 방식: Apple 유료 멤버십 없이 새 버전 확인 → 브라우저 다운로드 → 수동 앱 교체. [설계](../engineering/프로프리-앱-업데이트-설계.md), [무료 방식 검증](../quality/2026-10-16-무료-다운로드-업데이트-검증.md).

## 사용자

DMG를 열고 ProPre를 Applications(응용 프로그램) 폴더에 설치한다. 새 버전이 게시되면 앱 실행 시·4시간 간격으로 확인한다. 컨트롤 하단의 `업데이트 확인`으로 즉시 확인할 수도 있다.

`v버전 다운로드` → 교체 방법 확인 → `설치 파일 받기`를 누른다. 기본 브라우저에서 파일을 받으므로 완료 여부는 브라우저에서 확인한다. 예배/송출을 마치고 자동 저장 상태를 확인한 뒤 ProPre를 정상 종료한다. DMG에서 새 ProPre를 Applications에 드래그해 기존 앱을 교체하고 다시 실행해 하단 버전을 확인한다. 기존 자료 폴더는 삭제하지 않는다. 자동 저장 실패 상태에서는 오류를 해결하거나 백업한 뒤 종료한다.

다운로드 안내를 여는 동작이 예배/송출/오디오를 중단하지 않는다. 앱이 자동 설치·재시작하거나 브라우저 다운로드 완료를 판정하지 않는다. 네트워크 오류는 연결 복구 후 다시 확인하며 브라우저 요청 실패는 다운로드를 재시도한다. 무료 방식이 없는 기존 버전은 첫 무료 배포본까지 직접 받아 교체해야 한다.

서명·공증 없는 배포본은 macOS에서 실행 경고가 발생할 수 있다. 신뢰할 수 있는 원본을 받았을 때 OS가 제공하는 시스템 설정 → 개인정보 보호 및 보안 → 실행 허용 안내를 확인한다. 관리형 Mac 등 환경에 따라 허용되지 않을 수도 있다. 이 흐름과 새 버전 수동 교체는 실제 다운로드한 Mac에서 별도 확인해야 한다. [Apple 실행 안내](https://support.apple.com/ko-kr/102445).

## 배포 파일 만들기

기본 위치는 현재 공개 저장소 [Cat613/Propre Releases](https://github.com/Cat613/Propre/releases)다. 별도 서버와 Apple 계정은 필요 없다. 준비할 때는 아래를 실행한다.

```bash
npm run package:free
```

`release/0.1.0/`처럼 현재 package 버전 폴더에 DMG·ZIP·`propre-update.json`이 만들어진다. 앱 내부에 해당 저장소의 JSON 확인 주소를 넣으며 생성 명령은 GitHub에 업로드하지 않는다. macOS의 빌드 머신 CPU(arm64/x64)용 파일을 생성한다. 다른 CPU를 지원하려면 해당 빌드·실행 검증도 필요하다.

다른 HTTPS 배포 위치를 쓴다면 다음처럼 지정한다.

```bash
PROPRE_UPDATE_URL='https://downloads.example.org/propre/' npm run package:free
```

위 주소는 예시다. URL에는 비밀번호·토큰·query를 넣지 않는다. 파일명과 manifest의 DMG 주소는 바꾸지 않는다. 동일 버전의 다른 CPU 빌드를 같은 출력 폴더에서 생성하면 manifest에 기존 CPU 항목을 합친다. 다른 머신에서 빌드했다면 각 결과의 `downloads` 항목을 합치고 모든 링크를 검증한다.

## 새 버전 올리기

1. 변경을 검증하고 package/lock 버전을 함께 올린다. 예: `npm version patch --no-git-tag-version`.
2. 공개 배포 전에는 기존 `release-evidence/`의 코드·성경 권리와 플랫폼 수용을 실제 근거로 채운다. Apple 서명 증거는 무료 배포의 필수 조건에서 제외했다. `npm run release`는 이 증거 검사 → 전체 verify → 무료 패키지 생성 순서다.
3. GitHub Releases에 버전 태그의 draft를 만든다. 생성한 DMG와 ZIP, `propre-update.json`을 첨부한다. 태그/제목/파일/manifest의 버전이 일치해야 한다.
4. DMG 링크를 준비한 뒤 manifest가 연결되도록 정식 latest release로 공개한다. 단일 폴더 호스팅이면 DMG 먼저, `propre-update.json`을 마지막에 교체한다.
5. 이전 무료 버전 앱에서 발견 → 링크 열기 → 브라우저 다운로드 → 정상 종료 → 앱 교체 → 새 버전 실행/자료·예배·설정 보존을 확인한다.

정식 버전 숫자가 높아야 업데이트가 표시된다. 같은 `0.1.0`을 다시 올려도 기존 `0.1.0`에 새 버전으로 표시되지 않는다. 오배포는 더 높은 버전으로 수정하며 저장 형식을 읽지 못하는 구버전으로 자료를 되돌리지 않는다. 이번 구현/파일 준비는 실제 공개 게시나 권리/현장 수용을 대신하지 않는다.
