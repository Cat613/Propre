# 플레이리스트 파일 저장·불러오기

갱신: 2026-10-16 · 곡 파일·예배 파일 구분 · REQ-036/038 · TASK-031/033 · ADR-013/015

왼쪽 위 **현재 콘티 → 더 보기**에서 **파일로 저장**, **새 콘티로 불러오기**, **현재 콘티에 추가**를 사용합니다. 여러 콘티를 파일 이름으로 구분해 보관하고 다른 ProPre에서 불러올 수 있습니다. 앱 안의 여러 콘티는 [콘티 보관함](예배별-콘티-보관-편집.md)에서 관리합니다.

## 저장하기

1. 찬양 목록에서 필요한 곡을 플레이리스트에 넣고 순서를 정합니다. 같은 곡을 여러 번 넣을 수 있습니다.
2. **파일로 저장**을 누릅니다. 대기 중인 편집을 자동 저장한 다음 파일을 만듭니다.
3. 원하는 이름과 위치를 선택합니다. 예: `주일예배-2026-10-11.ppros`.

파일에는 플레이리스트의 곡 순서, 각 곡의 가사·슬라이드·파트 태그와 색상·자료 스타일·사용하는 포함 미디어가 들어갑니다. 같은 곡의 반복 순서는 모두 보존하지만 곡 본문은 한 번만 담습니다. 플레이리스트가 비어 있으면 저장 버튼이 비활성화됩니다. 저장한 파일은 그 시점의 사본이며 이후 앱에서 수정해도 파일은 자동 갱신되지 않습니다. 변경한 콘티는 다시 저장합니다.

## 불러오기

1. 콘티 더 보기의 **새 콘티로 불러오기**를 누르고 플레이리스트 `.ppros` 파일을 고릅니다.
2. 확인창에서 적용할 곡 순서를 읽습니다. 50개를 넘는 순서는 앞의 50개와 총 개수를 표시합니다.
3. **불러오기**를 누르면 각 곡은 찬양 목록에 저장되고, 이름/날짜와 독립 사본을 가진 새 콘티로 보관됩니다. 새 콘티의 순서가 적용되며 기존 콘티는 보관함에 남습니다.

찬양 목록의 곡과 제목·본문·슬라이드 구성·색상·스타일이 같으면 기존 곡을 재사용합니다. 같은 제목이어도 내용이 다르면 새 자료로 보관하므로 기존 가사를 덮어쓰지 않습니다. 같은 파일을 다시 불러오면 찬양 목록의 동일 곡과 포함 미디어를 재사용하고 새 콘티의 사본은 독립적으로 만듭니다. 결과 안내에서 새 곡과 재사용 곡 개수를 확인합니다.

현재 열어둔 곡과 송출 본문·배경·화면은 유지됩니다. 가져온 곡을 편집하려면 찬양 목록이나 플레이리스트에서 선택합니다. 다른 곡 선택과 송출은 기존 앱 동작을 따릅니다. 콘티 사본은 저장한 자료 스타일을 사용합니다. 찬양 목록의 원곡을 선택하면 기존 기본 프리셋 정책을 적용합니다.

## 취소와 오류

파일 선택이나 순서 확인에서 **취소**하면 플레이리스트와 찬양 목록을 바꾸지 않습니다. 형식 오류·누락 또는 손상된 미디어·저장 실패·중간에 변경된 순서는 전체 적용을 거절합니다. 곡만 일부 저장되고 순서가 빠지는 상태를 만들지 않습니다. 오류 안내를 확인한 후 파일이나 저장 공간을 점검하고 다시 시도합니다.

플레이리스트는 가사·미디어를 포함한 파일 전체 200MB, 미디어 한 개 100MB까지 지원합니다. 큰 콘티는 나누어 저장합니다. 누락된 등록 미디어는 기존 설정의 다시 연결 기능으로 복구한 후 저장합니다.

개별 자료 파일은 찬양 목록의 **파일 → 프로젝트 불러오기**, 전체 작업 공간은 **전체 백업·복원**을 사용합니다. 플레이리스트 파일은 플레이리스트의 불러오기 버튼을 사용합니다. 플레이리스트 파일에는 전체 찬양 목록, 설정, API 키, AI 연결 정보, 현재 작업본과 송출 상태가 포함되지 않습니다.

검증 근거는 [실행 기록](../quality/2026-10-05-플레이리스트-파일-저장-불러오기-검증.md)을 확인합니다.

희망한 곡을 기존 순서 끝에 넣으려면 `현재 콘티에 추가`를 선택합니다. 현재 콘티와 기존 항목을 유지하며 새 곡 사본을 추가합니다. 기도·설교·시간·담당자·운영 메모·웹/PDF 연결까지 옮길 때는 `예배 전체로 저장 / 예배 파일 불러오기`를 사용합니다. 곡 파일에는 이러한 비곡 정보가 포함되지 않습니다. [예배 파일 사용 안내](예배-전체-순서-사용-안내.md)를 확인합니다.
