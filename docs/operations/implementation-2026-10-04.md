2026-10-04 · 제품 0.1.0 · 기준 `develop / 3f625e3` 이후 로컬 변경 · 공개 배포 없음

후속 보완: 사용자 개발 실행의 검은 화면을 재현하고 개발 CSP·시작 실패 종료를 수정했다. 초기 빌드 기반 검증과 구분하여 [개발 시작 복구 검증](../quality/verification-2026-10-04-startup-recovery.md)을 추가했다.

사용자가 요청한 [운영 검토의 24개 항목](../../OPERATIONS_REVIEW.md)의 코드 개선과 자동 저장, 창 이름 구분을 구현했다. 자료·키·미디어를 다루는 권한과 저장 실패를 명확히 하고, 동일한 자료가 컨트롤·메인·모니터에 전달되도록 구조를 정리했다. 자동 검사와 macOS Electron 실행 결과는 [후속 검증 기록](../quality/verification-2026-10-04-implementation.md)에 있다. 실물 송출 장비, 사용자 리허설, 서명·공증, 자료 권리 확인은 별도 운영 확인 항목으로 남는다.

## 사용자에게 달라지는 동작

| 기능 | 최종 동작 |
| --- | --- |
| 창 구분 | `ProPre · 컨트롤`, `ProPre · 메인 송출`, `ProPre · 모니터`. 페이지 제목이 네이티브 제목을 덮지 못하며 Dock·창 메뉴에서 각 창을 선택하거나 다시 연다. |

| 자료 전환 | 새 찬양·파일 불러오기·성경 자료는 새 ID를 사용한다. 이전 자료의 저장 대기는 ID별로 유지되며 다른 자료를 덮지 않는다. 기존 자료를 다시 열면 다음 시작에서 그 자료를 복원한다. |
| 송출 | 기존 슬라이드 클릭 송출을 유지한다. 활성 슬라이드의 편집·삭제·정렬·Undo/Redo는 메인과 모니터에도 반영된다. 새 자료로 전환하면 활성 슬라이드 송출은 해제한다. |
| 전체 중단 | `모두 지우기`, F2, 모달 밖 Escape는 배경·본문·광고·고정 안내·자막·오디오를 함께 중단한다. 입력·IME·모달 내부 키는 송출 명령으로 사용하지 않는다. |
| 설정 | 프리셋·라우팅·크로마키·모니터 글자 크기·AI 모델·미디어 목록을 자동 저장한다. API 키 입력은 명시적으로 `키 등록 및 닫기`를 눌러 보호 저장한다. |

컨트롤 창만 닫으면 메인·모니터 창의 현재 표시를 유지하고 오디오는 중단한다. Dock에서 컨트롤을 다시 열 수 있다. 앱 전체를 다시 시작할 때 자료·설정·창 활성 상태를 복원하되 마지막 본문이나 소리를 자동 재송출하지 않는다.

자동 저장은 명시적 수동 저장 이전 상태를 계속 유지하는 방식으로 바뀌었다. 과거 자료로 돌아갈 때는 Undo 또는 `파일 → 직전 저장본 복구`를 사용한다. 복구와 전체 백업 복원은 현재 자료를 교체하므로 화면의 확인 절차를 따른다.

## 저장과 호환

- 앱 데이터 위치는 기존 `pro-presenter-lite` 디렉터리를 유지한다. 제품명 변경 때문에 기존 자료가 숨겨지지 않도록 했다.
- `workspace-v1.json`에 라이브러리·작업본·순서 참조·설정·미디어 등록 목록·장비 설정을 기록한다. 저장 성공은 임시 파일 기록과 교체가 끝난 뒤 확정한다.
- `.bak1`~`.bak5`는 직전 상태다. 손상 파일은 별도 보관하고 유효한 기록으로 복구한다. 유효한 기록이 없으면 원본을 덮는 저장을 중지하고 명시 복원을 제공한다.
- 기존 `config.json`은 자료 변환 후 보존한다. 보호 저장에 성공한 이전 API 키 필드는 평문 잔존을 없애기 위해 정리하며 다른 자료 필드는 유지한다.
- 과거 localStorage 프리셋은 같은 origin에서 접근할 수 있는 경우 검증 후 변환한다. 이전 `file://` 또는 개발 서버 origin에 있던 값이 새 `app://`에서 모두 자동 이전된다고 보장하지 않는다. 이전 데이터는 지우지 않는다.
- 기존 앱 미디어 폴더 안의 허용 파일은 변환한다. 폴더 밖 파일을 임의로 읽지 않으며 누락 등록으로 보관해 운영자가 `설정 → 누락 미디어 다시 연결`로 선택할 수 있다.
- 새 `.ppros`는 `format: propre-project`, `schemaVersion: 1`인 JSON이며 base64 미디어와 SHA-256 검증 정보를 포함한다. 기존 단일/라이브러리 JSON도 읽는다. API 키·개인 파일 절대 경로는 공유 파일에 포함하지 않는다.
- 작업 저장/IPC는 24MiB, 단일 등록 미디어는 100MiB, 휴대용 프로젝트/백업은 200MiB 한도를 적용한다. 초과 시 현재 자료를 유지하고 오류로 응답한다.

작업 전 문서와 기존 `dist-electron` 변경은 로컬 보존 사본을 만든 뒤 반영했다. 커밋·원격 푸시는 수행하지 않았다. 기준 소스와 변경 파일 해시는 [소스 기록](../quality/source-manifest-2026-10-04.json)에 있다.

## 운영 확인이 남은 항목

코드로 개선 가능한 경로는 반영했다. 다음 항목은 로컬 자동 검사의 통과를 실제 운영 증거로 바꿀 때 필요하다.

1. 지정 메인·무대 디스플레이의 연결/분리·배율·해상도·긴 한글 본문과 음향 장비의 중단/재개 리허설.
2. 실제 사용 자료와 이전 버전의 저장 파일로 설치·업그레이드·백업·롤백 확인. `.app` 생성은 설치·공증 완료를 뜻하지 않는다.
3. 운영자가 사용하는 Gemini 계정의 모델·오류·취소·네트워크 장애 확인. 저장된 실제 키를 이번 검증에 사용하지 않았다.
4. 코드·성경 데이터의 출처/사용 허락 근거와 배포 서명·공증 정보. 이를 임의로 만들지 않았으며 [릴리즈 기준](release-checklist.md)에서 관리한다.
5. 지정 자료 규모의 장시간 시작/검색/화면 적용 지연과 메모리 추세. 합성 테스트의 시작 시간과 프로세스 메모리를 장시간 현장 결과로 표시하지 않는다.

공식 API 적용 근거는 [Electron 보안 지침](https://www.electronjs.org/docs/latest/tutorial/security), [창 제목 변경 이벤트](https://www.electronjs.org/docs/latest/api/browser-window), [제한된 프로토콜 처리](https://www.electronjs.org/docs/latest/api/protocol), [Vite 마이그레이션](https://vite.dev/guide/migration), [Gemini 모델 안내](https://ai.google.dev/gemini-api/docs/models)다. 실제 구현·버전·동작의 근거는 저장소 소스와 실행 기록을 함께 사용한다.
