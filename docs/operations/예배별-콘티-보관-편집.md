# 예배별 콘티 보관·편집

2026-10-15 구현 기준 · REQ-038 / TASK-033 / TC-038 / ADR-015

## 새 콘티와 지난 콘티

플레이리스트에서 **콘티 보관함**을 엽니다. 왼쪽 목록에서 콘티를 선택하면 오른쪽에 예배 날짜, 곡·슬라이드 수와 전체 곡 순서가 표시됩니다. 목록 선택만으로는 현재 콘티가 바뀌지 않습니다. **콘티 열기**를 눌러 선택한 콘티를 엽니다.

왼쪽 현재 콘티 이름 아래의 **새 콘티**를 누르면 보관함 목록을 거치지 않고 생성 화면이 바로 열립니다. 보관함 안의 **새 콘티**도 계속 사용할 수 있습니다. 이름과 예배 날짜를 입력한 뒤 **빈 콘티** 또는 **현재 순서 복사**를 고릅니다. 기본은 빈 콘티이며 현재 순서 복사는 현재 곡과 순서를 독립된 사본으로 복사합니다. 복사할 곡이 없으면 복사 선택은 비활성화됩니다. 예배 날짜는 선택 사항입니다. 바로 연 생성 화면에서 **취소** 또는 Esc를 누르면 현재 콘티 화면으로 돌아옵니다.

보관함에서 콘티를 **열기**, **복제**, **이름·날짜** 변경할 수 있습니다. 다음 예배를 준비할 때 지난 콘티의 **복제**를 누르고 새 이름과 날짜를 입력해 **복제해서 열기**를 사용합니다. 복제한 곡은 원곡 및 다른 콘티와 별도로 수정됩니다. 콘티 이름·예배 날짜·포함된 곡 이름으로 검색할 수 있습니다. 최근 수정순·예배 날짜순·이름순 정렬을 지원하며 현재 콘티에 **현재** 표시가 붙습니다. **이름·날짜 변경**은 선택한 콘티 제목 옆 연필 버튼에서 열고, 저장 후 보관함에서 변경된 정보를 확인합니다. 새 콘티·복제 완료 후에는 해당 콘티로 돌아옵니다. 편집 중 Esc는 입력 화면을 닫고, 보관함에서 Esc는 보관함을 닫습니다.

콘티를 열어도 현재 편집 곡과 송출 화면은 유지됩니다. 그 콘티의 곡을 편집하려면 플레이리스트에서 곡을 선택합니다. 다른 콘티의 곡을 계속 편집하고 있다면 플레이리스트 영역의 **편집 중** 문구에서 소속을 확인합니다.

## 곡 수정과 원곡 반영

콘티의 가사·반복 슬라이드·파트 색상·자료 스타일은 자동으로 그 콘티에 저장됩니다. 찬양 목록에서 원곡을 수정하거나 삭제해도 보관한 콘티는 유지됩니다. 같은 콘티에서 같은 사본을 여러 번 배치한 반복 항목은 같은 내용을 사용합니다. 원곡을 콘티에 다시 추가하면 그 시점의 새로운 사본을 만듭니다.

콘티 곡과 원곡 모두 이 컴퓨터의 찬양·성경 기본 프리셋 설정을 따릅니다. 기본 프리셋이 없으면 저장된 자료 스타일을 사용합니다. 콘티에서 직접 프리셋이나 스타일을 변경하면 그 변경은 콘티에 저장됩니다.

콘티의 수정본을 원곡에도 반영하려면 **⋯ → 찬양 목록 원곡에 반영**을 누릅니다. 메뉴에는 반영할 편집곡 이름을 표시합니다. 확인창에서 원곡/콘티 본문과 슬라이드 수를 확인한 뒤 반영합니다. 원곡이 중간에 수정되었다면 안내하고, 확인창이 열린 뒤 수정되면 반영을 거절합니다. 다른 콘티는 그대로 유지됩니다. 연결된 원곡이 삭제되었다면 **찬양 목록에 새 곡으로 저장**을 사용합니다.

## 휴지통·파일·복구

선택한 콘티의 휴지통 버튼에서 이동 내용을 확인한 뒤 **휴지통으로 이동**을 누르면 보관 목록에서 제외합니다. 현재 콘티는 순서가 비워진다는 안내를 표시합니다. 보관함의 **휴지통 → 보관함으로 복원**으로 곡과 순서를 되돌릴 수 있습니다. 복원한 콘티를 보관 목록에서 바로 선택해 표시합니다. 현재 콘티를 휴지통으로 보내면 진행 순서만 비우며 현재 편집과 송출은 유지됩니다. 이번 버전에는 영구 삭제가 없습니다.

플레이리스트의 **⋯(콘티 더 보기) → 파일로 저장**은 현재 콘티의 이름·날짜·가사·반복·색상·스타일·미디어를 `.ppros`에 담습니다. 같은 메뉴의 **새 콘티로 불러오기**는 순서 확인 뒤 각 곡을 찬양 목록에 저장하고 새 콘티로 보관합니다. 메뉴의 **현재 콘티에 추가**는 현재 콘티의 기존 순서 뒤에 파일의 곡을 추가합니다. 기존 콘티는 보관함에 남습니다. 동일 파일을 여러 번 불러오면 콘티는 각각 독립적이며 같은 원곡/미디어는 재사용합니다. 전체 백업에는 보관함과 휴지통도 포함됩니다.

기존 데이터는 새 `workspace-v2.json`으로 자동 이전됩니다. 이전 `workspace-v1.json`은 보존됩니다. 기존 현재 순서는 **현재 콘티**라는 이름으로 보관되므로 필요하면 예배 이름/날짜를 바꿉니다. 새로운 수정은 v2와 최근 다섯 저장본에 기록됩니다. 이전 버전 앱에는 v2의 새 수정이 자동 반영되지 않습니다.

실패 시 오류 문구와 자동 저장 상태를 확인하고 다시 시도합니다. 원곡 반영 취소/버전 충돌, 보관함 저장 실패는 확인된 기존 데이터에 일부 결과를 적용하지 않습니다. 원본을 읽지 못해 저장이 차단되면 전체 백업 복원을 사용합니다. [설계](../engineering/콘티-보관함과-예배별-곡-사본.md), [검증](../quality/2026-10-06-콘티-보관함-검증-기록.md)을 참고합니다.

현재 콘티 상단은 이름·곡 수와 `새 콘티 / 보관함 / ⋯`으로 구성합니다. 예배 날짜가 있으면 이름 옆에 표시하고, 날짜 미정·중복 자동 저장 안내는 생략합니다. 파일 메뉴는 밖을 클릭하거나 Esc로 닫을 수 있으며 Esc로 메뉴만 닫을 때 송출은 유지됩니다.

## 현재 화면에서 빠르게 관리하기

- 현재 콘티 제목·날짜를 누르면 **콘티 정보 수정** 화면에서 이름과 날짜를 바꿀 수 있습니다. 저장·취소·Esc는 보관함을 거치지 않고 현재 화면으로 돌아옵니다. 곡과 순서·편집 중인 자료·송출은 유지합니다.
- 현재 콘티의 곡을 편집 중이면 상단에 같은 콘티 이름을 반복하지 않습니다. 다른 콘티·휴지통의 곡 또는 원곡을 편집할 때는 소속 안내를 유지해 편집 대상을 구분합니다.
- 원곡 반영은 **⋯** 메뉴에서 선택합니다. 원곡을 바꾸는 기존 확인과 revision 검증을 유지합니다. 연결된 원곡이 없으면 **찬양 목록에 새 곡으로 저장**을 표시합니다.
- 곡 목록은 순서·곡 이름·슬라이드 수를 한 줄에 표시합니다. `8장`은 슬라이드 8장을 의미합니다. 긴 곡 이름은 말줄임하고 hover로 전체 이름을 확인합니다.

## 2026-10-15 후속 사용성 개선

- 새 콘티는 제목을 한 번만 표시하는 작은 입력 화면이다. 이름·선택 날짜·시작 방식을 한 화면에서 정하며, 빈 콘티/현재 순서 복사를 나란히 선택한다. 보관함에서 만드는 경우에도 같은 입력을 사용한다.
- 예배 날짜는 연·월·일·오른쪽 달력 아이콘 등 입력칸 어디를 눌러도 기본 달력을 연다. 아이콘과 달력 색상은 라이트/다크 테마를 따른다. 날짜는 필수가 아니다.
- 콘티 곡에 Tab으로 접근한 뒤 Enter로 열고, Alt+위/아래 화살표로 순서를 바꾼다. 곡을 여는 동작 자체는 송출을 시작하지 않는다. 버튼·메뉴의 Space/화살표는 해당 요소의 조작에 사용한다.
- 찬양 목록의 삭제는 **찬양 휴지통**으로 이동한다. 기존 콘티의 독립 사본은 유지한다. **찬양 휴지통 → 복원**으로 되돌릴 수 있다. 현재 같은 ID의 새 찬양이 있으면 덮어쓰지 않고 충돌을 안내한다.
- 이미지·영상·오디오는 **미디어 휴지통 → 복원**으로 목록에 되돌린다. 삭제·복원은 현재 재생이나 송출을 시작/중단하지 않는다. 별도 송출 중지 버튼을 사용한다.
- 두 휴지통 모두 재시작과 전체 백업에서 유지되며, 휴지통에서 참조하는 미디어 원본은 파일 정리에서 보호한다. 이 변경 이전에 이미 영구 삭제된 항목을 자동으로 되살리는 기능은 아니다. 과거 삭제 항목은 기존 전체 백업을 확인한다.
