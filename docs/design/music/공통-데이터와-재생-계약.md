현행 구현은 로컬 파일 하나 중심이고 유튜브 뮤직 제어·음악 목록·구간 페이드가 구현된 것은 아니다. 위 경로는 조사 시점의 코드 근거이며 구현 착수 때 다시 확인한다.

## 영구 모델 제안

```ts
type LocalMusic = {
  assetId: string; startSeconds: number; endSeconds?: number;
  volume: number; loop: boolean; fadeSeconds: number;
};
type MusicItem = {
  id: string; revision: number; title: string;
  source: { kind: 'local'; local: LocalMusic }
        | { kind: 'youtube-music'; url: string; fallback?: LocalMusic };
};
type ServiceMusic = { version: 1; items: MusicItem[] };
// Setlist.music?: ServiceMusic
// CueItem.musicPreparationId?: string (같은 예배의 music.items 참조)
```

제목 1~200자, 예배별 200항목, URL 2048자, 로컬 설정은 기능 문서의 범위, volume 0~1로 검증한다. 모호한 중첩·알 수 없는 키를 거절한다. fallback은 대체 소스의 중첩을 허용하지 않는다. 전역 라이브러리·랜덤 셔플·여러 트랙 로컬 자동 재생목록은 후속이며 초기에는 준비 목록에서 수동으로 고른다.

사본 간 음악 ID와 구간 설정은 독립이다. 에셋 바이트는 해시 기반 재사용이 가능하지만 한 예배의 파일 재연결로 다른 예배 설정을 수정하지 않는다. 예배/템플릿 복제는 음악·큐 참조 ID를 새로 부여한다. 휴지통·템플릿·fallback이 참조한 에셋도 미디어 정리에서 보호한다.

## 비영구 런타임과 권한

Main MusicCoordinator가 sessionId, playbackGeneration, preparationRequestId, 연결 epoch, 전환 작업과 관리 소스 소유권을 갖는다. Control은 편집 초안·다음 준비와 로컬 HTML audio 적용을 담당한다. 렌더러 재로딩 시 Main은 미확인 상태로 바꾸고 외부 pause를 시도한다. 새 렌더러가 과거 재생을 재개하지 않는다.

상태는 연결과 재생을 독립 관리한다.

- 연결: disconnected / connecting / connected / stale / unsupported.
- 재생: idle / preparing / ready / starting / playing / pausing / paused / stopping / stopped / ended / error / unknown.
- 별도 필드: activeSnapshot, preparedSnapshot, sourceKind, requestId, playbackGeneration, preparationRequestId, sourceRevision, activePlaybackId, connectionEpoch, observedAt, position/duration(확인된 경우), capabilities, lastErrorCode.

playing 플래그와 재생 의도는 실제 관측값과 구분한다. 지속 저장에서 activeSnapshot·position·playing·탭 ID·쿠키·계정명·연결 비밀을 제외한다. 현재 위치는 세션 내에서만 유지한다. 상태 이벤트의 generation/epoch/sequence가 과거면 무시한다. pause/F2는 대기 중인 play보다 우선하고 오래된 play ACK가 다시 활성화하지 못한다.

## 명령 계약 제안

Control 전용 music-command에 requestId(UUID), action과 action별 대상 필드를 검증한다. action은 prepare/play/pause/stop/restart/fadePause/stopAll/setLiveVolume이다. prepare는 preparationRequestId와 예배/항목 revision, play는 preparedSnapshotId와 expectedPlaybackGeneration, 활성 조작은 activePlaybackId와 expectedPlaybackGeneration을 사용한다. stopAll은 현재 revision 일치를 요구하지 않는다. 설정 편집은 별도 save-service-music(expectedSetlistRevision, music) 원자 저장이다. 연결·해제는 connect/disconnect 전용 IPC로 분리한다.

로컬 엔진 지시는 Main이 등록한 Control main frame에만 보내며 applied/error 이벤트에 sessionId·generation·requestId를 요구한다. Output/Stage/임의 iframe/확장 content script는 앱 IPC를 직접 호출할 수 없다. Main은 명령 접수 accepted와 observed/applied 결과를 구분해 회신한다. 같은 requestId는 같은 결과를 돌려주며 이미 무효화된 요청은 stale로 거절한다. 재시도 시 새 play를 자동 생성하지 않는다.

외부 host는 검증된 확장의 고정 명령과 제한된 상태 데이터만 전달한다. payload 64KiB, 제목 200자, 허용 enum·ID·URL을 검증하고 과도한 이벤트를 제한한다. 전체 workspace를 브라우저로 전송하지 않는다. 로그에는 오류 코드·요청 시간·소스 종류만 남기고 URL 쿼리·계정·로컬 절대 경로·인증 정보를 기록하지 않는다.

## 예배 순서와의 연결

순서 편집에서 `음악 준비 연결`을 선택하면 제목·소스 배지를 표시한다. 큐 행 선택은 음악을 변경하지 않는다. 명시적 `이 순서 진행`이 완료되면 musicPreparationId가 있으면 다음 준비로 올리되 재생하지 않는다. audio:keep은 현재 소리 유지, audio:stop은 음악 조정자로 모든 관리 소리 중단을 요청한다. 중단 실패가 시각 순서 전환을 롤백시키지는 않으며 순서 결과에 `음악 중단 미확인`을 지속 표시한다. 새 순서 자동재생은 이번 범위가 아니다.

## 저장·이전·파일 호환

버전 제안은 workspace-v5 / portable schemaVersion 4 / ServicePlan version 2다. 구현 시 현재 버전을 재확인하고 이미 사용 중이면 다음 버전으로 조정한다. 기존 v4·휴대용3·plan1 읽기는 유지하고 music=[]와 참조 없음으로 이전한다. v1의 audio:keep/stop 의미를 바꾸지 않는다. v5 최초 기록 전에 v4와 백업 원본을 보존하고 전체 검증 성공 후 원자 저장한다. 새로운 데이터가 있어도 v4 파일에 조용히 기록하지 않는다. 구버전 앱의 읽기 가능성을 보장하지 않는다.

전체 백업·예배 단독·템플릿 형식 4는 해당 음악 설정, 유튜브 뮤직 안전 URL, 참조 로컬·fallback 에셋을 포함한다. 음악이 있는 예배만 이동해도 소스가 빠지지 않아야 한다. 단일 곡/기존 playlist 형식 1은 확장하지 않고 예배 파일 사용을 안내한다. 파일명·UI에서 음악 목록과 찬양 슬라이드 콘티를 구분한다.

가져오기는 IDs·revision·해시·모든 음악/큐/에셋 참조를 검증하고 새 ID로 원자 재매핑한다. 기존 개별 에셋 100MiB, 파일 전체 200MiB, 상태/IPC 기록 24MiB 한도를 유지하며 기준 문서 변경 없이 한도를 늘리지 않는다. 누락 파일은 누락 배지로 유지하고 재연결을 제공한다. 손상 에셋·크기 초과는 원본과 현재 상태를 보존하고 거절한다. 저장 실패 시 편집 초안·현재 음악 유지, 재시도 제공. 전체 복원 전 음악 중단은 외부 미확인 처리까지 수행한다.

새 설정을 추가하면 types/default/schema/persistentSettings/settingsChanged를 함께 갱신한다. 앱 종료/업데이트의 기존 저장·송출 보호 경로와도 통합한다. 세부 음악 정보는 청중/Stage payload로 전파하지 않는다.

## v1.1 보완: 준비 작업과 활성 재생의 수명 분리

공통 문서에서 짧게 쓴 generation은 재생 명령에서는 playbackGeneration을 뜻한다. prepare는 독립 preparationRequestId만 갱신하며 playbackGeneration·현재 재생·진행 중 페이드를 변경하지 않는다. 새 prepare는 이전 준비 결과만 폐기한다. F2/stopAll은 두 수명을 모두 무효화한다. 재생 소스 전환은 playbackGeneration을 올리고 새 activePlaybackId를 만든다.

| 상황 | 검증 기준 | 결과 |
| --- | --- | --- |
| 다음 곡 준비 응답 | preparationRequestId + 예배/항목 revision | 최신 준비에만 반영, 활성 재생 불변 |
| 준비한 항목 편집 후 재생 | preparedSnapshotId + 현재 저장 revision | 불일치면 재검사, 현재 음악 유지 |
| 재생 중 항목 편집·삭제 후 pause/stop | activePlaybackId + playbackGeneration | 저장 항목의 수정/삭제와 무관하게 활성 사본 중단 가능 |
| F2/음악 전체 중지 | 인증된 Control 권한 | revision 충돌과 무관하게 우선 중단 |
| 이전 로컬 play Promise가 뒤늦게 완료 | 엔진의 재생 세대 + activePlaybackId | 논리 결과 무시뿐 아니라 실제 요소 pause. 새 세대 요소를 잘못 멈추지 않도록 동일 엔진 인스턴스/소스 확인 |

준비는 메타데이터 검사이며 소리 없는 분석 경로를 사용한다. 재생 중인 단일 audio 요소의 src/currentTime/volume을 다음 곡 검사에 재사용하지 않는다. 관리 에셋의 읽기·길이 분석 또는 별도 비출력 디코더로 검사하고 작업별 취소·한도를 둔다. 유한 길이가 확인되지 않은 파일(NaN/Infinity/라이브 스트림)은 로컬 구간 재생 대상으로 확정하지 않는다.

## v1.1 보완: 활성 음량과 저장 설정

항목 편집 폼의 기본 음량/구간/반복은 저장 설정이며 다음 재생부터 적용한다. 고정 음악 바의 `현재 음량`은 활성 로컬 사본에 즉시 적용하는 비영구 값이다. 저장하려면 별도 `이 음량을 기본값으로 저장`을 사용하고 expectedSetlistRevision으로 충돌 검사한다. 페이드 gain과 현재 음량은 독립 값이며 사용자 음량 변경이 기존 gain을 초기화하지 않는다. 페이드 완료 후 이어 재생은 마지막 현재 음량, 새 항목 재생은 저장 기본 음량을 사용한다.

## v1.1 보완: 이벤트·정지 장벽·오류 계약

명령 구조는 action별 discriminated union으로 검증한다. 외부 명령은 sessionId, connectionEpoch, bindingId, documentEpoch, playbackGeneration, requestId, expiresInMs를 포함하고 host/worker/content adapter 모두 만료·대상·세대를 검사한다. worker에 역순 전달된 play가 최신 pause 이후 실행되지 않도록 세대별 마지막 sequence를 유지한다. 같은 세대의 중복 요청은 멱등 결과, 오래된 세대는 stale-request다. native port 재연결 시 이전 play 대기열을 폐기한다. 이 차단을 실제 외부 adapter에서 보장하지 못하면 직접 제어 지원 조건을 충족하지 못한다.

stopAll은 로컬 즉시 정지와 외부 pause 장벽을 병렬 적용하며 새 start는 장벽 결과 전에는 실행하지 않는다. 수동 확인은 특정 unresolved binding/documentEpoch와 해당 전환 ID에만 적용한다. 다른 탭·문서가 열리거나 재생 이벤트가 오면 확인을 폐기한다. 미확인 탭이 있는데 연결 정보만 지워 조용한 상태로 취급하지 않는다.

오류 코드는 missing-asset / invalid-range / stale-request / target-mismatch / binding-unresolved / autoplay-blocked / capability-unavailable / engine-error / save-conflict / bridge-unavailable로 제한한다. UI에는 원인+현재 소리 상태+가능한 다음 동작을 함께 표시한다. 재시도는 관측/준비에 한정하며 play 재시도는 운영자가 다시 요청해야 한다.

## v1.1 보완: 에셋 수명과 관측 신뢰도

논리 삭제된 항목·휴지통·템플릿·fallback 외에도 activeSnapshot/preparedSnapshot/진행 중 가져오기가 참조한 에셋에 세션 pin을 건다. 파일 정리는 저장된 참조와 세션 pin의 합집합을 사용한다. 정지/준비 교체/엔진 해제 확인 뒤 pin을 해제하고 충돌 복구 시 orphan 검사 후 정리한다. 활성 항목 삭제 직후 청소로 현재 재생 파일이 지워지면 안 된다.

외부 observedAt는 Main 수신 시각의 단조 시계로 신선도를 판정한다. 브라우저/worker heartbeat와 실제 탭 미디어 관측 시각을 따로 둔다. host 연결이 살아 있어도 탭 관측이 오래되면 unknown이다. 브라우저가 제공한 wall clock만으로 최신성을 판정하지 않는다.

등록한 재생목록 이름은 운영자 지정 라벨이며 실제 현재 곡 제목과 구분한다. 실제 곡을 읽지 못하면 `곡 정보 확인 불가`로 표시하고 링크 라벨을 현재 곡 제목처럼 보이지 않게 한다. playlist ID 일치만으로 곡의 시작 위치/순서를 보장하지 않는다.
