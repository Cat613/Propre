# 미디어 통합과 중앙 송출 미리보기 상세 설계

작성: 2026-10-17 Asia/Seoul · 설계 v1.2 · 상태: 로컬 구현·검증 완료 / 실제 서비스·장비 수용 전

사용자는 편집 상단의 여유 영역을 나누어 송출 미리보기를 배치하고, 음악 관련 기능을 미디어에 통합하는 방향으로 기능/UI·UX 재검토와 구현을 요청했다. 이 문서는 앞선 별도 고정 음악 바·펼침 목록 추천을 대체하는 현재 배치 기준이다. v1/v1.1의 대안 비교는 검토 배경이며 현재 추천 배치로 사용하지 않는다.

## 기능·화면 구조

- 중앙 편집 상단: 왼쪽에 편집 자료 제목·슬라이드 개수·편집 도구, 오른쪽에 실제 현재 송출 미리보기·송출 상태·화면 중지 도구를 배치한다. 미리보기는 현재 편집 자료가 아니라 기존 outputSnapshot/외부 소스 상태를 사용한다. 음악 준비·목록 편집은 시각 송출을 바꾸지 않는다. 슬라이드 선택·자료 열기 등 기존 시각 송출 동작은 이번 음악 통합에서 변경하지 않는다.
- 우측: 기존 미디어·스타일·레이어·설정 탭은 유지한다. 송출 미리보기를 제거해 미디어의 높이를 확보한다. 미디어 내부는 전체/이미지/영상/음악/웹·PDF 분류다. 전체에서는 음악 관리 진입을 제공하고, 음악 상세는 해당 분류를 실제로 열 때 불러온다. 이후 분류/탭 전환에서는 컴포넌트를 보존해 입력을 유지한다.
- 음악: 미디어 안에서 예배별 준비 목록·로컬 설정·유튜브 뮤직 링크·대체 파일·브라우저 연결을 관리한다. 별도의 큰 상단 음악 플레이어는 제거한다.
- 앱 상단: 작은 음악 상태와 진입·일시정지·중지만 유지한다. 대기 중 상태 바 표시를 끌 수 있지만 활성 음악·미확인 외부 음악의 중지 접근성은 유지한다. 미디어 탭과 별도로 재생 엔진을 소유한다.
- 중앙 `미디어` 버튼은 기존 이미지/영상 슬라이드 추가 기능을 보존하되 표시 이름을 `이미지·영상`으로 구체화한다. 우측 미디어 탭의 등록/음악 관리와 같은 기능처럼 표시하지 않는다.

## 반응형과 확대

중앙 command 영역 자체를 CSS container로 측정한다. 기본 미리보기 영역은 320px이며 내부를 화면 열과 상태·조작 열로 나눈다. 왼쪽 16:9 화면과 오른쪽 제목·연결 상태·슬라이드 정보·중지 도구를 나란히 배치해 화면 아래 누적되던 높이를 줄인다. 중앙 폭 560px 이하에서는 가로형 미리보기 전체를 편집 도구 아래 한 줄로 배치하고 화면 폭은 최대 180px로 유지한다. 360px 이하에서는 중지 도구만 전체 너비의 마지막 줄로 내려 버튼을 보존한다. 작은 미리보기에서 중지 버튼은 아이콘 대신 텍스트를 사용하며 화면은 계속 표시한다. 따라서 창 패널 리사이즈에도 편집 도구가 사라지지 않는다. 실제 검사 대상은 1440×960, 1280×800, 1024×768과 패널 너비 조절이다.

`확대`는 같은 미리보기 컴포넌트를 dialog로 확장한다. 실제 송출과 엔진은 새로 만들지 않는다. Escape/닫기는 기존 포커스로 돌아가고, F2는 폼·확대 dialog에서도 전체 중지한다. 확대/닫기만으로 화면이나 음악이 바뀌지 않는다.

## 음악의 사용자 흐름

1. 예배를 선택한 뒤 음악 파일 또는 유튜브 뮤직 링크를 등록한다. 새 파일은 설정 폼에서 이름·구간·반복·기본 음량·페이드 시간을 확인하고 저장한다.
2. 음악 항목 선택은 준비만 수행한다. 로컬은 소리 없는 별도 metadata 검사로 유한 길이와 구간을 확인한다. 현재 활성 audio 요소를 다음 곡 검사에 재사용하지 않는다.
3. 유튜브 뮤직 링크 저장은 로그인/탭 연결 완료가 아니다. 실제 연결 상태·현재 곡/목록 대상이 일치하지 않으면 재생 버튼을 비활성화하고 이유를 표시한다.
4. 명시적 재생/전환은 이전 외부 음악 pause·웹 음소거 확인 후 수행한다. 실패하면 현재 상태와 복구 이유를 표시하며 자동 대체하지 않는다.
5. 실시간 현재 음량은 활성 사본에만 적용한다. 설정 폼의 기본 음량·구간·반복은 다음 재생부터 적용한다.
6. 외부 끊김에서 대체 재생은 확인 전 차단한다. 특정 binding의 수동 정지 확인을 받아 해당 미확인 상태를 해소한 뒤 로컬 대체 파일을 시작한다. 수동 확인을 영구 허용으로 저장하지 않는다.
7. 다른 탭/미디어 분류 이동은 준비 선택·현재 재생을 유지한다. 다른 예배 선택은 준비 선택을 비우며 현재 실행 사본과 중지 접근성을 유지한다.
8. 삭제는 저장 목록에서 제거하되 실행 중인 사본은 유지한다. 세션의 `음악 삭제 되돌리기`는 설정만 복원하며 재생하지 않는다. 재시작 후 삭제 Undo까지 저장하는 기능은 현재 구현 범위에 포함하지 않는다.

## 데이터·재생 구현 계약

workspace-v5와 휴대용 형식4에 Setlist.music/ServiceTemplate.music을 저장한다. v4 원본·백업은 보존하며 읽어서 v5로 이전한다. 음악/로컬 대체 파일 URL은 기존 managed asset URL이고, 예배 단독 파일·템플릿·전체 백업에 실제 참조 파일을 포함한다. 독립 복제·가져오기는 음악 ID·연결 참조를 재매핑한다. ServicePlan version1에 선택적 musicPreparationId를 추가하고, 이전/지원 여부의 경계는 workspace/portable 새 버전으로 관리한다. v1.1의 plan2 제안은 구현 시 호환 비용 검토로 이 방식으로 조정했다.

로컬은 Control의 단일 HTMLAudioElement와 mediaSlice 요청 토큰을 사용한다. 준비 요청은 별도 preparationRequest, 음악 전환 의도는 request, 외부 실제 명령은 Main MusicBridge의 generation/만료/binding을 사용한다. 따라서 v1.1의 단일 Main MusicCoordinator 클래스 제안과 구체적 구현은 다르다. Main은 외부 권한·명령/전환 장벽, Control은 로컬 요소·준비/활성 상태를 소유한다. 기존 playAudio·clearLayer·clearAll·F2·웹 소리 켜기·예배 audio:stop 경로를 이 소리 정책에 연결한다. 가짜 adapter 성공을 실제 외부 제어 증거로 사용하지 않는다.

재생/준비/대체 사본의 파일은 세션 pin과 저장 참조로 정리에서 보호한다. 종료는 저장 flush 후 외부 pause를 확인하고 실패 시 창 유지 또는 외부 소리 잔류를 확인하고 종료하는 선택을 제공한다. 재시작은 목록만 복원하며 자동 재생하지 않는다. Look audio 비표시 후 표시 복원도 자동 재개하지 않는다.

## 유튜브 뮤직 배포·검증 경계

browser-extension/youtube-music은 Chrome MV3 연결 확장 소스다. native host helper는 앱 패키지에 포함하고 macOS 사용자 단위 manifest는 앱의 명시적 연결 설정에서 등록한다. 앱은 계정 인증/쿠키를 가져오지 않고 사용자가 로그인한 music.youtube.com 탭만 연결한다. 확장 ID와 연결 상태·재생 대상은 별도로 확인한다.

현재 확장 소스·앱 브리지·로컬 계약 검사를 제공하지만 실제 Google 로그인·실서비스 DOM 호환성·Premium/광고/지역·확장 배포/설치 수용은 별도다. 콘텐츠 스크립트가 실제 플레이어 곡/목록을 읽거나 명시적 play/pause를 적용할 수 없으면 지원으로 표시하지 않는다. 이때 링크 열기만 제공하고 직접 제어 완료라고 보고하지 않는다.

## 화면 검토 후 보완

사용자 후속 검토에서 미리보기 화면·정보·버튼의 세로 누적으로 편집 상단 여백이 커지는 문제가 확인되어, 미리보기 내부를 화면/상태·조작 두 열로 재배치했다. 중지 도구는 세 버튼을 가로로 유지한다. 왼쪽 찬양 목록 도구도 좁은 패널에서 줄바꿈해 버튼이 잘리지 않도록 했다. 음악 다음 준비/실행 도구는 긴 목록 아래가 아니라 현재 제어 아래에 배치한다. 폼이 열려 있을 때 다른 폼으로 덮어쓰거나 저장 전 같은 항목을 준비하지 못하게 하며 다른 탭으로 이동해도 입력은 유지한다.

동적 음악 상세는 50KB 개별 제한, 성경 추가 등 선택 예배 도구는 기존 선택 도구 제한으로 검사한다. 공유 기본 renderer 700KB 제한을 올리지 않는다. 라이트 테마 캡처는 버튼 색상 전환 완료를 확인한 뒤 촬영해 전환 중 프레임을 최종 화면으로 오인하지 않는다.


## 후속 편집 밀도 조정

제목 헤더와 편집 도구의 상하 패딩을 줄이고, 구간 바로가기 아래 margin과 슬라이드 목록 위 padding의 중복을 제거했다. 구간→슬라이드 제목→카드 순서를 짧은 간격으로 연결한다. 슬라이드 카드의 `송출 중` 배지와 접근성 이름의 같은 문구를 제거한다. 카드 강조는 기존 활성 위치를 보여주며 실제 송출 여부의 근거로 사용하지 않는다. 실제 창 연결·적용 상태는 현재 송출 미리보기에서 확인한다.


AI 찬양 준비 버튼은 제목 헤더 오른쪽, 슬라이드 개수 위에 고정 배치한다. 편집 도구의 flex-wrap에서 분리하여 도구 줄 너비 부족으로 별도 하단 줄에 밀려나지 않게 한다. 버튼 문구는 줄바꿈하지 않고 제목은 기존 말줄임을 사용한다.
