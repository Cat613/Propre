# 음악 UI·UX 대안과 추천안

작성: 2026-10-17 · 상태: 설계 비교·추천 / 앱 미구현 / 운영자 수용 전

[설계 인덱스](README.md), [기본 상호작용](01-음악-준비와-공통-패널.md), [검토 기록](../../review/2026-10-17-음악-병행-설계-검토.md)과 함께 읽는다. 아래 배치 수치와 행동 목표는 설계 제안이며 실제 화면 검사·리허설 결과가 아니다.

현재 추천은 사용자 후속 제안에 따라 [미디어 통합·중앙 미리보기 v1.2](05-미디어-통합과-송출-미리보기-구현-설계.md)로 변경했다. 아래 5개 대안은 비교 배경으로 보존한다.

## 해결할 사용자 과제

운영자는 슬라이드와 예배 순서를 보면서 세 가지를 즉시 알아야 한다. 지금 어떤 소리가 나오는지, 다음에 무엇을 틀 것인지, 어떻게 바로 멈추는지다. 설정·확장 설치·파일 관리는 준비할 때 처리한다. 재생 중에는 소스별 차이를 감추지 않되 조작 위치는 유지한다.

현행 ControlPanel은 상단 AudioPlayer와 좌측 순서/자료·중앙 슬라이드 편집·우측 미리보기/도구의 세 패널 구조다. 우측은 이미 미리보기와 미디어·스타일·레이어·설정이 차지한다. 음악 전용 네 번째 상시 패널을 바로 추가하면 1024×768에서 편집·미리보기 영역을 줄이므로 기본안으로 택하지 않는다.

## 다섯 가지 배치 대안

| 안 | 배치·조작 | 좋은 상황 | 비용·한계 | 채택 제안 |
| --- | --- | --- | --- | --- |
| 고정 음악 바 + 펼침 목록 | 상단 작은 바에서 현재 제어, 바로 아래 목록을 필요할 때 펼침 | 슬라이드와 음악을 한 사람이 조작, 노트북 | 펼친 동안 중앙 높이가 줄어듦 | 기본 추천 |
| 우측 음악 도구 패널 | 미리보기 아래 음악 탭, 상단 중지 상태는 계속 유지 | 곡 설정·연결 상태를 자주 보는 운영 | 다른 우측 도구와 탭 경쟁, 미리보기 높이 압박 | 선택 모드 |
| 순서별 음악 카드 | 좌측 큐 행에 연결 음악과 준비 배지, 행 버튼으로 준비 | 예배 순서에 맞춰 음악을 바꾸는 경우 | 같은 음악 중복 표시·긴 행, 전체 소리 상태는 별도 필요 | 기본안의 보조 |
| 진행용 큰 버튼 화면 | 예배 전/기도/예배 후 준비 항목을 큰 수동 실행 버튼으로 배치 | 사전 준비 완료, 터치·초보 운영자 | 편집 공간과 곡 수 관리에 부적합, 재생 오조작 주의 | 후속 진행 모드 후보 |
| 분리 음악 제어 창 | 독립된 작은 제어 창을 보조 모니터에 배치 | 음악 전담 운영자·여러 화면 | 창 유실·재연결·다중 컨트롤러 권한 문제 | 초기 범위 제외 |

순서 카드만 단독 사용하면 다른 예배의 음악이나 외부 미확인 소리가 행에서 사라질 수 있다. 어느 대안이든 실제 재생 상태와 음악 전체 중지는 앱 상단에 남긴다. 큰 버튼이나 분리 창을 초기 기능으로 동시에 만들지 않는다.

## 추천 조합과 공간 규칙

**고정 음악 바 + 펼침 준비 목록 + 순서의 연결 배지**를 기본으로 추천한다. 상시 플레이어는 제어를, 목록은 준비를, 순서 행은 맥락을 담당한다. 독립된 플레이어 세 개를 만드는 것이 아니라 하나의 상태를 다른 위치에서 읽는다.

- 기본 바는 약 48~56px 목표다. `음악 · 로컬/유튜브 뮤직 · 상태 · 제목`, `재생/일시정지`, `음악 중지`, `목록`을 둔다. 다음 항목은 폭이 부족하면 두 번째 줄로 내린다.
- 로컬 `현재 음량`과 `3초간 줄여 멈춤`은 폭이 허용되면 표시한다. 구간/반복/기본 음량·처음부터는 펼침 상세에 둔다. 긴급 중지는 더보기 안으로 숨기지 않는다.
- 펼침은 앱 안의 비모달 영역이다. 키보드 포커스를 가두지 않고 편집·순서로 이동할 수 있다. 높이는 작업 영역의 약 35% 이내 목표, 음악 목록 내부 스크롤과 크기 조절을 제공한다. 닫으면 호출 버튼으로 복귀한다.
- 1024×768은 두 줄 바와 단일 열 목록/상세 전환, 1280×800 이상은 목록과 상세 2열을 검토한다. 실제 남은 패널 폭을 기준으로 접고 창 폭만으로 결정하지 않는다.
- 순서 행에는 `음악: 기도 반주 · 로컬 · 파일 확인됨`과 `준비`만 둔다. 별도 재생 버튼을 행마다 반복하지 않아 선택과 실행이 섞이지 않게 한다.

```text
┌ 음악 · 유튜브 뮤직 · 재생 중  예배 전 음악 ────────────────┐
│ 실제 곡: 샘플 연주곡        [일시정지] [음악 중지] [목록] │
│ 다음 준비: 기도 반주 · 로컬 · 파일 확인됨   [전환해 재생]  │
├ 펼친 목록 ──────────────────┬ 항목 설정 ────────────────┤
│ 예배 전 음악 · 유튜브 뮤직   │ 등록 이름 / 소스           │
│ 기도 반주 · 로컬 [준비됨]    │ 시작·끝 / 반복 / 기본 음량 │
│ 예배 후 음악 · 유튜브 뮤직   │ 대체 파일 / 저장 상태      │
└─────────────────────────────┴─────────────────────────┘
```

## 처음 쓰는 흐름과 반복 사용

최초에는 음악 바를 작게 보이고 `음악 추가`를 제공한다. 소스 선택은 `내 컴퓨터 파일`과 `유튜브 뮤직 링크` 두 개다. 로컬 파일은 이름/음량을 기본으로 두고 `구간·반복`은 펼침 설정으로 제공한다. 등록 완료는 소리 없이 목록과 준비 상태로 돌아온다.

유튜브 뮤직은 링크 저장과 브라우저 연결을 분리한다. 링크를 먼저 저장하고 나중에 연결해도 된다. 연결 화면은 `확장 설치 확인 → 앱 연결 확인 → 탭 선택 → 재생 대상 확인` 진행 상태를 표시하고 실패 지점에서 재개한다. 이미 끝난 설치/로그인을 매번 반복하지 않는다. 인증 정보·계정 선택 화면을 앱 안에 복제하지 않는다. 앱에는 `브라우저 연결 프로그램 설정`처럼 사용자 용어를 쓰고 Native Messaging 같은 구현명은 진단 상세에만 둔다.

매주 예배 복제 시 음악 이름·로컬 구간·대체 파일·링크는 복제하지만 탭 연결·현재 곡 위치·재생 중 상태는 복제하지 않는다. 목록에는 `저장됨`과 `지금 재생 가능 여부`를 다른 상태로 표시한다.

## 상태별 문구와 행동

| 상태 | 사용자 문구 | 주 동작 | 보조 동작 |
| --- | --- | --- | --- |
| 음악 없음 | 준비한 음악이 없습니다 | 음악 추가 | 없음 |
| 로컬 준비 완료 | 파일 확인됨 · 아직 재생하지 않음 | 재생 | 설정 |
| 링크 저장·연결 없음 | 링크 저장됨 · 브라우저 준비 필요 | 브라우저에서 준비 | 연결 설정 |
| 외부 대상 확인 | 연결됨 · 재생목록 확인됨 | 재생 | 브라우저 열기 |
| 재생 시작 요청 | 재생 확인 중 | 음악 중지 | 없음 |
| 외부 일시정지 | 일시정지됨 · 위치 유지 | 이어 재생 | 브라우저 열기 |
| 외부 관측 만료 | 연결 끊김 · 음악이 계속 나올 수 있음 | 브라우저 확인 | 대체 음원 전환 절차 |
| 외부 중단 미확인 | 아직 중단을 확인하지 못했습니다 | 브라우저에서 정지 | 다시 확인 |
| 로컬 시작 실패 | 파일을 재생하지 못했습니다 · 현재 음악 중단됨 | 파일 확인 | 다른 음악 준비 |
| 저장 실패 | 설정을 저장하지 못했습니다 · 현재 재생 유지 | 저장 재시도 | 초안 유지 |

기술 오류 코드만 노출하지 않는다. 정상/준비는 중립색과 텍스트, 재생은 일관된 활성 표시, 외부 미확인은 경고색, 중지 버튼은 경고색과 명시적 이름을 사용한다. 초 단위 위치 갱신을 aria-live로 반복 읽지 않고 재생 상태가 바뀔 때만 알린다.

## 대체 음원 전환의 구체적 UX

대체 파일이 있으면 활성 유튜브 뮤직 상세에 `로컬 대체 음원으로 전환`을 둔다. 정상 연결에서는 이 한 번의 명령으로 외부 pause 확인 후 대체 파일 구간 시작부터 재생한다. 임의로 비슷한 시간 위치로 이동하지 않는다.

pause 미확인이면 바 아래에 지속 복구 영역을 연다. `음악이 계속 나올 수 있습니다. 브라우저에서 멈춘 뒤 전환해주세요`와 `브라우저에서 정지`, `다시 확인`을 제공한다. 수동 확인이 필요한 경우 `직접 정지했음을 확인` 체크와 `확인 후 대체 음원 재생`을 함께 둔다. 첫 클릭만으로 재생하지 않는다. 취소는 준비 유지, 현재 상태는 미확인으로 남긴다. 반복 팝업으로 진행 화면을 덮지 않는다.

일반 재생/일시정지는 확인 모달 없이 즉시 실행한다. 원본을 바꾸는 파일 재연결/삭제와 미확인 외부 소리의 수동 확인은 별도 단계가 필요하다. F2와 음악 중지는 모달 위에서도 동작해야 한다.

## 가독성·입력·행동 검증

명시적 텍스트 라벨과 최소 32px 데스크톱 버튼 목표, 터치 지원 시 약 44px 타깃을 적용한다. 위험한 중지는 재생/설정과 간격을 두되 항상 접근 가능하게 한다. 클릭 후 상태가 바뀌어도 버튼 위치를 흔들지 않고, 비지원 기능은 같은 공간에 빈 슬라이더를 두지 않는다. 드래그 순서 변경은 이동 위/아래 키보드 대안을 제공한다. 모든 비활성 사유는 hover 외에도 읽을 수 있게 한다.

운영자 리허설 과제: ① 현재 재생 소스 식별 ② 다음 곡 소리 없이 준비 ③ 한 번의 명령으로 정상 전환 ④ 외부 미확인 상황에서 수동 정지 후 대체 ⑤ 모달 열린 상태에서 중지 ⑥ 저장 실패 후 초안 복구. 성공 여부·오클릭·주저한 위치·필요한 화면 이동을 기록한다. 정상 재생 전환 1회 명령, 중지 1회 명령이 목표이며 설정/설치 클릭 수를 합산해 단순 성능처럼 제시하지 않는다.

## 단계별 채택

초기에는 고정 바+목록+연결 배지와 복구 흐름을 구현한다. 우측 음악 탭은 실제 넓은 화면 리허설에서 필요할 때 검토한다. 큰 버튼 진행 모드·분리 창·파형 편집·헤드폰 큐는 후속이며 현재 필수 구현 범위로 확대하지 않는다. 대안 비교 예시는 실제 연결·음향 검증을 대신하지 않는다.
