# 음악 카드에서 한 번에 재생

## 문제와 사용자 흐름

2026-10-18 캡처에서 준비한 음악은 루시 앨범인데 연결 탭에는 다른 찬양이 남아 있었다. 기존 화면은 대상 불일치를 긴 문장으로 안내하고 재생 버튼을 비활성화하여, 사용자에게 선택 → Chrome에서 준비 → 연결 확인 → 전환 재생 순서를 요구했다.

기본 흐름을 링크 등록 → 카드의 재생으로 바꾼다. 재생 버튼은 명시적 재생 승인이다. 제목 선택은 재생 없는 준비로 유지하며, 재생 없는 Chrome 연결·설정·순서 이동·삭제는 카드의 더 보기 안에 둔다. 재생 실패 시 기본 재생 버튼으로 재시도할 수 있고 연결 도움말을 보조 경로로 제공한다. 재생 중인 선택과 같은 준비 정보는 중복 표시하지 않는다.

## 동작 계약

`playMusic`은 저장 항목의 메타데이터·현재 예배·revision을 검증하고 `playPrepared`에 전달한다. `playPrepared`는 상태를 확인하여 대상이 이미 준비돼 있으면 재사용한다. 끊김·stale·다른 대상이면 `prepareMusicURL`로 올바른 페이지의 자동 연결을 요청한다. 다른 곡이 연결돼 있다는 이유로 사용자를 차단하지 않는다. 선택이나 링크 저장만으로는 재생하지 않는다.

Main의 준비 완료는 새 문서의 binding과 정지 상태뿐 아니라 실제 재생 가능한 대상 관측까지 기다린다. document_start의 빈 플레이어 보고만으로 준비 완료를 반환하지 않는다. 기존 연결의 중단 확인과 일회성 준비 요청 검증은 유지한다. 준비 및 연결 실패 시 기존 로컬 재생을 변경하지 않으며, 재생 전 기존 소스를 멈추는 공통 전환 계약을 따른다.

작업 중 버튼을 중복 실행하지 않는다. 소스가 없는 초기 연결 중에도 재생 취소 버튼을 제공하고, 기존 소스가 있으면 음악 중지 버튼을 유지한다. 중지/F2/요청 변경 이후 연결이 늦게 완료돼도 재생을 요청하지 않는다. 연결/로딩 안내는 성공 시 제거한다.

## 검증

- 단위 테스트: 이전 곡이 연결된 상태에서 요청 앨범으로 자동 연결 후 재생, 자동 연결 중 중지 후 늦은 응답의 play 차단, 오류 시 기존 소스 보존, Native 준비가 헤더 준비 관측까지 기다리는지 검사한다.
- Electron: 준비 선택 없이 카드 재생 한 번으로 로컬 음원이 시작되고 더 보기 안의 보조 동작이 정상 접근 가능한지 검사한다.
- 실제 Chrome: 등록 음악 2개, 다른 찬양이 연결된 사용자 화면을 확인했다. 앱 재시작 후 루시 앨범 카드의 재생만 눌러 새 탭 연결 → 첫 곡 아니 근데 진짜 재생을 확인했고, 앱 일시정지 후 실제 Chrome 플레이어 0:20 / 3:58에서 멈춘 것을 확인했다.

확장 설치와 Native host 최초 설정은 한 번 필요하다. 로그인·브라우저 재생 제한 및 다른 Chrome 프로필은 별도 복구 안내를 따른다. 이 변경은 공개 배포 패키지 갱신을 포함하지 않는다.
