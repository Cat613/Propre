# MUS-03 유튜브 뮤직 연결과 복구

작성: 2026-10-17 · 상태: 설계 제안 / 직접 제어·정책 적합성 미검증

## 목표와 기술 선택

유튜브 뮤직의 실제 웹 페이지에서 운영자가 로그인하고 곡·재생목록을 고른다. ProPre는 계정 인증·스트림 재생을 대신하지 않고 명시적으로 연결된 하나의 탭에 재생/일시정지 요청을 전달한다. Chrome 확장 content script → 확장 service worker → Native Messaging host → Electron Main의 로컬 브리지를 우선 검증한다. Native Messaging은 통신 수단이며 유튜브 뮤직 제어 기능이나 서비스 사용 허가를 보장하지 않는다.

2026-10-17 확인한 공식 근거:

- [Chrome Native Messaging](https://developer.chrome.com/docs/extensions/develop/concepts/native-messaging): 확장과 등록된 native host 통신, host의 allowed_origins 제한. host 설치·등록과 앱 패키지 경로 처리가 필요하다.
- [Google OAuth 정책](https://developers.google.com/identity/protocols/oauth2/policies): 개발자가 제어하는 embedded user-agent에서 OAuth 요청을 진행하는 것을 금지한다. 외부 브라우저 로그인을 우선하는 이유다.
- [YouTube 개발자 정책](https://developers.google.com/youtube/terms/developer-policies): API 이용 시 오디오/영상 분리, 숨긴 플레이어 재생, 광고 방해 등의 제한이 있다. 이 문서가 브라우저 자동 제어를 허용한다는 근거는 아니다. 구현 검증 시 실제 적용 약관·배포 정책과 사용 방식을 별도 검토한다.

브라우저 DOM 기반 제어는 비공식 연동이다. 선택자 변경·페이지 재구성·자동재생 제한으로 실패할 수 있다. 확인되지 않은 공개 YouTube Music 원격 API를 전제하지 않는다. 광고 차단·우회, 오디오 추출, 쿠키 복사, 로그인 우회, CAPTCHA 자동 처리는 하지 않는다.

## 최초 연결과 일상 조작

1. `유튜브 뮤직 연결` 화면에서 지원 Chrome 버전·확장 버전·host 등록 상태를 검사한다. 미설치면 정확한 설치 단계를 보여준다. 설계 단계에는 설치물을 배포하지 않는다.
2. 운영자가 브라우저에서 로그인한다. 계정 선택과 인증은 브라우저에서만 수행한다.
3. 탭에서 `이 탭을 ProPre에 연결`을 실행하고 앱과 확장 양쪽의 일회성 연결 확인으로 페어링한다.
4. 후보 탭 이름과 URL의 안전한 요약을 표시한다. 여러 탭이면 자동으로 가장 최근 탭을 선택하지 않는다. 기본 한 탭만 제어한다.
5. 연결 후 현재 대상·실제 재생 상태를 읽는다. 현재 재생 중인 음악을 바꾸지 않고 명시적으로 인수한다.
6. 등록한 링크와 연결 탭의 실제 곡/목록 식별자가 맞는지 검사한다. 다르면 `다른 음악이 열려 있습니다`와 `브라우저에서 준비`를 제공한다.
7. `재생`은 상태가 paused이면 명시적 play, playing이면 no-op이다. toggle 기반 명령은 사용하지 않는다. 일시정지도 명시적 pause여야 한다.

링크는 HTTPS music.youtube.com의 검증된 watch/playlist 경로, 허용 ID 쿼리만 저장한다. credentials·임의 redirect URL·알 수 없는 scheme/host는 거절한다. 원래 입력을 실행 가능한 코드나 셸 인자로 사용하지 않는다. 링크 등록은 자동 접속하지 않는다. 브라우저 열기는 사이트 자체 동작에 따라 소리를 낼 수 있으므로 현재 재생 중인 탭 이동을 자동 수행하지 않는다. 실제 로그인·Premium/광고·지역/곡 권한·자동재생은 별도 실서비스 검사다. 구독 상태로 광고 없음이나 모든 콘텐츠 재생을 추정하지 않는다.

## 지원 기능과 상태

필수 검증 capability는 readState, play, pause, readTarget이다. 하나라도 신뢰할 수 없으면 연결은 `직접 제어 불가`다. 다음 곡·탐색·볼륨·반복은 검증된 capability에 한해 후속 제공하며 초기 필수 범위에 넣지 않는다. 로컬 음량 슬라이더로 외부 볼륨을 바꾸는 것처럼 표시하지 않는다.

명령 접수 ACK와 실제 상태 이벤트를 구분한다. DOM/미디어 상태 확인도 브라우저 내부 상태의 증거이며 스피커 소리의 증거가 아니다. 로그인 화면·탭 종료·다른 사이트 이동·제어 요소 미발견·상태 불명은 성공으로 처리하지 않는다. 재생 실패 시 직접 브라우저 재생을 안내하고 운영자가 원하면 로컬 대체 흐름으로 이동한다.

heartbeat는 2초 간격, 마지막 상태 6초 경과 시 stale, 명령 결과 대기는 2초를 초기 제안값으로 둔다. 부하·확장 worker 재시작·macOS 절전에서 검증 후 조정한다. stale는 정지 상태가 아니다. 자동 명령 재전송으로 다시 재생시키지 않는다. 재연결 시 관측만 복구하고 자동 play를 보내지 않는다. 재접속/탭 교체 시 connectionEpoch를 바꾸고 이전 응답은 폐기한다.

## 연결 보안과 운영

확장은 music.youtube.com에 필요한 최소 host 권한과 nativeMessaging만 요청한다. 모든 웹사이트·브라우징 이력·쿠키 접근 권한을 요구하지 않는다. 확장 설치 ID allowlist, native host 경로 무결성, 사용자 전용 로컬 IPC 소켓 권한, 일회성 페어링 비밀·만료·재사용 거절을 적용한다. 확장에서 수신한 제목·ID·상태도 불신 입력으로 길이/열거값/대상을 검증한다. 사이트에서 임의 JS·파일 경로·IPC 명령을 넘길 수 없게 한다.

브리지는 명시적 명령 allowlist만 지원한다. 범용 JavaScript 실행, 임의 URL 이동, 시스템 명령 실행 API를 노출하지 않는다. 페어링 비밀은 OS 보호 저장에 두고 백업·로그에서 제외한다. 확장 재설치·연결 해제는 권한을 폐기하며 OS 공용 미디어 키로 몰래 대체하지 않는다.

앱 설치 경로 변경·앱 업데이트·확장 업데이트·미설치 host·확장 worker 재시작을 MUS-P0 검증에 포함한다. 실패하면 연결 상태 화면에서 복구할 수 있어야 한다. Chrome 외 브라우저는 별도 수용 전에는 지원 표시하지 않는다.

## v1.1 보완: 탭 인수·교체·연결 해제

연결 상태와 활성 소스 소유권을 구분한다. 로컬 재생 중 외부 탭을 연결해도 자동 외부 인수하지 않는다. 이미 외부 탭이 재생 중이면 `브라우저 음악도 재생 중`으로 표시하고 해당 탭 pause를 요청하거나 운영자가 명시적으로 인수하도록 한다.

제어 binding은 profileSession + tabId + documentEpoch + bindingId로 식별한다. 재생목록 전환의 SPA navigation도 targetRevision을 변경한다. 같은 playlist의 자연스러운 다음 곡은 현재 곡 정보만 갱신하며 임의 목록/곡으로 벗어나면 대상 불일치와 재생 가능성을 함께 표시한다. watch 링크는 video ID, playlist 링크는 list ID가 실제 플레이어 문맥과 맞아야 한다. 주소창 URL 일치만으로 실제 재생 대상을 확정하지 않는다. 이를 관측할 수 없으면 직접 제어 불가다.

탭 교체·연결 해제는 기존 binding pause 확인 → 이전 요청 폐기 → epoch 교체 → 새 관측 순서다. pause 미확인 시 이전 탭을 unresolved 상태로 보존하고 새 재생을 막는다. 운영자 수동 중단 확인 이후에만 교체를 완료한다. 탭을 잊거나 연결을 끊는 동작이 정지 성공처럼 표시되면 안 된다. 사용자 브라우저에서 강제 이동/탭 종료가 발생하면 자동 제어 보장을 해제하고 미확인 범위를 표시한다.

## v1.1 보완: native host·권한·worker 수명

content script는 nativeMessaging을 직접 호출할 수 없으므로 worker가 sender.origin/url·tabId·frameId=0·binding/document를 검사하고 host로 전달한다. content script의 isolated world에서 DOM/미디어 요소를 관측한다. 페이지 내부 전역 변수나 인증 토큰 접근을 요구하지 않는다. 허용된 DOM 경로로 명시적 play/pause와 대상 검증이 불가능하면 P0 실패로 기록한다. 임의 main-world 코드 주입으로 우회하지 않는다. [Native Messaging 공식 문서](https://developer.chrome.com/docs/extensions/develop/concepts/native-messaging), [Content scripts 공식 문서](https://developer.chrome.com/docs/extensions/develop/concepts/content-scripts).

연결 유지에는 runtime.connectNative의 포트를 사용한다. 포트 유지는 worker 수명에 영향을 주지만 host 종료/브라우저 종료/절전의 복구를 대신하지 않는다. worker의 setInterval만으로 2초 heartbeat를 보장하지 않고 Main의 주기적 상태 요청과 응답 최신성으로 판정한다. 단절 후에는 1/2/5초, 이후 최대 30초 간격으로 전송 연결만 재시도하며 재생 명령은 재전송하지 않는다. 앱 명시적 연결 해제 때 재연결을 중지한다. [Worker 수명 공식 문서](https://developer.chrome.com/docs/extensions/develop/concepts/service-workers/lifecycle).

확장 host permission과 nativeMessaging 외에 chrome.scripting을 실제 사용하면 scripting 권한을 명시하고 목적을 설명한다. 정적 content script 기반 검증으로 충분하면 scripting 권한을 추가하지 않는다. tabs 전체 권한은 기본 요구하지 않으며 허용 사이트 메시지에서 받은 탭만 후보로 제시한다. 최소 권한 조합은 P0에서 실제 설치로 검증한다.

host는 별도 helper 프로세스이며 시스템 Node 설치를 전제하지 않는다. 패키지에 포함한 실행물·실행 권한·stdio framing·stderr 로그·macOS 사용자 단위 등록/제거를 검증한다. 배포 확장 ID·브리지 protocolVersion·앱/확장 지원 범위를 교환하고 불일치면 지원하지 않는 연결로 처리한다. unpacked 개발 확장 성공은 일반 사용자 설치/업데이트 성공이 아니다. host 등록은 앱의 명시적 `브라우저 연결 설정`에서 수행하고 삭제/앱 이동 복구도 제공한다.

2초 timeout은 pause/start의 응답 확인 한도이며, 시작 실패로 처리한 명령도 뒤늦게 실행되지 않도록 명령 만료와 중단 장벽이 실제 content adapter까지 전달되어야 한다. 단순히 Main에서 늦은 응답을 무시하는 것만으로 이 조건을 충족하지 못한다.
