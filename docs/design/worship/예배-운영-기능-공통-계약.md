## 3. 목표 데이터 모델

아래 타입은 초기 설계 의사 코드다. 최종 Zod 계약은 shared/service-plan.ts와 기능별 shared 파일 및 아래 구현 기록을 따른다.

```ts
type ServicePlan = {
  version: 1
  timezone: string // IANA, 새 예배 기본값 Asia/Seoul
  plannedStartAt?: string // offset을 포함한 ISO instant
  items: CueItem[]
}
type CueItem = {
  id: string
  kind: 'song' | 'prayer' | 'scripture' | 'sermon' | 'offering' | 'announcement' | 'custom'
  title: string
  leader?: string
  durationSeconds?: number // 생략은 미정, 0은 시간 없는 순서
  operatorNote?: string
  stageNote?: string // 저장 메모. 자동 송출되지 않음
  songItemId?: string // song만, 기존 Setlist.items 행 ID
  binding?: CueBinding // song 외 자료 연결
  enter: EnterPolicy
  timer?: TimerPreset
}
type CueBinding =
  | { kind: 'presentation'; presentationId: string; slideId: string }
  | { kind: 'resource'; resourceId: string; page?: number; rotation?: 0 | 90 | 180 | 270 }
type EnterPolicy =
  | { visual: 'keep'; audio: 'keep' | 'stop' }
  | { visual: 'background-only'; audio: 'keep' | 'stop' }
  | { visual: 'black'; audio: 'keep' | 'stop' }
  | { visual: 'bound'; audio: 'keep' | 'stop' }
```

Setlist에 선택 `servicePlan`을 추가하고 Setlist.revision을 계획 변경의 단일 revision으로 사용한다. `song`은 songItemId를 통해 기존 곡 사본을 찾으며 binding을 가질 수 없다. 비곡 순서는 별도 소유 사본 `cuePresentations[{ownerSetlistId, presentation}]`와 `cueResources[{ownerSetlistId, resource}]`를 참조한다. 화면 자료를 연결할 때 원본의 본문/스타일 또는 URL/PDF 메타데이터를 복사하고 PDF·미디어 asset만 참조 공유한다. 원본 수정·삭제는 사본을 바꾸지 않는다. 웹 로그인 세션과 현재 DOM은 복사·저장하지 않는다.

Setlist.items는 servicePlan에서 song만 뽑아 만든 호환 투영이다. 기존 playlist는 활성 Setlist.items와 일치한다. 곡 추가/제거/복제/정렬·AI 콘티 적용·파일 불러오기도 이 세 구조를 한 트랜잭션으로 갱신한다. songItemId는 정확히 한 cue에서 참조하며, 같은 곡을 두 번 쓰려면 서로 다른 곡 행과 cue ID를 만든다. 같은 예배 내 원래 사본 재사용 정책은 유지한다. 서로 다른 예배의 본문 사본은 공유하지 않는다.

곡 목록에서 정렬하면 기존 곡 슬롯에 새 곡 순서를 대입하고 비곡 슬롯은 제자리에 둔다. 곡 추가는 선택한 큐 뒤, 선택이 없으면 끝에 넣는다. 곡 삭제는 대응 cue를 함께 제거하며 메모 삭제 범위를 미리 알린다. 전체 순서 이동은 큐시트에서 한다. 활성 진행 항목 삭제는 진행 종료/다른 항목으로 전환하기 전까지 거절한다. 순서 편집 자체는 송출을 바꾸지 않는다.

새 예배 작성은 최대 1,000개 cue다. 이전 파일의 1,000개 초과 곡 목록은 기존 상한 10,000개까지 보존해 이전하고 이후 개수를 늘리는 변경은 거절한다. 제목 200자, 담당자 100자, 메모별 2,000자, 시간은 0~86,400 정수 초로 제한한다. 모든 ID는 현행 Id 규칙을 따른다. 템플릿 200개, 예배별 비곡 자료 합계 1,000개를 제안하며 전체 24MiB 상한은 유지한다. 사본 증가로 한도를 넘으면 원자 거절하고 정리/백업 안내를 제공한다. 상한 증가는 측정 후 별도 결정한다.

## 4. 저장·이전·파일 호환

목표는 workspace schema 4다. 구현 착수 시 최신 버전을 확인하고 이미 사용 중이면 다음 가용 버전으로 변경한다. 현재 v3 파일·최근 다섯 저장본은 보존하고 새 파일에 원자 기록한다. v1/v2는 기존 이전 경로로 v3를 검증한 다음 새 스키마로 이전한다. 각 기존 Setlist.items 행을 순서대로 song cue로 바꾸며 곡/슬라이드/사본 ID, 메모 없는 기존 내용, draft, 미디어, 설정을 보존한다. 제목·날짜만 있는 콘티는 시작 시각을 추정하지 않는다.

실패 시 새 스키마의 부분 결과를 채택하지 않고 유효한 이전 파일로 재시도/복구를 안내한다. 손상 원본을 덮어쓰거나 빈 작업 공간으로 자동 저장하지 않는다. 이전 앱은 이전 파일만 읽어 신규 편집이 반영되지 않으므로 다운그레이드 시 경고한다. 미래 버전 파일은 쓰기 거절한다.

전체 백업에는 계획·템플릿·소유 사본·참조 assets를 포함한다. 새 `kind: service` 휴대 형식과 portable schema 3을 제안하며 기존 portable 1/2는 계속 읽는다. `service`에는 한 예배의 계획/사본/assets만 포함한다. 세션·로그인·무대 일시 안내·실행 토큰은 제외한다. 기존 playlist 내보내기는 곡만 담는 사실과 빠지는 비곡 순서·메모를 내보내기 전에 표시한다. 전체 예배 이동에는 service 파일을 권한다. 구버전에서 신형 파일을 부분 읽기하지 않도록 버전 검사한다.

복제/가져오기는 예배·cue·행·본문·자료 ID를 새로 만들고 내부 참조를 일괄 재매핑한다. asset은 해시 검증 후 재사용한다. 예배 휴지통은 계획과 모든 소유 사본을 보존하고 참조 assets의 정리를 막는다. 삭제/복원·원곡 반영 계약은 기존 정책을 유지한다.

## 5. 명령·권한·경합

Control만 `saveServicePlan`, `prepareCue`, `commitCue`, `skipCue`, `finishService`, `sendStageMessage`, `clearStageMessage`, `timerCommand`, `runPreflight`, `saveTemplate`, `instantiateTemplate`, `previewCuesheet`, `exportCuesheet`를 호출한다. 이는 신규 제안 API이며 현행 API가 아니다. Main/Stage는 전용 payload 소비와 applied 응답만 한다. 외부 MCP는 초기 구현에서 이 변경 명령을 자동 노출하지 않는다.

변경 요청 공통 필드는 requestId(UUID), setlistId, expectedSetlistRevision이다. 실행 요청은 sessionId, expectedSessionRevision, cueId와 준비 토큰을 추가한다. 저장은 기존 편집 flush·Repository 직렬화에 연결하고 결과에 새 revision을 반환한다. 같은 requestId 재시도는 한 세션 안에서 같은 결과를 반환하며 같은 ID·다른 본문은 거절한다. 재시작을 가로지르는 실행 명령 재전송은 거절한다. plan 충돌이면 최신 내용을 별도 표시하고 입력 초안을 유지하며 재검토 후 저장하게 한다.

실행은 `명령 수락 → 출력 적용 대기 → applied/실패`로 구분한다. prepare 토큰은 plan revision, source revision, slide/page/rotation, output generation에 묶고 하나라도 바뀌면 무효화한다. 시각 전환 실패 시 이전 화면을 유지하고 진행 항목을 확정하지 않는다. 이미 실행된 정지 같은 비가역 부수 효과는 되돌렸다고 표시하지 않는다. 중복 실행·늦은 응답을 session revision으로 거절한다.

청중 snapshot에는 메모·담당자·stageNote·타이머를 넣지 않는다. Stage snapshot에는 현재/다음 가사와 지정된 공개 무대 안내·시간만 넣는다. Control은 전체 계획을 받는다. plain text만 허용하고 HTML/스크립트·임의 파일 경로를 렌더링하지 않는다. 진단에는 ID/오류 코드/시간만 기록하고 메모·담당자·본문·URL query를 넣지 않는다.

## 6. 런타임·복구·설정

Main의 ServiceSession이 sessionId, setlistId, planRevision, currentCueId, cue별 대기/진행/완료/건너뜀, executionRevision, 타이머 상태를 소유한다. 선택한 편집 cue와 currentCueId는 별개다. 계획 변경 시 동일 cue ID만 세션에 연결하고 변경된 자료는 재준비한다. 활성 큐 삭제·현재 연결 자료 교체는 진행 종료 또는 명시 전환 후 허용한다. 새 cue는 대기, 삭제된 비활성 cue의 기록은 요약에만 남긴다.

완료 시 실제 소요 시간·진행 기록을 별도 ServiceRun 요약에 저장한다. 실행 중에는 cue 전환·타이머 조작 시 최소 복구 체크포인트를 원자 저장하며 1초 tick마다 디스크에 쓰지 않는다. 요약은 예배당 최근 20개, 전체 2MiB 이내로 제한하고 초과 시 오래된 요약부터 제거한다. 메모/일시 안내 본문은 기록하지 않는다. 재시작 시 체크포인트를 '중단된 예배'로 보여주며 `재개`/`새로 시작`을 선택한다. 재개도 화면/소리를 자동 재생하지 않고 타이머는 일시정지에서 확인 후 재개한다.

새 설정은 타입, 기본값, Zod, 저장 projection, 런타임 변경 감지, 백업을 함께 갱신한다. Stage 배치·기본 안내 유지시간·시간 경고값이 대상이다. 창 재연결은 최신 버전 snapshot을 받고, 만료된 안내는 보내지 않는다. F2 전체 중단은 모든 시각 출력·오디오·무대 안내를 지우고 타이머를 일시정지하며 실행 대기를 취소한다. 재개는 운영자가 선택한다.

## 2026-10-16 구현 조정

workspace-v4와 portable backup schema 3을 적용했다. ServicePlanSchema의 구조 상한은 이전 파일의 기존 10,000행을 보존하기 위한 값이며 새 작성/추가에서는 Repository가 1,000개를 제한한다. 이전 자료를 새 상한에 맞춰 자르지 않는다. 곡 보기 정렬·AI 적용/Undo·콘티 복제에도 전체 계획을 연결했다.

큐시트 입력은 별도 입력 창에서 제목·시간과 선택 상세를 함께 확인한 후 명시 저장한다. 기존 예배별 곡 편집의 자동 저장은 유지한다. 순서 정책과 자료 연결이 반만 저장되는 것을 막기 위해 입력 창의 적용 단위를 한 트랜잭션으로 정했다. 입력 초안은 로컬 복구 기록에 보존하고 충돌 시 자동 덮어쓰지 않는다.

웹 source가 비활성화되는 전환은 기존 coordinator의 웹 음소거 정책이 소리 유지보다 우선한다. 예배 소유 PDF가 참조하는 파일은 해시가 다른 파일로 다시 연결할 수 없으며 새 PDF 등록 후 명시적으로 연결해야 한다. 본문 사본에 연결한 이미지·영상 assets의 재연결 정책은 후속 보완/수용 항목이다.

현재 saveServicePlan은 requestId를 통해 세션 내 중복 저장을 제거한다. 자료 연결 명령은 revision 비교와 UI 중복 실행 차단을 적용했으며 동일 requestId 재시도 영수증은 후속 작업이다. 예배 단독 service 파일은 아직 구현하지 않았고 기존 playlist로 비곡 순서를 보존한다고 안내하지 않는다.

## 2026-10-16 P5a 계약 완성
