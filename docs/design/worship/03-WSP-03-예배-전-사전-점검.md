# WSP-03 예배 전 사전 점검

2026-10-16 · 설계 v1 · 로컬 구현·수용 반영 · [공통 계약](예배-운영-기능-공통-계약.md) · 수용: WSP-T03

## 목적·검사 범위

운영자가 예배 시작 전에 누락 자료와 준비 상태를 찾고 바로 수정하도록 돕는다. 자동 검사 결과와 사람이 확인해야 하는 실제 화면·소리를 구분한다. 검사 자체는 현재 송출·오디오·브라우저 탐색을 바꾸지 않는다.

| 검사 | 자동으로 확인할 것 | 결과 해석 |
| --- | --- | --- |
| 계획 | ID/참조/페이지/시간·policy 유효성 | 구조 오류는 실행 차단 |
| 로컬 자료 | asset 존재·종류·등록 메타데이터·PDF 페이지 범위 | 미디어 디코딩·실제 소리는 별도 |
| 슬라이드 | 설정한 출력 크기/폰트의 텍스트 측정·캔버스 경계 | 잘림 가능성 경고, 사람이 미리보기 확인 |
| 출력 창 | 지정 화면 존재, 창 ready/applied 상태 | 물리 케이블·프로젝터 상태 보증 아님 |
| 웹 | 저장 주소 유효성, 해당 자료의 현재 준비 상태 | 로그인·접속·DRM은 수동 확인 |
| 저장 | pending/error·백업 가능 여부 | 저장 실패는 준비 완료 판정 차단 |
| 현장 | Main·Stage 가독성, 실제 소리, 비상 중단, 오프라인 리허설 | 운영자가 직접 확인 |

검사를 위해 웹 주소에 자동 접속하지 않는다. 로그인 확인은 기존 준비 패널의 `열어 확인`으로 이동하며 운영자가 실행한다. 전체 파일 해시/긴 영상 디코딩은 기본 검사에서 제외하고 누락 의심 파일만 추가 확인한다.

## 화면·사용 흐름

전체 순서 상단 더 보기 또는 작은 `사전 점검` 상태 버튼에서 연다. 결과는 '확인 필요 N개 / 권장 N개 / 수동 확인 N개'로 요약하며, 정상 항목은 기본 접는다. 각 행에는 문제·대상 순서·다음 조치 하나를 보여준다.

1. 현재 계획과 출력 설정 revision을 고정해 검사 실행. 진행률은 검사한 항목 수로 표시한다.
2. 문제 행 `수정하기`로 cue/자료/설정에 이동한다. 점검 창을 닫아도 검사 결과를 유지한다.
3. 돌아오면 변경된 범위에 `재검사 필요` 표시. `다시 검사`로 최신 상태를 평가한다.
4. 수동 항목에는 `직접 확인함` 체크와 시각만 남긴다. 실제 사람 이름은 기록하지 않는다.
5. 자동 차단 없음·필수 수동 확인 완료일 때 `준비 확인 완료`. 경고는 명시적으로 확인하고 남겨둘 수 있다.

사전 점검 완료는 예배 시작의 전역 허가 스위치가 아니다. 실행 시에는 항상 현재 cue를 다시 검증한다. 웹 자료를 당일 쓰지 않으면 해당 cue를 건너뛰거나 화면 정책을 수정할 수 있다. 오류를 숨기기 위한 '모두 무시' 버튼은 제공하지 않는다.

## 결과 모델·유효기간

`PreflightRun { id, setlistId, setlistRevision, dependencyFingerprint, startedAt, completedAt?, cancelledAt?, results[] }`를 사용한다. 결과는 `checkId, cueId?, severity(blocking/warning/manual/info), status(pass/fail/unchecked/acknowledged), code, action`이다. 사용자에게 보이는 설명은 code로 생성하며 파일 절대 경로·원문을 진단에 저장하지 않는다.

dependencyFingerprint는 실제 참조 자료 revision·asset 등록/삭제 세대·출력 설정 revision·화면 topology 세대·폰트 로드 세대를 포함한다. cue 이동·정책 변경도 전체 요약을 무효화한다. 내용 변경은 해당 cue 검사, 화면/폰트 변경은 레이아웃과 수동 가독성 확인을 무효화한다. 예배 날짜 변경·새 앱 실행·새 예배 복제는 수동 확인을 초기화한다. 자정 경과만으로 같은 예배의 확인을 지우지 않고 세션과 날짜 변경으로 관리한다.

결과는 실행 중 메모리, 최종 요약은 예배당 최근 1회만 저장한다. 전체 백업에는 포함할 수 있지만 가져오기에서는 '과거 기록'으로만 표시하고 완료 효력을 부여하지 않는다. 취소된 부분 결과는 준비 완료로 채택하지 않는다. 저장 실패는 UI에서 실패를 명시한다.

## 성능·복구·표현

한 번에 하나의 점검 작업만 실행한다. 로컬 asset 검사 동시성 4, 슬라이드 측정은 작은 batch로 yield하며 동일 자료는 검사 내 캐시를 재사용한다. 취소하면 다음 batch와 결과 발행을 막는다. 실행 중 콘티가 바뀌면 결과는 원래 콘티에 남기고 현재 콘티 점검으로 오인하지 않게 제목을 고정한다. 변경된 revision 결과는 '이전 내용 기준'으로 표시한다.

폰트 미로드·측정 불가·파일 접근 실패는 pass로 바꾸지 않고 수동 확인/오류를 반환한다. 긴 문장을 자동 축소·분할하지 않으며 수정 제안만 한다. 정보/경고/차단은 아이콘+문구로 구분한다. 1024×768에서 결과는 단일 세로 목록, 수정 후 원래 문제 행으로 포커스를 복귀한다.

## 개발·수용

순수 검사 엔진 → repository/asset/display 어댑터 → 읽기 전용 결과 UI → 수정 복귀·무효화 → 현장 확인 체크 순으로 구현한다. 합성 cue 1,000개에서 UI 입력·취소가 유지되는지 측정하고 장비·자료 크기·소요 시간을 보고한다. 목표 취소 반영은 1초 이내이며 실측 전 달성했다고 기록하지 않는다.

파일 누락·페이지 초과·폰트 미준비·revision 변경·검사 취소를 테스트한다. 사전 점검 중 청중 화면·소리·현재 source가 바뀌지 않아야 한다. 물리 프로젝터·Stage·스피커 검사는 운영자 체크와 현장 증거로만 완료 처리한다.

## 2026-10-16 구현 확정

최근 요약은 별도 로컬 파일에만 보관하고 새 앱 실행에서는 현재 준비 완료로 승계하지 않는다. 전체 백업에 요약을 추가하지 않았다. 결과는 새 자료/새 예배에 효력을 주지 않는다. 본문 측정은20슬라이드 yield, 본문5,000자/전체10,000슬라이드 상한 이후 수동 확인으로 조정했다. 실물 장비 검사를 자동 pass로 대체하지 않는다. [계약·성능·검증 결과](../../quality/2026-10-16-사전-점검-검증.md).
