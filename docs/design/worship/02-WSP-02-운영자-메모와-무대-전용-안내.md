# WSP-02 운영자 메모와 무대 전용 안내

2026-10-16 · 설계 v1 · 로컬 구현·수용 반영 · [공통 계약](예배-운영-기능-공통-계약.md) · 수용: WSP-T02

## 목적·정보 구분

순서에 남기는 지속 메모와 진행 중 무대에 보내는 일시 안내를 분리한다. 운영자 메모는 예배 준비·인수인계용이며 Control에서만 보인다. stageNote는 무대 안내 초안으로 저장하되 진행 시 자동 표시하지 않는다. 실제 안내는 `무대에 보내기`로만 발행한다. 기존 청중용 하단 자막 기능과 입력창·데이터·대상을 공유하지 않는다.

| 정보 | 영속 | 노출 | 기본 내보내기 |
| --- | --- | --- | --- |
| operatorNote | 예배 cue | Control | 꺼짐 |
| stageNote | 예배 cue | Control의 안내 초안 | 꺼짐 |
| StageMessage | 메모리만 | Control 상태·Stage | 항상 제외 |

## 화면·사용 흐름

선택 순서의 상세에 `운영 메모`와 접힌 `무대 안내`를 둔다. 입력창은 대상 이름을 항상 표시한다. 순서 행에는 내용 전체 대신 메모 아이콘만 표시하며 접근 가능한 이름에 '메모 있음'을 넣는다.

1. 운영 메모 작성 → 자동 저장 상태 확인 → 다른 순서로 전환. 저장 실패 시 초안을 유지하고 재시도할 수 있다.
2. 무대 안내 열기 → 저장된 초안 또는 직접 입력 → 유지시간 선택 → Stage 미리보기 확인 → `무대에 보내기`.
3. Control 상단의 작은 표시줄에 `무대 표시 중 · 남은 18초 · 지우기`를 표시한다. 메모를 편집해도 표시 중인 안내 본문은 바뀌지 않는다.
4. 다른 안내를 보내면 이전 안내를 대체한다. 교체될 문구를 미리보기에서 보여주며 같은 버튼 중복 클릭은 한 번만 처리한다.
5. 만료·지우기·F2 중단 시 Stage에서 제거하고 Control 상태도 함께 바꾼다. 선택 cue가 바뀌었다고 안내를 지우거나 다시 보내지 않는다.

Stage에는 상단 고정 안내 영역을 확보하고 가사를 가리지 않는다. 안내가 없으면 가사 영역이 공간을 회수한다. 최대 두 줄·120자로 제한하고 한글 긴 문장도 잘림 없이 줄바꿈한다. 표시 전에 두 줄을 넘으면 전송을 막고 문구 축약을 안내한다. 큰 글씨와 '안내' 표식으로 구분하며 깜빡임·소리를 기본 제공하지 않는다.

## 데이터·발행·시간

`StageMessage { id, sessionId, text, sentAt, expiresAt?, revision }`를 Main이 소유한다. text는 trim 후 1~120자 plain text, TTL은 5/10/20/30/60초 또는 `직접 지울 때까지`다. 기본 20초이며 무기한은 표시줄에 `직접 지우기 필요`를 명시한다. 만료 판단은 Main 시간 서비스가 수행한다. Renderer의 로컬 카운트가 발행 상태를 결정하지 않는다.

send는 expectedMessageRevision으로 경쟁을 검사한다. clear는 대상 messageId를 포함해 늦은 지우기가 새 안내를 지우지 않게 한다. Stage 재연결 시 아직 유효한 최신 안내만 보낸다. 앱 재시작은 모두 제거한다. Stage 창이 없으면 전송 버튼은 비활성이고 `무대 화면 열기`를 제공한다. 창이 열렸지만 ack 대기 중이면 `표시 확인 중`, 시간초과면 `무대 표시 확인 필요`로 표시한다. 전송 수락과 실제 렌더 확인을 구분한다.

청중 OutputSchema와 시각 합성에는 StageMessage 필드를 추가하지 않는다. Main의 권한 검사와 별도 Stage payload projection으로 차단한다. 작업 공간·백업·ServiceRun에는 일시 안내 본문을 넣지 않는다. stageNote는 백업에는 보존하되 공유용 PDF에서 기본 제외한다.

## 빈 상태·오류·접근성

선택한 순서가 없으면 일반 무대 안내만 보낼 수 있고 저장 메모는 편집할 수 없다. 빈/공백·초과 안내는 입력 아래 한 문장으로 안내한다. 전송 실패 시 입력을 보존하고 재전송은 최신 revision을 확인한다. 실패한 요청 때문에 기존 무대 안내가 사라지지 않는다.

키보드로 입력·TTL·미리보기·전송·지우기에 접근한다. Enter는 줄바꿈이며 전송 단축키를 기본 할당하지 않는다. IME 조합 종료가 전송으로 해석되지 않는다. 모달·서브패널 닫기 후 원래 버튼으로 포커스 복귀한다. 좁은 창에서는 두 메모를 탭으로 나누지 않고 세로로 배치해 대상 라벨을 계속 보이게 한다.

## 개발·수용

메모 저장·Undo → Stage payload와 수명 서비스 → 안내 UI → 재연결/만료/보안 회귀 순으로 개발한다. 메모 Undo는 저장 내용만 복원하며 전송을 다시 실행하지 않는다. StageMessage UI 변경에 따른 가사 맞춤 재계산을 검사한다.

Control에만 있는 문구가 청중 IPC·Main DOM·PDF 기본 출력에 없는지 직접 검사한다. 만료와 재연결이 겹쳐도 안내가 부활하지 않아야 한다. 실제 Stage 모니터에서 가사·타이머와 동시 표시 시 가독성 확인을 별도 수행한다.

## 2026-10-16 구현 확정

P1과 같은 명시 저장·초안 복구를 사용한다. Control과 Stage가 같은 글꼴/측정으로 현재 Stage 창의 두 줄 제한을 확인한다. renderer ack를 별도 channel로 받아 수락과 표시 확인을 분리했고 Control 상단에 현재 안내를 고정 표시했다. Main monotonic deadline과 TTL timer가 만료를 소유한다. [로컬 수용 결과](../../quality/2026-10-16-운영-메모-무대-안내-검증.md).
