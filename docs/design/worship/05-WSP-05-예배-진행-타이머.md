# WSP-05 예배 진행 타이머

2026-10-16 · 설계 v1 · 로컬 구현·수용 반영 · [공통 계약](예배-운영-기능-공통-계약.md) · 수용: WSP-T05

## 목적과 시간 의미

운영자에게 현재 순서의 경과와 전체 예배의 예상 지연을, 무대에는 선택한 남은 시간을 보여준다. 실제 진행 기록과 계획 시간을 분리하며 0초 도달로 화면이나 다음 순서를 자동 실행하지 않는다. 기존 clock/timer Prop과 별도 서비스로 구현하고 청중 출력에는 기본 표시하지 않는다.

| 시간 | 계산 기준 | 미입력 처리 |
| --- | --- | --- |
| 계획 시작 | 예배 시작 instant + 앞 순서 duration 합 | 앞 순서에 미정 있으면 이후는 '시각 미정' |
| 순서 경과 | 해당 실행 구간의 단조 시간 누적 | 항상 측정 가능 |
| 순서 남음 | 설정 duration - 타이머 누적 | 카운트업만 제공 |
| 전체 경과 | 예배 세션 시작 후 실제 벽시계 경과 | 일시정지 중도 포함 |
| 계획 대비 지연 | 실제 경과 - 현재 위치까지 계획 경과 | 계획이 불완전하면 '일부 시간 미정' |
| 예상 종료 | 현재 시각 + 현재 남은 시간의 0 이상 값 + 이후 계획 합 | 미정 있으면 총 종료는 미정, 알려진 합만 표시 |

예배 일시중단 시간은 전체 실제 경과에 포함하며, 타이머의 일시정지는 해당 카운트만 멈춘다. 운영자가 계획 시작을 늦게 잡아도 실제 시작과 분리해 표시한다. 과거 cue 재진행은 새 구간을 만들어 총 소요에 더한다.

## 화면·사용 흐름

Control 현재 진행 표시줄에는 `설교 · 12:30 경과`와 작은 시간 버튼만 기본 표시한다. 펼치면 시작/일시정지/재개/초기화, `+1분`, `무대 표시`를 제공한다. 전체 계획 대비 지연은 시작 시각과 duration이 유효할 때만 보인다. 상세 통계는 더 보기에 둔다.

1. 순서에 예상 시간을 입력하거나 `타이머 설정`에서 카운트다운/카운트업과 경고 시간을 정한다.
2. cue 진행은 실제 구간 경과 측정을 시작한다. 별도 타이머 자동 시작은 기본 꺼짐이다. 켜려면 cue 설정에서 명시한다.
3. `타이머 시작` 후 Stage 표시를 켜면 현재/다음 가사 위 고정 시간 영역에 표시한다. 무대 메시지 영역과 겹치지 않는다.
4. 카운트다운은 0 뒤에 `1:23 초과`로 계속 표시한다. 기본 경고는 남음 2분 이하 주의, 0 이하 초과이며 문구·아이콘을 함께 쓴다.
5. 다음 cue 진행 성공 시 이전 타이머는 정지·기록, 새 cue는 기본 대기 또는 명시한 자동 시작을 따른다. 준비 선택만으로 시간은 바뀌지 않는다.

초기화는 타이머 카운트만 0/설정값으로 돌리며 실제 예배 실행 기록은 지우지 않는다. `+1분`은 타이머 목표만 늘리고 원래 계획은 유지한다. 표시줄에 `계획 30분 · 타이머 31분`으로 차이를 보이며 지연 계산은 원래 계획을 사용한다. 실행 중 계획 변경은 이후 cue에 즉시 적용하되 현재 timer 목표는 별도 '현재 타이머에도 반영'을 실행해야 한다.

## 데이터와 시간 소유권

`TimerPreset { mode, targetSeconds?, warningSeconds, autoStart, showOnStage }`를 cue에 저장한다. target은 1~86,400초, warning은 0~target, 카운트업은 warning 없음이다. 실제 시간은 Main 서비스가 monotonic clock으로 계산한다. UI의 1초 tick은 표시 갱신에만 쓰고 상태를 매번 IPC로 되돌리지 않는다.

`TimerRuntime { sessionId, cueId, runId, state(idle/running/paused/finished), elapsedMs, targetSeconds?, revision, sampledAt }`를 snapshot으로 발행한다. Stage는 샘플 사이를 보간하되 Main 동기화 시 교정한다. OS 벽시계 변경은 duration을 바꾸지 않는다. 절전은 suspend/resume 이벤트에서 타이머를 일시정지하고 마지막 확인값을 유지하며 '절전으로 일시정지' 안내 후 운영자가 재개한다. 실제 전체 벽시계 경과에는 절전이 포함된다.

Control renderer 재생성은 Main runtime을 받는다. Stage 재연결도 현재 상태를 받는다. Main 재시작은 checkpoint를 읽어 paused로 복구하고 자동 진행·자동 표시하지 않는다. IPC command는 expectedTimerRevision으로 오래된 pause/+1분 응답을 거절한다. F2는 타이머 pause·Stage 표시 제거이며 재개는 명시한다.

## 빈 상태·오류·접근성

진행 중인 cue가 없으면 `순서를 진행한 뒤 타이머를 시작하세요`를 표시한다. 무대 창이 없더라도 Control 타이머는 사용할 수 있고 무대 표시만 비활성이다. duration 미정은 0분으로 표시하지 않는다. 화면이 좁으면 전체 시계보다 현재 타이머와 정지 제어를 우선한다.

타이머 숫자를 매초 스크린리더 live region으로 읽지 않는다. 시작·정지·경고 진입만 알린다. 색상 외 '남음/초과'를 붙이고 깜빡임·알림 소리를 기본 제공하지 않는다. UI 응답이 멈춰도 Main 시간은 계속 진행하며 복귀 시 최신 값을 표시한다.

## 구현·수용

주입 가능한 clock 기반 계산 엔진 → 세션·checkpoint → Control 표시 → Stage 배치 → 절전·재연결을 구현한다. fake clock으로 경계/연장/재진행/시계 변경을 검증하고 실제 장시간 실행으로 drift를 측정한다. 60분 기준 ±1초 목표를 제안하며 실측 환경과 결과를 별도 남긴다. 0초에 자동 송출이 없고 청중 payload에 시간 정보가 없는지 확인한다.

## 2026-10-16 구현 계약 조정

Timer runtime/최근1,000개 마감 요약은 별도 로컬 체크포인트에 보관하고 세션 실행 UUID로 연결한다. 계획·백업·휴대 파일에는 runtime을 넣지 않는다. 정상 닫기/명령/10초 주기로 저장하며 비정상 종료는 마지막 확인 checkpoint를 paused·Stage 숨김으로 복원한다. 계산/저장/수신 대상과 단기 실측·60분 미검증은 [검증 기록](../../quality/2026-10-16-예배-타이머-검증.md)에 구분한다.
