# 예배 저장 기반과 전체 순서 첫 구현 검증

2026-10-16 Asia/Seoul · 기준 HEAD `4dbdd7d` + 기존 미커밋 변경 및 이번 diff · WSP-P0 로컬 검증 / WSP-P1 구현·수용 진행 중

## 구현 범위

- workspace-v4: v1/v2/v3 원본·백업 bytes 보존, 전체 계획/곡 투영의 원자 저장, 미래 버전 쓰기 차단, 보관함/휴지통·사본 유지.
- ServicePlan: 엄격한 필드·범위·중복/고아 참조·소유권 검증, 자료 사본, 새 예배 1,000개/이전 10,000행 보존, AI 적용·Undo·콘티 복제 연결.
- portable backup 3: 계획·예배 소유 본문/외부 자료·assets의 전체 백업/복원. 이전 backup 1/2 읽기 유지. 예배 단독 service 파일은 아직 미구현.
- Control 전용 API: 계획 저장 requestId 중복 제거·revision 충돌, 자료 연결+메타데이터의 한 트랜잭션 저장, Main/Stage에서 변경 API 미노출.
- 전체 순서 UI: 곡/전체 보기, 새 순서·담당자·시간·운영 메모·자료/화면 정책의 명시 저장, 선택 무송출, 정렬·제거·Undo, 입력 초안 보존·충돌 후 명시 재적용.
- ServiceSessions: 준비 토큰·source revision/generation·출력 버전 확인, 명시 진행, 재시도 중복 제거, 중단/완료, 재시작 시 interrupted 복구, 예배당 최근 20회/2MiB 이내 진행 기록. 일시 안내·메모 본문은 실행 기록에 없음.
- 진행 중 변경/삭제 제한, 업데이트 설치 차단, F2의 늦은 결과 차단. native 출력 완료 전에 interrupted 체크포인트를 먼저 기록해 디스크 실패가 화면 변경으로 이어지지 않게 구성.

단위/계약 검사는 합성 데이터와 오류 주입으로 수행했다. 미래 스키마 차단·v3 원본/체크포인트 불변·동시 동일 요청·stale 편집·디스크 실패 후 같은 요청 재시도·혼합 순서 투영·비곡 메모 보존·사본 수정 독립성·전체 백업·실패한 연결의 원자성·F2 중 출력 대기·재시작 비자동 실행을 포함한다.

신규 Electron 검사는 feature flow 전에 실제 app.getPath('userData')가 임시 PROPRE_TEST_USER_DATA와 일치하고 Application Support가 아님을 단언한다. 기존 AI/성경 삽입/개발 시작 helper에서 누락된 동일 단언도 추가했다. 실제 사용자의 workspace·예배 자료·키는 테스트 입력으로 사용하지 않았다.

## 발견·수정한 문제

1. headless Main이 보이지 않는다는 이유로 기존 창에 다시 show/focus를 호출해 resize generation이 바뀌고 순서 진행이 취소됐다. visibility 대신 창 존재/파괴 상태로 생성 여부를 판단하도록 수정하고 전용 native 검사를 통과했다.
2. 1024×768에서 상세·메모·Undo와 목록이 합쳐져 진행 버튼 일부가 아래 패널에 가려졌다. 목록/상세를 스크롤 영역에 두고 준비·진행을 독립된 고정 하단에 배치했다. 두 버튼 모두 viewport에 완전히 포함됨을 검사했다.
3. 새 콘티의 기본 전체 순서 보기에 따라 기존 제목/행 배치 검사의 전제가 바뀌었다. 새 기본 보기의 선택 상태를 검증하고 곡 보기로 전환한 뒤 기존 한 줄 제목/개수 배치를 검사하도록 갱신했다. 수정 전 최종 전체 실행은 76/77, 갱신 후 77/77이다.
4. 진행 중 사용자 입력/늦은 일반 snapshot이 native 전환을 덮지 않도록 기존 operator lock을 사용하고 전환 중 Main의 일반 Output/Stage 발행을 제한했다. F2는 계속 허용한다.

개발 시작 실패를 의도적으로 만드는 검사에는 React preamble 오류 로그가 출력되며, 해당 오류 경로의 종료 검사는 통과했다. 실제 정상 시작 실패로 분류하지 않는다.

## 미완료와 다음 경계

WSP-01 전체 수용 완료로 표시하지 않는다. 예배 단독 service 파일, 자료 연결 requestId 재시도 영수증, 예배 소유 웹/PDF의 전용 native 전환·복귀 검사, 연결 페이지/회전 편집, 진행 중 수동 송출 상태와 다음 순서 편의, 이미지/영상 재연결의 과거 사본 보존, 입력 충돌·포커스 복구의 전용 검사가 남았다. 이를 마친 후 WSP-P2 무대 안내로 진행한다.

자동 업데이트 설치 guard는 새 세션과 연결했고 서비스의 active 수명과 기존 업데이트 회귀를 확인했다. 실제 서명 설치 프로세스로 진행 중 차단을 수용한 것은 아니다. 물리 프로젝터/Stage/스피커·실제 웹 로그인/DRM·Windows·실 인쇄·배포·사용자 과제 평가는 이번 범위가 아니다.
