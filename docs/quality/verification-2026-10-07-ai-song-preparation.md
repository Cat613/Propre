# AI 찬양 준비 구현 검증

2026-10-07 Asia/Seoul · REQ-037 / TASK-032 / TC-037 / ADR-014 / FLOW-011

다른 세션의 콘티 보관함 적용이 완료된 것을 확인한 뒤 개발했다. 기존 변경을 임시 기준 사본과 hash로 보관했으며 기존 파일을 삭제하지 않았다. 관련 소스 버전은 [source manifest](source-manifest-2026-10-07-ai-song-preparation.json)에 기록했다. 실제 사용자 자료나 API 키를 테스트 입력으로 사용하지 않았다. 기능 구현·합성 API 계약·격리 앱 검증과 실제 모델의 악보 품질 평가는 구분한다.

## 신규 단위 검사

`tests/song-preparation.test.ts`는 A2/B2/C1/TAG1의 `A B A B×2 C B TAG` 14장 전개, 반복별 고유 ID·색상·진행 매핑, 빈 간주 본문, 파일 왕복, 잘못된 파트/반복/한도, 새 곡 등록·기존 append ID·같은 곡 반복, 현재 draft 보존, 기존 원곡 유지/명시적 갱신·역사 사본 보존, replace의 원자 저장, 재시작 영수증 중복 방지, 다른 계획의 같은 requestId 거절, 콘티/원곡/신규 후보 충돌, 저장 실패 전체 미적용·재시도, 변경 후 undo 거절을 검사한다.

`tests/song-providers.test.ts`는 Gemini/OpenAI/Claude의 PDF 전달·도구 정의·원시 응답·후속 결과 회신·usage·Gemini signature 보존을 합성 응답으로 확인한다. Gemini의 parametersJsonSchema와 OpenAI의 parameters 계약을 구분하며 키가 요청 본문/반환 상태에 포함되지 않음을 확인한다. 인증 오류·불완전 출력·요청 크기·AbortSignal을 검사한다.

`tests/song-jobs.test.ts`는 PDF 해독·복사·hash, 공식 SDK의 실제 내부 MCP 발견/호출/스테이징/승인 적용, 모델의 원곡 갱신/확인 권한 제거, 추정 송폼 자동 적용 중단, 원곡 후보 연결, 출처 변조·위장 파일·파일 수 거절, 취소 후 늦은 결과 거절, 미완료 작업 복구, 연결별 키/기본 변경/제공자 변경 경계, 완료 원문 만료·명시 보관·중단 초안 보호, 부분 실패의 성공 초안 보존과 선택 파일만 재전송을 검사한다.

## 신규 앱 시나리오

`tests/electron/song-preparation.spec.ts`의 5개 시나리오는 모든 창을 임시 userData로 시작하고 실제 `app.getPath('userData')`를 먼저 확인한다. 실제 파일 picker 결과와 provider 응답만 합성 자료로 제어한다.

- PDF 선택 → 로컬 PDF.js 원문 페이지 표시 → 가사 수정·반복 변경 → 새 곡 자동 등록·append → 순서 되돌리기 → 재시작. 현재 draft·메인/모니터 송출·기존 항목 ID 보존을 확인한다.
- OpenAI 연결 선택 → 확인이 필요 없는 결과의 자동 replace → 새 곡/콘티/적용 기록 저장.
- Claude 연결 선택 → 동일한 자동 replace·현재 편집본 보존.
- 추정/불확실 송폼은 자동 적용을 멈추고, 잘못된 반복 수정은 저장·원래 콘티 변경 없이 오류를 보여준다.
- Electron의 실제 이미지 디코더로 만든 PNG를 읽고 원본을 표시한다. 검토 가사를 수정한 뒤 창을 닫아도 재열기에서 복구되고 원본 보관 선택도 유지된다.

준비 미리보기 화면을 캡처해 가사·파트·반복·원곡 연결·적용 버튼의 배치를 직접 확인했다. 기존 외부 MCP/성경 삽입/자동 저장/창 재시작/파일 이동/콘티 보관함/메인·모니터 스타일 회귀도 포함했다. 개발 시작 실패를 의도적으로 발생시키는 기존 시나리오의 React preamble 오류 출력은 해당 실패 종료 검사의 입력이며 전체 검사는 통과했다.

## 저장과 개인정보 경계

workspace-v2의 songReceipts는 선택적 기본 배열을 사용해 기존 저장 파일을 읽는다. 송폼·슬라이드 매핑은 PresentationSchema 및 portable 파일에 보존하며 곡 내용 중복 비교에서도 송폼을 고려한다. 원문 준비 파일은 일반 미디어·발표·백업에 자동 포함하지 않는다. 새 라이선스 원문은 앱 패키지에 포함했다. 작업/Provider 로그에는 가사·원문·키·개인 경로를 기록하지 않았다.

실제 계정에 분석 요청을 보내지 않았다. 모델 ID 접근, 비용, 한국어 스캔·텍스트 악보의 OCR 정확성, 절/후렴/엔딩과 D.C./D.S./Coda 해석은 운영자가 실제 자료로 대조해야 한다. 로컬 구현과 합성 도구 성공을 실제 모델 품질 평가로 기록하지 않는다.
