# 앱 업데이트 검증

> 이전 서명·자동 설치 방식의 실행 기록이다. 현재 무료 다운로드 방식은 [새 검증 기록](2026-10-16-무료-다운로드-업데이트-검증.md)을 따른다.

2026-10-16 · REQ-040 / TASK-040 / TC-040 / ADR-017. [설계](../engineering/프로프리-앱-업데이트-설계.md), [배포 절차](../operations/앱-설치와-업데이트-배포.md).

## 범위

기존 수정이 많은 checkout의 변경을 보존하고 자동 업데이트 service·Control UI/IPC·Main 저장/송출 잠금·릴리즈 설정을 추가했다. 테스트는 임시 `PROPRE_TEST_USER_DATA`를 사용하고 실제 `app.getPath('userData')` 일치를 확인했다. 패키지 검사는 GUI 사용자 자료를 열지 않는다.

## 자동 증거

- 상태/배포 설정/native 어댑터 17개: 비설정 빌드의 무접속, 자동 확인과 수동 다운로드, 일반 종료 자동 설치 비활성, 다운로드/설치 중복 거절, 저장 거절 후 재시도, 원시 오류 비노출, native 검증/시간 초과 후 늦은 이벤트의 재시작 방지, 4시간 확인과 리스너 정리, HTTPS 및 인증정보 없는 URL 검증.
- 송출 잠금 3개: 업데이트 중 새 창·토글 차단, 비동기 창 열기 중 활동 표시, 저장 실패 후 활동 표시 정리.
- Electron 업데이트 4개: 개발 실행 비활성, 알림/진행률/오류/설치 모달, 메인·모니터 실행 중 재시작 비활성 및 송출 preload 메서드 미노출, 실제 Electron 프로세스에서 생산 updater chunk 초기화. 이 UI 검사는 Main 상태 이벤트를 합성하며 실제 새 버전 서버를 사용하지 않는다.
- 타입·lint·형식·생산 빌드와 Renderer 번들 예산 검사. core JS 640,977 bytes.
- `package:check`: macOS arm64 unsigned 로컬 ProPre.app 및 합성 MCP stdio 호출. app.asar에 updater chunk와 라이선스 원문 포함/바이트 대조.
- updater 배포 설정을 실제 electron-builder configuration schema로 검증했다.
- `npm audit --omit=dev`: 0건. 전체 audit는 개발 도구 경로에 moderate 8건/high 1건을 보고했다. HEAD lockfile의 감사 결과와 동일하며 이번 추가로 새 권고 대상 패키지는 생기지 않았다.

처음 추가한 module-load 검사는 Playwright evaluate의 dynamic import 제한에 실패해 실제 Electron 진입 파일 방식으로 수정했다.

## 최종 검사 결과

- `npm run verify`의 lint·typecheck·전체 unit 181개·생산 빌드·bundle 검사 통과.
- 해당 실행의 Electron 전체 74개 중 73개 통과, 기존 workbench 제목 입력 검사 1개 실패. 제목을 비운 직후 기존 제목으로 돌아가 5초 내 기대값과 일치하지 않았다. 이 전체 실행을 green으로 표시하지 않는다.
- 이후 `app-update.spec.ts`, `automation.spec.ts`, `workbench.spec.ts`를 함께 재실행해 14개 전부 통과했다. 추가 업데이트 4개와 실패했던 제목 입력·AI 재시작 시나리오가 포함된다.
- 이전 회귀에서는 기존 AI 재시작 시나리오의 시작 후 저장 상태 확인이 5초 시간 초과했고, 최종 전체 및 후속 재실행에서는 통과했다. 기존 비업데이트 시나리오의 간헐 실패를 별도 기록하며 실패한 검사를 삭제하거나 기대값을 완화하지 않았다.
- `npm run format:check` 전체 통과. 배포 주소 없는 release guard의 차단도 확인했다.
- 최종 코드의 `package:check` 재실행 통과. macOS arm64 로컬 패키지 생성과 updater chunk/라이선스 포함·바이트 대조를 다시 확인했다.

## 미실행

실제 Apple Developer ID 서명·공증, 배포 주소/계정 연결, DMG/ZIP/metadata 게시, 서로 다른 서명된 A→B 설치와 실제 자료/설정 유지, 손상/서명 오류 실파일, Intel/다른 OS·물리 송출 장비·최종 사용자 수용은 수행하지 않았다. 로컬 unsigned 패키지와 mock/native UI 검사를 실제 배포 완료로 해석하지 않는다. 기존 라이선스/성경 권리·플랫폼 수용 릴리즈 gate는 유지한다.
