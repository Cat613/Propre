# 플레이리스트 파일 저장·불러오기 검증

2026-10-05 (Asia/Seoul) · REQ-036 / TASK-031 / TC-036 / ADR-013 / FLOW-010 · 결과: 구현·로컬 검사 통과

## 범위와 환경

사용자가 선택한 파일 저장·불러오기 우선 범위다. 플레이리스트 영역에 전용 두 버튼, 곡/반복 순서/자료 스타일/파트 태그 색상/참조 미디어의 휴대 파일, 순서 확인 후 곡 등록과 순서 교체를 구현했다. 동일 내용은 재사용하고 다른 내용은 새 자료로 보관한다. 여러 콘티 보관함은 후속 범위다.

기준: develop / 3f625e3에 쌓인 기존 작업 내용을 별도 임시 프로젝트로 복사하고 그 사본에서 구현·검증했다. 호스트 macOS arm64 / Node 25.2.1 / Electron 44.5.1. 실제 Electron 검사는 `PROPRE_TEST=1`과 독립된 임시 userData를 사용하고, 실행 중 `app.getPath('userData')`가 해당 경로인지 기능 실행 전에 검증한다. 합성 가사·미디어만 사용하며 사용자의 실제 찬양 데이터에 테스트를 실행하지 않았다. 검사 후 기존 공유 작업과 겹치는 변경이 없는지 비교해 기능 변경 23개 파일만 원래 프로젝트에 적용했다. 적용 직후 소스가 검증한 사본과 모두 일치함을 확인했고 원래 프로젝트의 타입 검사도 통과했다.

15개 파일 계약 검사는 자료/슬라이드 ID와 시각이 달라도 동일 내용 재사용, 제목/ID 충돌에서 기존 가사 보호, 태그 색상이 다르면 새 자료 보관, orphan 참조·순서에 없는 곡·향후 버전·설정 혼입·중복 순서 ID·잘못된 kind 거절을 포함한다. 전체 순서 교체와 곡 등록이 함께 지속되며 재시작 후 재불러와도 중복 곡이 생기지 않는다.

미디어 검사에서는 참조 미디어만 포함, 기존 asset ID가 다른 bytes인 경우 새 ID로 충돌 해소, 본문 안의 URL 문자열 유지, 같은 파일 재불러오기에서 곡/미디어 중복 방지, 손상된 bytes/누락 파일 거절을 확인했다. 원자 저장의 실제 rename 실패를 주입해 기존 디스크·메모리 상태 유지와 생성 미디어 정리를 확인했다. 최종 트랜잭션 직전에 순서가 바뀐 경우도 거절하고 생성 파일을 정리한다.

네이티브 검사는 메인과 모니터에서 현재 합성 본문을 띄운 상태로 새 콘티를 가져와 기존 선택/draft/live snapshot과 두 창의 본문이 유지되는지 비교했다. 취소를 기본값으로 둔 확인창의 순서 안내를 검사하고 출력 역할에는 파일 API가 노출되지 않음을 확인했다. UI 스크린샷에서 버튼·반복 순서·찬양 목록의 개별 곡을 시각 확인했다. 테스트의 시스템 파일/확인 대화상자 선택 응답은 합성 경로로 대체했다.

전체 Electron 검사 중 고의로 React 초기화를 깨뜨리는 기존 장애 복구 검사에서 개발 서버 오류 메시지가 발생한다. 해당 복구 검사는 통과했다. 숨겨진 테스트 창의 상태는 실제 송출 장비 연결 증거로 해석하지 않는다.

## 남은 확인과 전달

설치용 앱 배포·서명/공증·다른 컴퓨터로 파일 이동하는 운영자 수용 검사·물리 송출 장비 검사는 수행하지 않았다. 소스와 로컬 실행 기능의 완료이며 공개 릴리즈 완료를 의미하지 않는다. [사용 안내](../operations/playlist-files.md)와 [데이터 계약](../engineering/data-ipc-contracts.md)을 따른다.

원래 실행 앱에서 새 버튼과 기존 4곡 콘티가 표시되는 것을 확인했다. 앱 재실행 전후 실제 workspace 파일의 SHA-256이 같아 기존 가사·스타일·파트 색상·선택·순서가 byte 단위로 보존되었다. 재실행 후 Mac 화면 잠금으로 마지막 네이티브 화면 확인과 AI 세션 재허용은 진행하지 못했다. AI 연결은 기존 세션 정책에 따라 재허용해야 한다.
