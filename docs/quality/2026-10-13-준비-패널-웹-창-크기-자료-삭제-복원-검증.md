# 준비 패널·웹 창 크기·자료 삭제 복원 검증

2026-10-13 (Asia/Seoul) · REQ-039 / TC-039

[사용 안내](../product/웹-PDF-송출-기능-상세-안내.md) · [운영 안내](../operations/웹-PDF-화면-송출.md)

## 요청과 변경

사용자가 별도 웹 준비 창의 크기를 조절할 수 없다고 보고했고, 닫기 문제는 별도 창이 아니라 컨트롤 안의 웹 준비 패널이라고 명확히 했다. 이어 자료 삭제를 되돌릴 수 없다고 보고했다. 기존 변경은 보존하며 이번 시작 HEAD·hash는 `/tmp/propre-preparation-controls-baseline.json`에 기록했다.

1. 준비 창을 resizable로 바꾸고 resize 시 native 웹 view의 bounds를 갱신한다. 최초 크기는 화면 작업 영역 안에 맞추고 최소 480×320을 사용한다. resize는 준비 확인을 무효화하며 재확인은 창을 출력 크기로 강제 되돌리지 않는다. 송출에서는 메인 창 크기에 맞게 반응형 페이지가 다시 배치될 수 있다.
2. 컨트롤 준비 패널에 `준비 패널 닫기`를 추가했다. 선택한 자료 재클릭도 패널을 접는다. 현재 송출·등록·별도 브라우저 상태를 유지한다. 늦게 완료된 준비 결과가 접은 패널에 적용되지 않도록 요청 번호를 무효화한다. 현재 송출의 복귀/중지 도구는 유지한다.
3. 자료를 활성 목록에서 숨기는 삭제 표시와 revision을 저장한다. `삭제 되돌리기`는 최근 삭제부터 복원하고 삭제 뒤 해당 버튼에 초점을 옮겨 자료 영역 Ctrl/Cmd+Z를 지원한다. 슬라이드 편집 Undo와 섞지 않는다. 재시작과 전체 백업에 삭제 상태를 보존하고 삭제 PDF도 미디어 정리에서 보존한다. 영구 삭제는 이번 범위에서 제공하지 않는다.
4. 복원 항목이 없을 때 이전 구현의 삭제를 최근 5개 저장 복사본에서 찾는다. 현재에 없는 자료만 복원하며 PDF는 등록 asset·원본 hash를 검증한다. 현재 곡·콘티·설정의 전체 rollback은 수행하지 않는다. 저장 복사본/원본이 없으면 오류를 표시한다. 실제 사용자 데이터의 직접 복구 작업은 실행하지 않았다.

전체 검사에는 기존 편집·슬라이드·미디어·오디오·콘티·AI·성경·저장/복구 흐름을 포함했다. 시작 HEAD `4dbdd7de94c72ff20ed385ec0e70e647d7c49a35`를 유지하고 hash 비교에서 이번 수정·문서·검사·생성 번들 외의 기존 변경을 건드리지 않았음을 확인했다.

새 단위 검사 2개: 삭제 PDF의 원본 참조 유지·6회 체크포인트 뒤 정리·재시작·전체 백업·revision 복원, 이전 hard-delete의 복사본 조회 복구와 현재 설정 보존.

새 Electron 검사 3개: 컨트롤 패널 닫기/재클릭/현재 웹 송출 유지, 준비 창 resize에 따라 innerWidth/innerHeight 변경·토큰 무효화·사용자 크기 유지, URL/PDF 삭제의 버튼/키보드 복원 및 PDF 재준비.

기존 중지 경쟁 검사에서 메인 창의 초기 URL 로딩이 끝나기 전에 window를 찾는 race가 있어 화면 URL 준비를 기다리도록 검사만 보완했다. 기능 기대 조건은 완화하지 않았다.

모든 Electron 기능 검사는 임시 `PROPRE_TEST_USER_DATA`를 사용하고 실제 app.getPath('userData')를 대조한다. 합성 HTTP 페이지와 생성 PDF만 사용한다. 실제 사용자 저장소를 여는 패키지 UI 검사는 실행하지 않는다. 실사이트·프로젝터·Windows·서명/공개 배포는 별도 수용 범위다. 커밋·푸시는 하지 않는다.
