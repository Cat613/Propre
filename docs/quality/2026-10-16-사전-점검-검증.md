# WSP-P3 사전 점검 검증

2026-10-16 · macOS arm64 / Node25.2.1 / Electron44.5.1 · HEAD4dbdd7d + dirty 작업 보존

## 최종 계약

Control 전용 `preflight` 명령과 Main 검사 서비스를 추가했다. 예배 revision·참조 문서 revision·소유 resource·asset 등록과 실제 파일 size/mtime·설정·화면 연결/health·폰트 상태로 fingerprint를 만든다. 검사 시작 중 Repository가 변경되면 시작을 거절한다. 변경 후 결과는 이전 내용 기준이며 직접 확인도 재검사 전 차단한다. 창 열기·외부 접속·출력/오디오 발행을 검사 코드에서 호출하지 않는다.

계획/곡 투영, 자료·파일 존재, PDF 페이지, 출력 창 applied 상태·디스플레이 연결을 검사한다. 웹 접속/로그인은 자동으로 실행하지 않고 수동 항목이다. 본문은 저장한 글꼴/크기의 canvas 줄바꿈·요소 경계를 측정한다. 기존 FittedText의 자동 축소를 수정하지 않고 축소/경계 위험을 경고한다. 상대 글자 단위·없는 글꼴·폰트 미준비·회전 요소·측정 상한은 직접 확인 또는 보수적 경고다. 글꼴 이름이 fallback과 구분되지 않으면 pass로 추정하지 않는다.

본문은20슬라이드마다 yield하고 한 본문5,000자를 넘으면 측정 불가로 분류한다. 전체10,000슬라이드 상한 이후도 수동 확인이다. 과도한 텍스트 때문에 UI가 멈추거나 pass로 오인하는 것을 줄이기 위한 조정이다. Main 파일/순서 검사 동시성은4, batch 사이 yield·진행 알림·취소를 제공한다. 같은 자료는 검사 내 재사용한다.

실제 메인/Stage 가독성·음향·전체 중지 리허설은 별도 체크다. 경고도 명시 확인할 수 있지만 차단 오류는 무시할 수 없다. 모든 조건을 확인해야 준비 확인 완료이며 저장 중/오류·이전 revision·취소/실패 상태는 완료가 아니다. 이 결과는 cue 실행의 전역 허가 스위치가 아니다.

예배당 최근 한 결과를 별도 service-preflight-v1.json에 원자 저장한다(최근500예배·2MiB). 코드/ID/시각/결과만 남기며 본문·개인 이름·절대 경로를 저장하지 않는다. 이전 앱 실행의 기록은 현재 준비 완료로 로드하지 않는다. 백업/파일 가져오기가 준비 완료를 부여하지 않는다.

## 검사 결과와 수정

- 전체 단위/계약26파일236개 통과. 사전 점검 신규6개는 읽기 전용·수동 확인·누락 파일/웹 무접속·fingerprint 변경·미측정·1,000cue 취소·저장 실패·새 인스턴스 비승계를 검사한다.
- 관련 Electron 사전 점검4/4 통과. 자료 누락·실제 현재 live 유지·메모리 결과 재열기·cue 수정 이동/재검사·직접 확인 저장·Stage 연결 무효화·Stage 권한 제한·1,000cue 취소/완료·큰 본문/없는 폰트·Escape 복귀를 검사했다.
- 기존 큐시트6개 검사 중 포커스 회귀를 발견했다. 공통 modal guard cleanup과 RAF 초점 이동의 경쟁을 수정해 modal guard 해제 후 선택 행으로 돌려준다. 전용 키보드 검사를3회 반복해 모두 통과했다. 새 모달의 Escape도 공통 guard에 명시 연결했다.
- 수동 체크가 저장 응답 전에 원래 값으로 돌아가는 문제를 수정했다. 확인 중 상태/낙관 체크를 표시하고 저장 실패는 되돌린다. Main도 동시 확인을 거절해 확인 하나가 다른 확인을 덮지 않게 했다. 준비 완료는 저장 확인 뒤에만 표시한다.
- native 창 생성과 URL 로드가 비동기라는 검사 전제를 보완했다. 또한 테스트 보고서 디렉터리를 공유하는 Playwright 실행을 잠깐 중복 실행해 trace 기록 오류가 생겼다. 두 실행 종료 후 순차로 다시 실행했다. 마지막4개는 단일 실행에서 통과했다.
- lint/typecheck/생산 build 통과. 폰트 fallback 검사를 추가하기 전 renderer core690,587bytes로700KB 예산 통과. 최종 전체/번들 회귀는 다음 공통 출력 변경 후 다시 수행한다.

모든 새 Electron flow는 임시 PROPRE_TEST_USER_DATA와 실제 app.getPath('userData') 일치를 먼저 확인했다. 합성 이미지/가사만 사용했다. 실제 사용자 자료와 키는 검사하지 않았다.

## 성능·화면·한계

[실측 JSON](evidence/worship-preflight-20261016/timing.json)은 합성1,000cue(찬양1개+자료 없는 기도999개) 조건의 Control 취소/재검사 wall latency다. 취소는1초 미만, 전체 완료도1초 미만이었다. 개별 수치는 해당 JSON을 기준으로 하며 대용량 실제 미디어·1,000개 서로 다른 자료 결과로 일반화하지 않는다.

[1024×768 캡처](evidence/worship-preflight-20261016/compact.png)를 열어 모달 단일 목록·차단 오류·수동 체크·재검사/닫기·하단 버튼을 시각 확인했다. 파일 크기/페이지/글꼴 상태를 검사한 것은 실제 재생·실물 장비·미디어 디코딩·음향의 수용 증거가 아니다. 실제 장비 체크는 운영자가 수행해야 한다.
