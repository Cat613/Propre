# 품질·수용 테스트 계획

> 초기 기획·검사 계획을 보존합니다. 실제 구현과 대체 정책은 [구현 결과](../operations/2026-10-04-운영-개선-구현-결과.md), [ADR-008](../governance/결정-기록.md), [후속 검증](2026-10-04-운영-개선-후속-검증.md)을 기준으로 읽습니다.

작성일: 2026-10-04 · 상태: 계획 · 관련: [요구사항](../product/요구사항-및-추적표.md), [실행 기록](2026-10-04-검증-실행-기록.md)

아래 TC는 안정화 목표를 검증할 계획이다. 초기 표본은 별도 기록의 PARSER/STORE ID로 남겼고 후속 기능의 로컬 실행은 날짜별 검증 기록에 남겼다. 그 표본을 통과했다고 전체 TC나 현장 검증을 통과한 것으로 표시하지 않는다. TC-030은 이번 문서 체계 검사에 해당한다.

## 환경과 증거 구분

| 환경 | 검사 대상 | 증명하지 못하는 것 |
| --- | --- | --- |
| 정적 검토·타입 | 코드 경로·타입·설정 | 실제 표시·저장·재생 |
| 격리 자동 검사 | 실제 parser·Store와 mock IPC/저장소 | OS 장치·파일 권한·창 표시 |
| 격리 번들 | 소스·모듈 변환·정적 자산 생성 | Electron 시작·설치·서명 |
| 네이티브 통합 | 새 userData의 Electron 창·IPC·실제 파일 | 실제 프로젝터·음향·현장 운영 |
| 실장비 | 지정 OS·모니터·프로젝터·음향 | 모든 환경과 모든 사용자 적합성 |
| 사용자 리허설 | 준비·진행·복구·종료 과제 | 설치 채널·스토어 승인 |
| 릴리즈·복원 | 설치·업그레이드·롤백·새 환경 복원 | 검사하지 않은 OS·장비 조합 |

네이티브 자동 검사는 기존 사용자 데이터와 다른 임시 userData를 사용한다. 외부 AI는 합성 이미지와 명시된 시험 계정으로만 검사하며 키·실제 자료를 로그에 남기지 않는다. 이번에 실제 API를 호출하지 않았다.

## 합성 검사 자료

- 가사: 빈 슬라이드, 한글 장문, 1개·여러 텍스트 요소, 요소만 있는 자료, content와 elements가 다른 자료.
- 성경: 공백·큰 장·숫자 권·오류·없음·역범위. 데이터 원문을 검증 로그로 복사하지 않는다.
- 파일: legacy 단일/라이브러리, 새 버전, 미래 버전, duplicate ID, 중첩 오류, 누락 미디어, 저장 실패.
- 장비: 1화면 제어, Main 추가, Stage 추가, 서로 다른 해상도·DPI, 연결 해제·재연결.
- 네트워크: 오프라인 기본 운영과 선택 AI 요청을 분리한다.

## 결함과 실행 기록

결함은 관련 REV·REQ·TASK·TC, 기준 커밋, 최소 재현, 예상·실제, 자료 보존 여부, 증거 환경, 재검사 결과를 포함한다. 실제 키·자료 내용·개인 경로를 제거한 합성 재현을 남긴다. 날짜별 실행 파일은 `verification-YYYY-MM-DD.md` 형식으로 추가하고 같은 날 여러 기준이면 구분 접미사를 사용한다.

## TC-031 창 제목·Dock 구분

환경: 실제 macOS Electron. 컨트롤·메인·모니터를 열어 고유 네이티브 제목과 Dock/창 메뉴를 확인한다. HTML 페이지 제목 변경·reload·닫기/재열기 뒤에도 이름과 현재 상태가 유지되어야 한다. REQ-031/TASK-026, N02에 연결한다.

TC-002는 사용자 후속 자동 저장 요청에 맞춰 저장 대기/실패/복구/종료와 별도 내보내기를, TC-006은 새 ID 불러오기·빈/부분 결과 보호를 검사한다. 실 실행 결과는 [후속 검증](2026-10-04-운영-개선-후속-검증.md)에 있다.

## TC-032 모니터 찬양·성경 스타일 연동

환경: 실제 Electron의 임시 자료와 합성 찬양/성경. 메인 자료 기본 스타일·텍스트 요소의 사용자 스타일을 비교하고 찬양→성경 전환, 현재/다음 구절·시계, 정렬 실시간 변경·reload/재열기·송출 해제를 확인한다. 모니터 글자 크기 설정을 유지하며 긴 현재/다음 본문이 800×600/640×480 창의 영역에 들어가는지 검사한다. 공통 스타일과 Stage 중첩 검증/이전 상태 호환은 단위 검사로 확인한다. REQ-032/TASK-027/ADR-009와 [실행 기록](2026-10-05-모니터-찬양-성경-스타일-연동.md)에 연결한다.

본문 크기·색상·글꼴 변경이 모니터 본문에는 반영되고, 메인/모니터의 구절 표기는 기존 별도 스타일을 유지하는지도 확인한다.

## TC-033 기본 프리셋 자동 적용

환경: 단위 저장소와 실제 Electron의 임시 자료. 서로 다른 저장 스타일의 기존 찬양/성경과 두 기본 프리셋을 사용한다. 기존·새·가져온 자료 선택, 첫 송출, 혼합 자료의 종류 전환, 현재 종류 기본값의 즉시 적용, 같은 종류 진행 중 직접 조정 유지, 지정 없음/없는 ID/삭제 시 저장 스타일 유지와 ID 정리를 검사한다. 메인/모니터 표시·자동 저장된 스타일/기본값·정상 종료 후 재시작을 실제 앱에서 확인한다. REQ-033/TASK-028/ADR-010과 [실행 기록](2026-10-05-기본-프리셋-자동-적용-복구.md)을 따른다.

## TC-035 찬양에 성경 구절 추가

환경: 단위 저장소·기존 내장 성경 자료와 실제 Electron의 임시 합성 찬양. 구절/범위/장·숫자 권명·묶인 절·잘못된/부분 검색을 검사한다. 결과 선택/전체 해제·검색 변경·늦은 결과·취소/Escape·위치 기본값·맨 앞/중간/뒤·빈 자료/삭제된 위치를 확인한다. 자료 ID·제목·기존 가사·현재 송출·스타일·한 번의 Undo/Redo·다음 모니터 순서·본문/구절 표시·인라인 편집·자동 저장/라이브러리/정상 재시작을 검증한다. 긴 장은 작은 창에서도 결과가 스크롤되고 추가 버튼과 검색창이 보이는지 확인한다. ## TC-034 외부 AI 로컬 연결과 자료 준비
