# 개발 실행 검은 화면 복구 검증

2026-10-04 · 제품 0.1.0 · 로컬 수정 · 커밋·푸시 없음

사용자가 실행 불가를 알려준 뒤 현재 개발 실행의 검은 컨트롤 화면과 종료 시 자동 저장 실패 안내를 확인했다. [이전 검증](verification-2026-10-04-implementation.md)은 빌드된 Renderer로 실행하는 검사였으며, Vite의 개발 화면 초기화 경로가 포함되지 않았다. 당시 검사 통과를 모든 실행 경로의 정상 동작으로 확대해서 보고한 부분을 정정한다.

## 원인과 수정

- CSP가 Vite React의 초기화용 인라인 모듈을 차단했다. `@vitejs/plugin-react can't detect preamble` 오류와 빈 화면을 임시 저장소에서 재현했다.
- 개발 서버를 시작할 때 매번 임의 nonce를 생성하고 Vite가 초기화 스크립트에 적용하도록 했다. Electron은 같은 nonce의 스크립트만 허용한다. 임의 인라인 스크립트·eval을 전체 허용하지 않는다.
- 개발 연결의 WebSocket 허용 주소는 실제 개발 서버 주소에서 계산한다. URL 뒤 중복 슬래시를 제거했다.
- 패키징된 앱은 개발 서버 환경 변수를 사용하지 않으며 프로덕션 CSP는 자체 스크립트만 허용한다.
- 컨트롤 초기화 완료와 창 생성 상태를 구분한다. 초기화 전에 멈춘 창은 저장할 새 편집이 없는 상태로 닫을 수 있다. 초기화 후 실제 저장 실패 시 종료를 막는 기존 보호는 유지한다.

관련 코드: `vite.config.ts`, `shared/content-security-policy.ts`, `electron/main.ts`, `electron/services/windows.ts`.

## 검사 범위

새 Electron 검사는 실제 프로젝트의 Vite 설정과 React 개발 초기화 스크립트를 사용한다. 검사용 저장소를 따로 만들고 자동 실행을 억제한 뒤 검사 프로세스로 Electron을 실행한다. 개발용 Main/preload 빌드가 기존 프로덕션 산출물에 남지 않도록 검사 종료 시 원래 파일을 복원한다.

| 검사 | 확인 내용 |
| --- | --- |
| 개발 시작·편집·종료 | 컨트롤 표시, 자동 저장 표시, 슬라이드 추가의 디스크 저장, 모니터 창 표시, 정상 종료 |
| 보안 범위 | Vite nonce 일치, nonce 없는 임의 인라인 코드 차단, 프로덕션 nonce 미적용, 잘못된 nonce 값 차단 |
| 시작 실패 종료 | 다른 nonce로 시작 실패를 유도한 뒤 거짓 자동 저장 실패 안내 없이 종료 |
| 기존 회귀 | 자동 저장·재시도·중단 복구·파일·미디어·독립 창 등 기존 실제 Electron 14개 사례 |

## 기존 자료 보존과 실제 실행 확인

복구 전 저장 파일과 브라우저 저장 기록을 별도 로컬 사본으로 보존했다. 저장된 자료 49개와 순서 4개의 구조·개수만 확인했으며 자료 원문이나 키를 검증 문서·로그에 기록하지 않았다. 실제 자료를 테스트 입력으로 사용하지 않고, 마지막 실행 확인에서 앱이 기존 저장 내용을 읽는 경로만 확인한다.

실제 개발 실행을 다시 열어 macOS 화면에서 컨트롤 UI·자동 저장됨 표시·기존 순서 4개와 라이브러리 목록을 확인했다. 화면을 확인한 뒤 사용자 자료를 선택·편집하거나 송출하지 않았다. 재시작 전후 라이브러리 49개와 순서 4개의 전체 데이터가 동일함을 확인했다. 개발 서버와 앱은 실행 상태로 유지했다.

시작 실패 종료 검사는 의도적으로 잘못된 nonce를 전달해 검은 화면을 유도한다. 이 사례의 preamble 오류는 기대된 실패 조건이며 정상 개발 실행에서 발생한 오류가 아니다. 실제 저장 실패와 중단 복구를 다루는 기존 검사는 함께 통과했다.
