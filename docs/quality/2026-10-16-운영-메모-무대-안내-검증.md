# WSP-P2 운영 메모·무대 안내 검증

2026-10-16 · HEAD 4dbdd7d + 기존 dirty 작업 보존 · macOS / Electron 44.5.1

## 구현·계약

운영 메모와 무대 안내 초안은 cue 편집의 명시 저장·로컬 초안 복구·구조 Undo·충돌 보호를 사용한다. P1에서 선택한 명시 저장 계약을 P2에도 적용했다. 무대 초안은 cue 진행으로 자동 발행하지 않는다. 전체 순서의 접힌 `무대 안내 · 청중 비공개`에서 초안/직접 입력→유지시간→미리보기→명시 전송한다. 현재 안내는 Control 상단에도 표시해 곡 보기로 바꾸어도 지울 수 있다.

StageMessages가 Main 메모리에 단일 안내와 revision·requestId 영수증을 관리한다. 1~120자 plain text, trim 후 최대 두 줄, TTL 5/10/20/30/60초 또는 직접 지우기를 허용한다. 기본20초다. 전송 전 Control과 Stage에서 같은 canvas/system-ui 600 폰트·실제 Stage 크기로 줄바꿈을 측정한다. 두 줄 초과는 UI 전송을 차단한다. 다른 크기·렌더러 상태로 실제 표시가 불가능하면 Stage가 negative ack를 보내 `표시 확인 필요`를 표시하며 잘린 안내를 출력하지 않는다.

Main TTL은 setTimeout과 monotonic deadline을 사용한다. expiresAt은 표시 메타데이터다. 벽시계 조정이 안내 수명을 바꾸지 않는다. clear는 message ID/revision, send는 expectedRevision/requestId를 검사한다. 늦은 clear/ack·중복 send는 새 안내를 덮지 않는다. Stage 재연결은 최신 유효 안내만 replay하며 3초 미확인은 unconfirmed다. F2/전체 중지는 제거하고 앱 재시작은 빈 상태다.

별도 `stage-message` channel을 Stage에만 전달하며 Control에는 상태 channel을 제공한다. 청중 OutputSchema/Stage 가사 payload/Repository/portable/ServiceRun에는 일시 안내를 추가하지 않았다. Stage 발행 API는 Control에만 노출하며 acknowledgement는 Stage 역할만 허용한다.

## 검증

- lint/typecheck/생산 build 통과.
- 전체 단위/계약 25개 파일230개 통과. 신규 안내6개는 잘못된 입력·TTL·경합·idempotency·만료/교체·재연결·ack timeout/negative ack·F2·새 인스턴스·한글 줄바꿈·벽시계 조정을 포함한다.
- 관련 Electron12/12 통과: 큐시트6 + 기존 Stage3 + 신규 안내3. feature flow 전에 실제 app.getPath('userData')가 임시 PROPRE_TEST_USER_DATA와 일치함을 확인했다.
- native 검사: 저장 초안 무송출, 명시 전송/교체/지우기, 입력 편집의 현재 안내 불변, Main DOM 비노출과 청중 live snapshot 불변, workspace의 ephemeral 본문 제외, 5초 만료, renderer reload 재연결·만료 후 비부활, native Stage F2, Main 재시작 초기화, Control만 send 가능, 긴 한글·세 줄 차단·Enter 무전송·가사/안내 영역 분리.
- 중간 실패: trim 이후 무의미한 끝 빈 줄을 제거하는 계약에서 Enter 세 번을 줄 제한 위반으로 가정한 테스트가 실패했다. 실제 문구가 있는 세 줄을 입력하도록 바꾸고 Enter만으로 전송되지 않음도 별도 확인했다. 최종 통과했다.
