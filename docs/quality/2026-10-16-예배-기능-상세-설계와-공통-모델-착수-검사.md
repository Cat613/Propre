# 예배 기능 상세 설계와 공통 모델 착수 검사

2026-10-16 Asia/Seoul · 범위: 문서 + WSP-P0 공통 모델 일부 · 기능 전체 수용: 미실행

## 작업과 선행 조건

사용자 요청에 따라 7개 기능별 상세 설계, 공통 계약, 개발·수용 계획을 별도 문서로 작성했다. [설계 인덱스](../design/worship/README.md)가 진입점이다. 기능별 UI·상태·흐름·데이터·복구·접근성·개발 순서·수용 기준을 기록했다.

자동 업데이트 세션(01a1402b-1c65-7a41-b19d-b9cf52d2ef64)의 최종 completed 응답에서 로컬 개발·검증 완료를 확인했다. 선행 보고의 전체 Electron 마지막 실행은 73/74이며 해당 기존 제목 입력 검사는 재실행 통과한 간헐 실패다. 이 채팅에서 그 전체 검사를 재실행하거나 모든 검사가 일괄 통과했다고 판단하지 않았다. 서명/실배포 업데이트 수용은 남아 있다. 예배 기능의 조건부 개발 착수는 허용된 상태다.

## 공통 모델 첫 구현

[shared/service-plan.ts](../../shared/service-plan.ts)에 strict Zod 입력, cue/plan/timer 정책, 기존 곡 행의 계획 변환, 곡 투영, 비곡 메모를 보존하는 곡 재정렬/제거, 미정 duration을 구분한 계획 시각 계산, private 필드를 제외하는 명시적 summary projection을 추가했다.

[tests/service-plan.test.ts](../../tests/service-plan.test.ts)는 반복 사본/행 ID 유지, 혼합 순서 정렬·삭제·신규 곡 삽입, 중복/고아 참조 거절, 종류별 연결/상한/시간대, 자정과 미정 시간, private 필드 제외, 타이머의 명시 시작 기본값을 검사한다. 삭제된 곡 슬롯을 먼저 제거해야 남은 기도/찬양의 상대 순서를 유지할 수 있음을 검토 중 확인해 정상 기대 회귀 검사를 추가했다.

이 모듈은 아직 Repository/실제 workspace schema·IPC·UI에 연결하지 않았다. workspace 파일을 변경하거나 새 화면을 제공한 단계가 아니다. WSP-P0 전체와 WSP-01~07을 완료로 표시하지 않는다.

## 기존 변경 보존과 이어갈 작업

작업 전 git 상태와 추적/비추적 파일 229개의 해시를 /tmp/propre-worship-design-20261016/baseline.json에 기록했다. 이 채팅이 기존 파일에 추가한 변경은 docs/README.md와 당시 `docs/governance/change-log.md`(현 파일: `docs/governance/문서-계획-변경-이력.md`)의 새 문서 연결이다. 자동 업데이트 세션이 같은 시간에 바꾼 앱/검사/문서는 해당 세션의 결과로 보존했다. Git 전체 diff는 이 채팅의 변경만을 뜻하지 않는다.

다음 작업은 최신 기준에서 공통 모델을 workspace 이전·Repository·백업·명령 권한에 연결하는 것이다. 이후 번호 순서로 기능을 구현한다. 이 채팅의 heartbeat `propre`를 ACTIVE, 15분 간격으로 등록했으며 조회로 등록을 확인했다. [개발 계획](../delivery/예배-운영-기능-순차-개발-계획.md)에 이어갈 지점과 완료 기준을 기록했다. 커밋·푸시·배포는 수행하지 않았다.
