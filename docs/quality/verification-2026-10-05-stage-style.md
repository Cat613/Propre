# 모니터 찬양·성경 스타일 연동

2026-10-05 (Asia/Seoul) · 제품 0.1.0 · REQ-032 / TASK-027 / TC-032 / ADR-009

사용자는 메인 화면의 찬양·성경별 표시를 모니터에도 비슷하게 적용해 달라고 요청했고, 현재·다음·시계를 유지하며 본문 스타일만 연동하는 방향을 선택했다.

성경 구절 표기를 본문 스타일 편집에 함께 연동하는 추가 요청은 사용자가 철회했다. 메인의 구절 스타일과 기존 편집 정책은 그대로 유지하며, 모니터 구절도 해당 별도 설정을 사용한다.

## 구현 동작

- Stage 전체 상태에 자료의 globalSlideStyle을 전달하고, 메인/모니터가 같은 본문 스타일 해석을 사용한다.
- 현재·다음 본문은 자료와 텍스트 요소의 글꼴·색상·굵기·가로/세로 정렬·줄 간격을 따른다. 찬양/성경 기본 굵기와 별도 줄 간격의 차이도 동일하다.
- 성경은 각 본문의 bibleReference를 따로 표시한다. 구절 글꼴·색상과 위/아래·좌/우 방향을 따르고 본문·시계와 겹치지 않도록 별도 줄을 사용한다.
- 모니터의 현재/다음 글자 크기는 별도 최대 크기다. 긴 본문은 공통 FittedText로 영역에 맞춰 줄인다. 구절 크기와 여백도 창 크기에 맞춘다.
- 현재·다음의 70:30 비율은 시계 영역을 제외한 공간에 적용한다. 텍스트 요소는 저장된 읽기 순서로 표시하며 캔버스 좌표·구절 미세 픽셀 이동은 모니터 읽기 구성에 맞춘다.
- 자료 스타일 변경·송출 전환·송출 해제·모니터 다시 열기·reload 때 최신 본문·스타일·구절 상태가 적용된다.

## 검증 범위

임시 userData의 합성 찬양·성경·여러 텍스트 스타일로 검사한다. 실제 사용자 자료·키를 테스트 입력으로 사용하지 않는다. 구현·검사는 기존 격리 작업 폴더에서 진행해 실행 중인 사용자 앱에 중간 상태를 적용하지 않는다.

| 검사 | 확인 내용 |
| --- | --- |
| 스타일 계약 5개 | 자료 기본 스타일·명시 사용자 스타일·찬양/성경 기본 차이·Stage 스타일 중첩 검증/이전 상태 호환·현재/다음 스타일 전달 |
| 실제 Electron 사례 1 | 찬양 색상/정렬·다음 개별 스타일→성경 본문/각 구절→실시간 정렬·글꼴·색상 변경→reload/재열기, 시계와 모니터 읽기 구성. 본문 크기·색상·글꼴 변경 시 메인/모니터의 별도 구절 스타일 유지 |
| 실제 Electron 사례 2 | 긴 성경 본문과 요소 텍스트의 현재/다음 영역 맞춤, 800×600/640×480 창, 구절/시계 분리, 송출 해제 후 대기 상태 |

자동 스크린샷의 합성 찬양·성경·작은 창 결과를 직접 확인했다. 실제 공연장 모니터·거리·해상도·설치 폰트별 가독성은 이 검사와 구분한다.

## 원래 프로젝트 반영과 실제 시작 확인

실행 중인 앱의 자동 저장됨 상태를 확인하고, 저장 파일·브라우저 저장 기록·등록 미디어를 별도 로컬 사본으로 보존했다. 정상 종료 뒤 최신 저장본도 추가 보존했다. 다른 작업의 소스 변경이 없는지 최초 해시와 대조한 뒤 이번 변경 30개 파일과 검증된 빌드/로컬 앱을 원래 프로젝트에 반영했다. 반영 소스 17개의 해시와 로컬 앱의 app.asar 해시가 소스 기록과 일치한다.

원래 프로젝트에서 개발 실행을 다시 열어 컨트롤 UI·자동 저장됨 표시·역할별 창 메뉴를 확인했다. 모니터 창을 열어 시계·다음 슬라이드·송출 대기 구성을 macOS 화면에서 확인했다. 본문/스타일의 세부 비교는 위 임시 자료 검사에서 수행했으며, 실제 사용자 자료를 선택·수정하거나 송출하지 않았다.

재시작 전후 라이브러리 51개·순서 4개 및 작업본·설정·미디어·에셋·장비 선택의 전체 데이터가 동일했다. 사용자가 작업 중 추가한 자료도 마지막 저장본에 포함해 보존했다. 개발 서버와 컨트롤·메인·모니터 창을 실행 상태로 유지했다. 재시작 때 마지막 본문을 자동 송출하지 않는 기존 정책에 따라 메인은 대기 상태다.
