# AI 선택과 실제 요청 연결 검증

2026-10-16 · 범위: 기존 파일 작업의 AI 변경 후 분석 동선

기존 작업은 생성 당시의 AI를 보관하지만 화면의 선택은 새 파일에만 바로 적용되었다. 기본 분석 버튼과 별도 전환 버튼이 함께 있어 Gemini 선택 후 기본 분석을 누르면 작업에 남은 OpenAI로 요청할 수 있었다.

분석 버튼을 하나로 합쳤다. 선택과 작업의 연결 ID·제공자·모델이 다르면 버튼에 재전송을 명시하고 switchSongAI 성공 후에만 분석한다. 키 없는 연결·분석 대상 없음은 실행을 막으며 처리 중 선택 변경을 차단한다. 이번 분석에 사용할 연결과 모델을 표시하고, 선택이 다르면 기존 오류에 이전 분석 AI를 표시한다. 분석 실행 없이 선택만 바꾸어 파일을 전송하지 않는다.

- 타입·생산 빌드·변경 컴포넌트 ESLint·Prettier·공백 검사 통과.
- 번들 검사 통과: 공통 Renderer 673,837바이트.
- 찬양 준비 Electron 8개 통과. 신규 회귀는 OpenAI 작업 생성/실패→Gemini 선택→단일 분석 동작에서 요청 순서가 OpenAI 한 번, Gemini 한 번임을 단언한다. 이전 오류 구분과 작업 프로필 변경도 확인했다.

Electron은 폐기 가능한 사용자 경로와 실제 app.getPath('userData') 일치를 먼저 확인했다. 제공자 응답은 모의이며 실제 사용자 키·실 API·실계정 할당량은 확인하지 않았다. 기존 작업 트리 변경을 보존했고 커밋·푸시·설치용 패키징·배포는 수행하지 않았다.
