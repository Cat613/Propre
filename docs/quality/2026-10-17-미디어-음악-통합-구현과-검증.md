# 중앙 미리보기·미디어 음악 통합 구현과 검증

날짜: 2026-10-17 Asia/Seoul · 기준: e6c3cee 위의 현재 dirty 작업 트리 · 상태: 로컬 구현·검증 완료 / 실제 Chrome 서비스·현장 수용 대기

## 범위와 보존

사용자가 기능·UI/UX 상세 설계를 다시 검토하고 구현을 요청했다. 현재 기준은 [v1.2 상세 설계](../design/music/05-미디어-통합과-송출-미리보기-구현-설계.md)다. 원래 작업 트리에는 AI 찬양 준비·설정·테스트와 문서/생성물 변경이 있었다. 해당 소스 변경을 보존하면서 이 기능을 추가했다. 커밋·푸시·배포·실제 사용자 Chrome 확장 설치·사용자 음악/예배 데이터 변경은 수행하지 않았다. 검사 데이터는 임시 PROPRE_TEST_USER_DATA로 분리했고 각 Electron 검사에서 app.getPath('userData')가 임시 경로인지 확인했다.

## 설계·UX 검토에서 보완한 점

1. 준비 수명과 재생 의도를 분리하고 F2/stop이 대기 중 play보다 우선하도록 했다. 오래된 브라우저 응답은 sequence로 거절한다.
2. 활성 사본과 저장 목록을 분리해 편집/삭제 뒤에도 중지할 수 있게 했다. 삭제 Undo는 해당 항목만 복원하여 다른 항목 수정과 새 등록을 보존한다.
3. 페이드 후 이어 재생에서 음량이 0으로 남는 문제를 수정했다. 현재 음량과 저장 기본 음량을 구분한다.
4. 연결 끊김은 정지 성공이 아니다. 대상/연결 미확인 시 재생을 비활성화하고 외부 잔류와 대체 흐름을 표시한다. Chrome 실제 제어는 아직 수용하지 않았다.
5. 1024px에서 미리보기 도구를 가로로 배치하고 왼쪽 찬양 도구도 줄바꿈해 잘림을 줄였다. 다음 준비의 실행 버튼은 긴 음악 목록 위로 옮겼다.
6. 음악 설정과 성경 추가 도구를 실제로 열 때 불러오도록 분리했다. 기본 공유 renderer 700KB 한도를 올리지 않고 선택 음악 도구 50KB 개별 한도를 적용했다.
7. 라이트 캡처는 테마 전환의 150ms 버튼 색상 transition 완료를 실제 CSS 값으로 확인한 뒤 촬영했다. 전환 중 흐린 프레임을 최종 UI로 오인하지 않았다.
8. 기존 성경 dialog 검사에서 F2를 무시하던 기대를 새로운 긴급 중단 정책과 구분했다. 일반 dialog 내 ArrowRight가 송출을 바꾸지 않는 검사를 유지하고 F2는 음악 확대/입력창에서 중단하는 별도 검사를 적용했다.

최종 번들: core 696,674 bytes / 선택 예배 도구 84,694 bytes / 선택 음악 도구 13,260 bytes. 기본 core 제한 700,000 bytes를 유지한다. 최종 캡처는 1440×960, 1280×800, 1024×768과 라이트 테마에서 확인했다.

전체 실행 전 발견한 버전 기대/조작 이름 불일치, 페이드 재개 음량, 테스트의 app.firstWindow()가 Stage를 잡는 재시작 경합을 고쳤다. Stage 검사는 Control URL을 명시적으로 선택하게 했다. 초기 실패를 성공으로 취급하지 않고 수정 후 전체 verify를 완료했다. 개발 시작 실패를 의도한 기존 검사는 React preamble 오류를 출력하지만 해당 거절/종료 검사의 예상 조건이며 최종 전체 검사는 통과했다.

## 미검증·출시 경계

- 실제 Google 로그인, 실제 유튜브 뮤직 DOM/콘텐츠·광고·Premium·지역·자동재생, Chrome의 실제 native host 등록/브라우저 실행은 미검증이다. 확장/앱 코드를 만들고 합성 adapter와 패키지 helper를 검사한 것으로 구분한다. P0 실서비스 통과로 보고하지 않는다.
- 개발 확장 설치는 일반 사용자 배포가 아니다. 고정 확장 ID, Chrome 배포, 서명/공증과 다운로드한 앱 설치·업데이트 경로 수용은 남아 있다.
- 실제 스피커/믹서 음량·기기 전환·절전·60분 재생, 300ms 반응·250ms 구간/페이드 오차 목표와 운영자 리허설은 미검증이다. 무음 WAV의 엔진 상태 검사를 실음향 확인으로 쓰지 않는다.
- MUS-T10~15와 외부 관련 T23/24/28/29는 계약/합성 수준의 일부 근거만 있다. T20 실장비는 대기다. 기존30개 수용 계획 전체를 현장 완료로 표시하지 않는다.
- 음악 삭제 Undo는 현재 세션 내 기능이다. 앱 재시작 뒤 Undo 보관, 전용 헤드폰 미리듣기·장치별 라우팅·crossfade·외부 탐색/반복/볼륨 제어는 현재 제공하지 않는다.

## 후속 UI 조정: 미리보기 내부 두 열 배치

사용자 캡처에서 송출 화면 아래 상태·버튼이 누적되어 편집 상단 여백이 커지는 문제를 수정했다. 기본 320px 영역 안에서 16:9 화면을 왼쪽, 제목·상태·슬라이드 정보·중지 도구를 오른쪽 열에 배치한다. 중앙 컨테이너가 560px 이하일 때만 이 가로형 미리보기를 편집 도구 아래로 내린다. 360px 이하에서는 중지 버튼을 마지막 한 줄로 분리한다. 화면 내부 렌더러에 레이아웃 스타일이 전파되지 않도록 직접 자식에만 배치를 적용한다.

검증: 타입 검사와 앱 빌드, ESLint, 번들 예산 검사 통과. 기존 music-workspace 및 workbench Electron 테스트 8개 통과. 1440×960·1280×800·1024×768 창 크기의 캡처와 1440 라이트 테마를 확인했다. 확대·Escape 복귀·F2 전체 중지와 실제 송출 중지 동작을 기존 통합 테스트로 확인했다. 별도 임시 사용자 데이터로 실행했으며 실제 사용자 작업공간을 사용하지 않았다. 최신 캡처는 output/music-2026-10-17/preview-horizontal-*.png에 보존했다.


## 후속 UI 조정: 편집 영역 여백과 카드 표시

찬양 제목과 도구 사이 패딩, 구간 아래 margin과 슬라이드 목록 padding의 중복, 슬라이드 제목 아래 간격을 줄였다. 카드의 `송출 중` 배지 및 접근성 이름의 같은 문구를 제거했다. 활성 위치 강조와 실제 송출 동작은 보존한다. 타입 검사·빌드·린트·번들 검사와 기존 workbench/music-workspace/sections Electron 테스트 11개가 통과했다. 라이트 테마 캡처로 간격과 배지 제거를 확인했으며 output/music-2026-10-17/editor-spacing-light.png에 보존했다.
