## 확인한 동작

`tests/setlists.test.ts`는 콘티 추가 시점 복사, 원곡 수정/삭제 후 콘티 보존, 콘티끼리 독립 수정, 같은 사본의 반복 순서, 명시적인 원곡 반영과 버전 충돌, 삭제된 원곡의 새 저장, CRUD/날짜/휴지통 복원, 디스크 저장 실패 후 원자 복구, v1 이전 원본의 바이트 보존 및 유효 백업 복구, 손상 원본 저장 차단, 전체 백업/플레이리스트 파일 호환, 사본/휴지통만 참조하는 미디어 유지, 잃어버린 사본 journal 보호와 유효 날짜를 검사한다.

`tests/electron/setlists.spec.ts`는 보관함 버튼을 사용해 복제/날짜/수정/원곡 반영 취소와 확인/이름 변경/휴지통 복원을 실행한다. 보존한 스타일과 기본 프리셋을 구분하고, 과거 콘티 열기 후 선택·Undo·메인/모니터 출력이 유지됨을 검사한다. 실제 디스크 오류 뒤 재시도, 원곡 반영 확인 중의 버전 충돌, 재시작과 renderer crash 후 콘티 사본 journal 복구를 확인한다. 기존 자동 저장·AI·성경 삽입·플레이리스트 파일·송출 검사를 함께 통과했다.

앱 테스트는 임시 userData를 사용하고 기능 실행 전에 실제 `app.getPath('userData')`가 해당 경로인지 확인했다. 사용자 찬양 데이터로 자동 테스트를 실행하지 않았다. 개발 초기화 실패 검사에서 의도한 React preamble 오류를 발생시켜도 종료 흐름 테스트는 통과했다.

## 적용과 운영 범위

기존 변경이 있는 작업 공간과 분리해 구현/검사했다. 적용 직전 변경 대상이 초기 스냅샷과 동일함을 확인하고 작업 변경분만 반영했다. 적용 뒤 실제 작업 공간의 TypeScript/production build도 통과했다. 자동 저장 완료와 송출 창 닫힘을 확인한 뒤 정상 종료/재시작했고 실제 앱에서 콘티 보관함 버튼과 현재 콘티 4곡을 확인했다.

사용자 원본은 별도 체크포인트를 두고 이전 전후를 비교했다. v1 파일은 바이트 단위로 동일했고, v2의 원곡 54개·draft·설정·미디어·asset 등록·장비/활성 설정이 기존 값과 동일했다. 현재 순서 항목 ID를 보존했고 독립 사본 4개는 이전 자료의 가사/슬라이드/스타일을 그대로 담았다. 슬라이드 수는 23/26/43/6, 총 98개다. 확인 이후 편집 곡과 송출을 바꾸지 않고 작업 화면으로 돌아왔다.

패키징·서명·배포 및 실제 외부 디스플레이 연결 검증은 이번 기록에 포함하지 않는다. 콘티 보관함의 영구 삭제와 AI PDF 통합 제작(TASK-032)은 별도 범위다. [사용 안내](../operations/예배별-콘티-보관-편집.md), [저장/API 설계](../engineering/콘티-보관함과-예배별-곡-사본.md)를 참조한다.
