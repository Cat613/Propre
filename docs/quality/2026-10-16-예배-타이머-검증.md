# WSP-P4b 예배 타이머 검증

2026-10-16 · HEAD4dbdd7d + dirty 작업 보존 · macOS arm64 / Electron44.5.1

## 구현·최종 계약

Main TimerEngine이 주입 가능한 단조 시계로 타이머 카운트와 실제 cue 경과를 계산한다. idle/pause 중에도 실제 cue 경과는 이어지고 reset은 타이머 카운트만 초기화한다. Main이1초 snapshot을 발행하고 Control/Stage는 수신 시점부터 짧게 보간하며 IPC로 카운트를 되돌리지 않는다. 벽시계 변경은 타이머 elapsed에 영향을 주지 않는다. 전체 예배 경과/계획 시각은 별도 wall instant를 사용한다.

예상 시간이 있으면 기본 카운트다운, 없으면 카운트업이며 자동 시작은 꺼짐이다. 순서별 명시 preset에서 자동 시작/무대 표시를 선택할 수 있다. 준비·선택은 타이머를 바꾸지 않는다. cue 진행 성공만 새 run ID와 타이머를 만들고 이전 타이머를 마감한다. 0초 이후 초과를 표시하며 화면/순서를 자동 전환하지 않는다.

start/pause/resume/reset/+1분/Stage 표시/현재 계획 반영은 expectedRevision/requestId를 검사한다. 중복 명령은 한 번만 적용하고 동시 명령은 대기 안내한다. +1분은 타이머 목표만 바꾸고 계획은 보존한다. 실패한 저장은 원래 타이머로 되돌리되 쓰기를 기다린 경과는 잃지 않는다. cue 변경이 먼저 일어나면 이전 실패 응답이 새 타이머를 덮지 않는다.

계획 시작 시각은 컴퓨터 현지 시간대 입력을 instant로 저장하고 IANA 예배 시간대로 표기한다. 앞/현재 duration 미정은 지연을 계산하지 않고 이후 미정은 예상 종료를 미정으로 남긴다. 알려진 남은 합은 별도로 표시한다. 타이머 연장은 원래 계획 지연 기준을 바꾸지 않는다.

runtime/최근1,000개 마감 timer run은 별도 service-timer-v1.json(2MiB)에 저장한다. ServiceRun의 새 실행에는 UUID를 붙여 반복 cue를 구분한다. 세션/계획 파일에 일시 카운트를 매초 쓰지 않는다. timer checkpoint는 명령·세션 전환·10초 주기·정상 닫기 flush에서 저장한다. 비정상 종료는 마지막 확인된 checkpoint까지만 복원한다. Main 재시작은 matching session/cue/run만 paused로 복구하고 Stage 표시는 끈다. 새 예배·파일 import로 runtime을 승계하지 않는다.

OS suspend 이벤트는 pause·Stage 숨김, 복귀는 명시 재개다. F2/전체 중지도 pause·Stage 숨김이며 무대 안내를 함께 제거한다. Stage 타이머는 청중 OutputSchema에 넣지 않고 별도 Stage-only channel을 사용한다. 무대 창이 없으면 켜기를 차단한다.

## UI와 번들

현재 순서의 실제 경과를 접힌 표시줄에, 타이머 제어·목표/계획 차이·전체 경과/지연·예상 종료는 펼친 상세에 둔다. Stage는 안내/타이머/시계/현재 가사/다음 가사를 별도 영역으로 배치한다. 긴 한글의 단어 끝이 외톨이 한 글자로 갈라지는 것을 줄이기 위해 Stage 본문에 keep-all/balanced wrapping을 적용했다. 기존 가사 맞춤 계산을 유지한다.

전체 큐시트와 사전 점검을 dynamic import로 분리했다. 기존 공통700KB JS 예산을 늘리지 않고, 실제로 열 때 불러오는 상세 chunk는 별도 총180KB/개별100KB 상한으로 검사한다. PDF parser/worker의 기존 선택 로드 상한은 유지한다. 타이머 포함 생산 빌드: 공통665,769bytes / 예배 상세44,462bytes / 선택 PDF1,397,111bytes로 통과했다. 공유 하위 chunk는 계속 공통 합계에 포함해 제외 범위를 보수적으로 잡았다.

## 증거와 한계

최종 캡처/짧은 실측은 전체 회귀 후 evidence 폴더에 보존한다. 약2~3초 로컬 측정에서 main monotonic 값과 관찰 wall 경과를 비교했다. 이 실측과 fake clock 검사는 실제60분 drift ±1초 목표의 증거가 아니다. 실제60분 장시간·실제 절전/복귀·프로젝터/Stage/음향은 현장 잔여 수용이다. OS 이벤트 주입 성공을 실제 하드웨어 절전 수용으로 표현하지 않는다.
