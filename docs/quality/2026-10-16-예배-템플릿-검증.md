# WSP-P5a 예배 템플릿 검증

2026-10-16 · HEAD4dbdd7d + dirty 작업 보존 · macOS arm64 / Electron44.5.1

## 구현·계약

현재 예배를 템플릿으로 저장할 때 기본은 매번 채우기 슬롯이며 담당자·운영 메모·무대 초안은 제외한다. 날짜·계획 시작 instant·실행/점검/타이머 runtime을 템플릿에 넣지 않는다. 항목별 고정 자료를 명시 선택하면 현재 예배의 문서/외부 resource를 다시 독립 사본으로 저장한다. 고정 PDF 페이지/회전과 미디어 참조는 보존한다. 포함 개인정보/자료 수를 UI에 표시한다.

새 예배는 고정 자료와 선택한 슬롯을 새 소유 사본으로 만든다. 콘티/행/cue/presentation/resource ID는 새로 발급하며 실제 asset만 공유한다. 원곡·템플릿·이미 생성한 예배가 서로 수정 전파되지 않는다. 슬롯 source revision·템플릿 revision·현재 콘티 identity/revision과 requestId를 검사해 경쟁/중복 생성/실패를 원자 처리한다.

미완성은 저장 가능하다. 찬양 슬롯은 빈 독립 presentation과 곡 행을, 비곡 필수 슬롯은 materialPending을 남긴다. prepare와 preflight가 필수 미완성을 차단한다. 기존 cue 편집에서 찬양 빈 슬롯/비곡 자료를 연결할 수 있고 비곡은 자료 없이 현재 화면 유지로 진행할 것을 명시 선택할 수 있다. 찬양 슬롯을 채우면 실제 새 찬양 제목을 사용한다.

관리 UI는 이름/설명·종류/순서·슬롯 이름/필수·고정 자료 교체·화면 정책·담당자/메모 편집, 복제, 휴지통/복원을 제공한다. 편집 화면에는 송출 버튼이 없다. 생성 시 슬롯은 하나씩 펼쳐 자료를 고르게 해1,000개 슬롯에 전체 라이브러리 option을 반복 렌더하지 않는다. 새 콘티 화면의 템플릿 진입은 입력한 이름/날짜를 유지한다.

이번 미배포 예배 기능 묶음의 workspace4 계약에 serviceTemplates 기본 빈 컬렉션을 완성했다. 이전 파일은 빈 기본값으로 읽고 기존 v3 원본 보존 경로를 유지한다. portable schema3 backup에는 휴지통까지 포함하며 단독 kind=service-template 파일은 한 템플릿과 실제 참조 assets만 포함한다. 예배 service 파일과 전용 진입점을 분리한다. import는 새 ID·hash 재사용·충돌 재매핑을 사용하고 현재 예배/편집/송출을 바꾸지 않는다.

템플릿의 고정 미디어/PDF도 cleanup과 다른 바이트 relink에서 보호한다. 템플릿200개·항목1,000개·공통24MiB/휴대200MiB 상한을 유지한다. 영구 삭제는 제공하지 않아 휴지통 자료도 보존한다.

## 확인하며 보완한 공통 경로

찬양 슬롯 연결과 곡 제거의 Undo는 plan만으로 사본 연결을 복구할 수 없었다. Undo checkpoint에 곡 행/사본 참조를 함께 저장하고 Control 전용 restoreSongRows를 검증해 복원한다. 다른 예배의 사본이면 새 사본을 만들어 공유를 막는다. 빈 슬롯 연결→Undo는 이전 빈 사본/필수 상태로 되돌아가고, 곡 제거→Undo는 기존 사본과 행을 복구한다. 실행 중인 곡의 presentation 참조 변경도 Main 세션 guard가 막는다.
