# 기본 프리셋 자동 적용 복구

2026-10-05 (Asia/Seoul) · 제품 0.1.0 · REQ-033 / TASK-028 / TC-033 / ADR-010

사용자가 일반/찬양 기본 프리셋을 지정해도 기존 찬양을 띄울 때 적용되지 않는 문제를 보고했다. 자료별 스타일을 복원하는 후속 개선에서 기존 자료 선택의 기본 프리셋 적용 경로가 빠졌다. 새 찬양 생성에만 남은 자동 적용을 자료 선택과 송출 경로에 다시 연결했다.

## 수정 동작

- 기존 자료 선택·새 자료 생성·가져온 자료 열기에서 종류에 맞는 기본 프리셋을 적용한다. 지정 없음/없는 ID는 자료의 저장 스타일을 유지한다.
- 다시 시작한 자료의 첫 송출과 찬양↔성경 종류 전환에 해당 기본 프리셋을 적용한다. 본문·스타일·배경을 한 번의 상태 변경으로 보내 메인과 모니터가 같은 상태를 받는다.
- 현재 종류의 기본 프리셋을 변경하면 즉시 반영하고 다른 종류의 기본값 변경은 현재 화면 스타일을 바꾸지 않는다.
- 같은 종류의 슬라이드를 진행하는 동안 직접 조정한 스타일을 유지한다. 자료를 다시 열거나 종류를 전환하면 지정된 기본 프리셋을 다시 적용한다.
- 프리셋 삭제는 기본값·선택 ID를 정리하고 현재 스타일을 유지한다. 개별 텍스트 사용자 스타일의 우선순위와 별도 성경 구절 스타일 편집은 유지한다.
- 적용된 자료 전역 스타일과 기본 프리셋 설정은 기존 자동 저장 경로로 기록한다.

## 검증 범위

단위 사례 6개로 기존 자료·새 자료·가져오기·첫 송출·혼합 종류 전환·직접 조정·설정 변경·없는 ID·삭제·송출 상태 일치를 확인한다.

실제 Electron 사례는 합성 자료와 임시 userData를 사용한다. 저장 스타일이 서로 다른 찬양/성경에 기본 프리셋을 지정하고, 현재 화면의 즉시 적용·다른 종류 설정의 영향 없음·직접 조정 유지·기존 자료 재선택의 자동 적용을 확인한다. 자동 저장된 스타일/기본값, 정상 종료 후 재시작·모니터 표시, 기본값 해제 후 저장 스타일 복원도 확인한다. 실제 사용자 원문이나 키는 테스트 입력에 사용하지 않는다.

## 최종 실행 결과

lint·TypeScript·단위/계약 83개·실제 Electron 19개·코드 형식·번들 예산·macOS arm64 로컬 앱 생성·변경 공백 검사 모두 통과했다. 이 중 프리셋은 단위 사례 6개와 실제 앱 사례 1개다. 원래 자료의 저장 스타일 우선은 기본 프리셋을 지정하지 않은 경우로 명확히 했다.

실제 앱 재시작 검사의 창 복원 순서 차이로 모니터를 컨트롤로 선택하는 테스트 문제가 발견되어 컨트롤 URL로 검사 대상을 지정했다. 창이 이미 복원된 경우에는 다시 토글하지 않는다. 수정 후 전체 Electron 19개를 다시 통과했다.

같이 수정한 [모니터 표시 검증](2026-10-05-모니터-찬양-성경-스타일-연동.md)과 [소스·패키지 식별](source-manifest-2026-10-05-stage-style.json)을 연결한다. 로컬 앱 검증과 물리 송출 장비·실제 운영 리허설·서명/공증/공개 배포는 구분한다. 커밋·푸시는 수행하지 않았다.

원래 프로젝트에도 수정 코드와 검증된 로컬 앱을 반영했다. 저장 완료·백업·정상 종료 뒤 다시 실행해 컨트롤 UI·자동 저장됨 표시·모니터 시계를 확인했다. 라이브러리 51개·순서 4개 및 작업본·설정·미디어·에셋·장비 선택의 전체 데이터가 동일하다. 상세 보존·반영 근거는 [모니터 검증의 원래 프로젝트 확인](2026-10-05-모니터-찬양-성경-스타일-연동.md#원래-프로젝트-반영과-실제-시작-확인)에 기록했다.
