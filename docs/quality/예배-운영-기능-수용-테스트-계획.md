# 예배 운영 기능 수용 테스트 계획

2026-10-16 · 상태: 수용 계획 / 로컬 실행 기록 연결 / 현장 수용 대기 · [설계 인덱스](../design/worship/README.md) · [개발 순서](../delivery/예배-운영-기능-순차-개발-계획.md)

## 환경과 증거 분리

단위/계약 검사는 합성 fixture·fake clock·오류 주입으로 수행한다. Electron 검사는 폐기 가능한 PROPRE_TEST_USER_DATA를 사용하고 앱 내부 app.getPath('userData')가 그 경로인지 먼저 단언한다. 기존 사용자 데이터·키·실제 예배 메모를 쓰지 않는다. 실패한 임시 환경은 개인정보 없는 재현 자료만 보존한다.

UI 검토는 1024×768/1280×800/1920×1080 Control과 16:9 Stage를 포함한다. 실제 모니터·프로젝터·음향·프린터는 별도 현장 확인이다. 이 문서에 적힌 절차는 통과 기록이 아니다.

## WSP-T02 메모와 무대 안내

- Given operatorNote와 stageNote가 다른 cue, When 저장·백업·복제, Then 독립 보존되고 청중/Stage로 자동 발행되지 않는다.
- Given Stage 열림, When TTL 5초 안내 전송 후 5초 경과, Then 제거되고 재연결해도 부활하지 않는다.
- Given 안내 A 뒤 B 전송, When A의 늦은 clear/ack 응답, Then B를 지우거나 A 표시 완료로 덮지 않는다.
- Given Stage 닫힘/ack 지연, When 전송 시도, Then 열기 안내 또는 표시 확인 대기이며 실제 표시 성공으로 오인하지 않는다.
- Given 120자/121자·IME 조합·HTML 문구, When 입력·전송, Then 제한과 plain text가 지켜지고 Enter로 오발송되지 않는다.
- 가사·긴 안내·타이머 동시 배치의 잘림·겹침은 스크린샷과 실제 Stage에서 각각 확인한다.

## WSP-T03 사전 점검

- Given 누락 asset·PDF 초과 페이지·참조 오류, When 검사, Then 정확한 cue와 수정 동작을 표시한다.
- Given pass 결과, When source/font/display/plan revision 변경, Then 영향 결과를 재검사 필요로 전환한다.
- Given 웹 자료, When 자동 검사, Then 외부 접속·로그인·라이브 변경 없이 수동 확인을 요구한다.
- Given 검사 중 콘티 변경·취소·이전 응답 도착, Then 현재 콘티의 준비 완료 상태를 덮지 않는다.
- Given 1,000 cue, When batch 검사와 취소, Then UI 조작을 유지하고 처리 수·취소 지연을 측정한다.
- Given 수동 소리 확인 체크 없는 자동 pass, Then 현장 준비 완료로 표시하지 않는다.

## WSP-T04 구간 바로가기

- 2페이지 후렴 3회 반복에서 각 발생 첫 슬라이드와 next가 실제 배열과 일치한다.
- songForm 없는 라벨 자료·비연속 동일 라벨·미지정 슬라이드를 별도 구간으로 처리한다.
- 구절 삽입·수동 정렬·삭제 후 인덱스를 재생성하고 stale slideId/revision 송출을 거절한다.
- 기본 칩 선택은 무송출, 즉시 모드는 명시 표시, 앱 재시작 시 기본 준비 모드다.
- 웹/PDF 중 선택은 현재 source 유지, 명시 송출은 coordinator를 통해 안전하게 가사로 복귀한다.
- 실제 운영자 과제: 후렴 재진입→브릿지→마지막 후렴, 오조작과 필요한 조작 수를 기록한다.

## WSP-T05 타이머

- fake clock에서 시작·pause·resume·reset·+1분·0 경계·초과·동일 명령 재시도를 검사한다.
- wall clock 변경이 elapsed를 바꾸지 않고 절전/복귀는 pause 안내를 생성한다.
- cue 선택은 timer 불변, commit 성공만 이전 기록 마감/다음 preset을 적용한다.
- 재시작은 checkpoint에서 paused 복원, Stage 재연결은 최신 snapshot, F2는 pause·표시 제거다.
- 시작 시각 미정·앞 duration 미정·자정 경과·계획 변경 후 계산과 '미정' 표현을 확인한다.
- 실제 60분 실행의 drift·OS/장비를 기록한다. 목표 ±1초와 측정 결과를 구분한다.
- 색상 인지 없이 남음/초과 구분, 매초 스크린리더 알림 없음, 가사와 영역 충돌 없음을 확인한다.

## WSP-T06 템플릿

- 현재 예배→기본 제외 설정으로 템플릿 저장 시 날짜·담당자·메모·실행 상태가 섞이지 않는다.
- 슬롯/고정 자료 혼합 템플릿→새 예배 두 번 생성 시 ID·본문·자료 소유권이 서로 독립이다.
- 템플릿·원곡·생성 예배 각각 수정/삭제 후 나머지 본문은 불변이다.
- 미완성 생성은 가능하지만 자료 필수 cue 실행은 차단하고 연결 동작을 제공한다.
- 생성 중 디스크 실패·request 중복·revision 충돌·한도 초과는 부분 예배를 남기지 않는다.
- 템플릿 휴지통·복원·파일 왕복에서 assets 보존·해시 재사용과 내부 ID 재매핑을 확인한다.
- 키보드만으로 템플릿 선택→슬롯 입력→생성→원래 라이브 확인까지 완료한다.

## WSP-T07 PDF·인쇄

- 공용/찬양팀/운영자용 DTO의 열·본문을 비교하고 공용에 담당자·메모·URL이 없는지 검사한다.
- 저장 실패 중 export를 차단하고 고정 revision 생성 후 동시 편집 시 갱신 안내를 표시한다.
- 긴 한국어·영문·특수문자·HTML 입력, 빈 시간, 1,000행, 최대 메모의 PDF를 만든다.
- 렌더 페이지의 첫/중간/마지막·페이지 경계에서 한글·반복 헤더·행 이어짐·쪽 번호·여백을 시각 확인한다.
- preview job 교체/취소·native 저장 취소·파일 쓰기 실패·폰트 실패에서 이전 job과 임시 파일이 남용되지 않는다.
- 인쇄 renderer의 외부 요청·탐색·임의 로컬 파일 접근을 거절한다.
- 실제 프린터 A4 세로/가로 출력은 별도 기록하고 OS 인쇄 요청 성공과 실제 인쇄 성공을 구분한다.

## 실행 기록 형식

기능별 검증 문서에 기준 checkout/diff, 합성 fixture, 환경, 명령, 통과/실패/미실행, UI 캡처 경로, 수정 후 재검사, 실제 장비 미확인 항목을 남긴다. 문서 정합성 검사 결과는 기능 테스트 결과와 별도 기록한다. 계획 단계의 이 문서에는 테스트 통과 수를 선기입하지 않는다.

## 현재 실행 근거

7개 기능의 로컬 구현·단위/계약·Electron 검증을 마쳤다. 기능별 기록은 [설계 인덱스](../design/worship/README.md), 전체 회귀는 [최종 검증](2026-10-16-큐시트-PDF-인쇄와-최종-회귀.md)에 연결한다. 이 계획의 모든 현장 항목을 통과한 것은 아니며 실장비·60분 타이머/절전·실제 인쇄·서명 설치는 별도 수용이다.
