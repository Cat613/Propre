# 프로프리 앱 업데이트 설계

2026-10-16 · REQ-040 / TASK-040 / TC-040 / ADR-019 · 사용자 요청으로 Apple 유료 멤버십 없는 다운로드·수동 교체 방식으로 전환했다. 이전 자동 설치 결정 ADR-017은 과거 기록으로 남긴다.

## 사용자 흐름

처음 받은 DMG를 열고 ProPre를 Applications에 설치한다. 앱은 시작 시와 실행 중 4시간마다 `propre-update.json`을 확인한다. 중앙 하단에 현재 버전과 수동 확인 버튼을 두며, 새 버전이 있으면 `v버전 다운로드`를 표시한다. 버튼을 누르면 접근 가능한 모달에서 다음 순서를 안내한다.

1. `설치 파일 받기`를 눌러 기본 브라우저에서 다운로드를 시작한다.
2. 브라우저에서 다운로드 완료를 직접 확인한다.
3. 예배·Main/Stage 송출을 마치고 자동 저장 상태를 확인한 뒤 ProPre를 정상 종료한다.
4. 새 DMG의 ProPre를 Applications에 드래그해 기존 앱을 교체하고 다시 실행한다.

앱은 브라우저의 다운로드 진행/완료와 Finder의 앱 교체를 알 수 없으므로 완료나 설치 성공을 표시하지 않는다. `download-opened`는 기본 브라우저에 다운로드 요청을 전달했다는 뜻이며 재다운로드·교체 안내를 제공한다. 예배/송출 중에도 안내를 열 수 있지만 교체는 종료 후 수행하도록 표시한다. 앱은 송출·예배 상태·오디오·자료를 변경하거나 자동 종료/설치하지 않는다. 모달은 Escape·닫기·배경 클릭으로 닫고 포커스를 복구한다.

서명·공증 없는 앱은 macOS 경고가 발생할 수 있다. 신뢰한 배포본에 대해 OS가 제공하는 실행 허용 흐름을 안내하며 시스템 전체 보안 설정을 바꾸는 명령을 제공하지 않는다. 기존 자료 디렉터리와 workspace-v4·portable3 형식은 유지한다. 앱 교체와 사용자 자료 삭제를 구분하며 다운그레이드로 저장 형식을 되돌리는 작업은 지원하지 않는다.

## Main 소유 상태와 IPC

`disabled → idle → checking → available → opening → download-opened` 상태를 사용한다. 네트워크/형식 오류는 `error`에서 다시 확인하고, 브라우저 요청 실패는 `available`로 돌아가 재시도한다. 같은 확인·브라우저 요청은 중복 실행하지 않는다. revision으로 늦은 Renderer 조회 응답을 무시하며 종료 시 확인 요청·타이머를 정리한다.

| Control 메서드 | Main 채널 | 기능 |
| --- | --- | --- |
| getAppUpdate | get-app-update | 메모리 상태 조회 |
| checkAppUpdate | check-app-update | 수동 버전 확인 |
| downloadAppUpdate | download-app-update | Main이 검증한 DMG URL을 기본 브라우저로 전달 |
| on | app-update-changed | 상태 알림 |

기존 Control 창·메인 frame·origin 권한 검사를 재사용한다. 송출·PDF helper·외부 웹 view에는 업데이트 API/알림을 노출하지 않는다. Renderer가 URL/경로/명령을 넘기는 API와 설치·재시작 IPC는 없다. Main의 종료 저장/예배 체크포인트 경로는 그대로 유지한다.

## 배포 파일과 보안 경계

현재 공개 저장소 `Cat613/Propre`의 Releases를 기본 위치로 사용한다. `PROPRE_UPDATE_URL`로 다른 HTTPS 디렉터리를 지정할 수 있다. 소스 파일에서 기본 위치를 바꿔도 이미 배포한 앱의 주소는 자동 변경되지 않는다.

릴리즈용 package.json의 `propreUpdates.feedURL`에 `https://github.com/Cat613/Propre/releases/latest/download/propre-update.json`을 포함한다. 개발 실행과 해당 metadata 없는 일반 로컬 패키지는 네트워크에 접속하지 않는다. 지원 플랫폼은 macOS arm64/x64이며 호스트 CPU로 패키징하고 실제 검증 CPU는 별도 기록한다.

```json
{
  "schemaVersion": 1,
  "version": "0.2.0",
  "downloads": {
    "mac-arm64": "https://github.com/Cat613/Propre/releases/latest/download/ProPre-0.2.0-arm64.dmg"
  }
}
```

정식 `major.minor.patch`만 숫자로 비교하고 같은/낮은 버전·prerelease는 권하지 않는다. 해당 CPU의 DMG가 없으면 다른 CPU 파일을 제시하지 않는다. DMG 링크는 feed와 같은 HTTPS origin, 인증정보/query/fragment 없는 `.dmg`로 제한한다. Main이 URL을 소유하므로 arbitrary scheme으로 `shell.openExternal`을 호출하지 않는다.

확인 요청은 인증정보 없이 15초 제한·최대64KiB로 읽는다. GitHub asset CDN 이동을 위해 최대5회의 HTTPS redirect만 허용한다. HTTP 이동·잘못된 JSON/schema·과도한 크기·없는 파일·오프라인은 일반 오류와 재시도로 처리하고 원시 URL/인증정보/오류는 UI에 노출하지 않는다. HTTPS와 배포 계정에 신뢰를 두며 Apple의 서명/공증 검증 또는 앱 내부 파일 해시 검증을 제공한다고 주장하지 않는다.

## 빌드와 전환

`npm run package:free`는 생산 빌드 후 서명·공증 없이 DMG/ZIP과 `propre-update.json`을 만든다. `npm run release`는 기존 권리/장비 증거와 전체 검사를 거친 후 동일한 무료 파일을 만든다. builder `publish:null`, `publish:'never'`, `identity:null`, `forceCodeSigning:false`, `notarize:false`로 Apple 인증과 게시를 요구하지 않는다. electron-updater, Squirrel native adapter, 설치 IPC와 설치 전용 송출 잠금을 제거했다.

배포자는 DMG를 먼저, manifest를 마지막에 게시한다. GitHub는 draft에 모든 파일을 올리고 정식 latest release로 공개한다. 다른 CPU를 따로 빌드할 경우 동일 버전 manifest의 항목을 합친다. 준비 명령은 외부 게시를 수행하지 않는다. 구 자동 설치 앱에 이 주소가 소급 적용되지 않으므로 무료 흐름이 포함된 첫 배포본은 수동 설치가 필요하다.
