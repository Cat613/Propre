# 콘티 보관함과 예배별 곡 사본

갱신: 2026-10-16 Asia/Seoul · 구현 기준 · REQ-038 / TASK-033 / TC-038 / ADR-015 / FLOW-012

## 사용자 흐름과 정책

플레이리스트의 **콘티 보관함**에서 이름·선택 날짜를 입력해 현재 순서를 새 콘티로 복사하거나 빈 콘티를 만든다. 보관한 콘티를 열고 복제·이름/날짜 변경·검색·휴지통 이동/복원할 수 있다. 복제는 새 콘티와 독립된 곡 사본을 함께 만든다. 현재 편집 곡과 송출은 콘티 열기·생성·복제·휴지통 이동으로 자동 전환하지 않는다. 필요한 곡을 클릭하면 기존 자료 선택/송출 흐름을 따른다.

곡을 콘티에 넣을 때 그 시점의 가사·반복 슬라이드·파트 색상·자료 스타일·미디어 참조를 복사한다. 찬양 목록의 원곡을 수정하거나 삭제해도 과거 콘티에 반영하지 않는다. 콘티 안에서의 수정은 그 콘티의 사본에 자동 저장한다. 같은 콘티에서 동일한 사본을 여러 번 배치하면 동일 사본의 수정이 반복 항목에도 반영된다. 원곡을 다시 추가하면 추가 시점의 별도 사본을 만든다. 서로 다른 콘티가 하나의 사본을 공유하지 않는다.

콘티 곡 편집 중 **찬양 목록 원곡에 반영**으로만 원곡을 갱신한다. 원곡 연결이 없으면 **찬양 목록에 새 곡으로 저장**으로 새 원곡을 만든다. 확인창에서 원곡과 콘티 본문 일부/슬라이드 수를 비교하고, 원곡이 콘티 생성 이후 바뀌었으면 안내한다. 취소를 기본값으로 두며 확인 중 원곡 또는 사본의 revision이 바뀌면 전체 반영을 거절한다. 다른 콘티의 사본은 갱신하지 않는다. 보관함을 통해 과거 콘티를 직접 편집하는 것은 그 콘티의 의도적인 변경으로 저장한다.

콘티 사본을 선택·첫 송출할 때는 보존한 자료 스타일을 사용한다. 원곡의 기존 기본 프리셋 적용 정책은 유지한다. 원곡/콘티 편집 맥락을 플레이리스트 영역에 표시한다. 콘티를 열고도 이전 콘티의 곡을 계속 편집 중이면 해당 곡의 소속 콘티 이름을 표시한다.

## 저장과 이전

현재 기준 파일은 `workspace-v4.json` / schemaVersion 4다. 사본 계약은 v2에서 도입되었고 v4에서도 유지한다. 원곡 library와 아래 필드를 한 원자 저장에 기록한다.

| 필드 | 계약 |
| --- | --- |
| setlists | 고유 ID, 이름, 선택 날짜, 생성/수정/최근 열기 시각, revision, 순서 참조, 선택 deletedAt |
| setlistSongs | 독립 Presentation, 선택 sourcePresentationId/sourceRevision. 원곡 library에 넣지 않음 |
| activeSetlistId | 현재 콘티 ID 또는 null |
| playlist | 현재 콘티 items와 동일한 순서 참조. presentationId는 콘티 사본의 ID |
| draft | 마지막 편집 곡. 원곡 또는 사본 ID를 그대로 보존 |

먼저 유효한 v4를 읽는다. 없으면 v3→v2→v1 순서로 존재하는 이전 파일을 선택해 원본과 최근 다섯 백업에서 유효 상태를 찾는다. v1의 순서는 독립 사본을 가진 현재 콘티로 변환하며 전체 계획과 곡 투영을 구성해 v4를 원자 기록한다. 이전 원본과 백업은 수정하지 않는다. 미래 버전 또는 복구 불가능한 데이터는 쓰기를 차단하고 안내한다. 기존 config.json만 있는 환경은 기존 변환 경로를 사용한다.

사본 ID에는 `setlist_` 접두사를 사용한다. 저장 위치가 없는 사본의 journal 복구를 원곡 추가로 처리하지 않고 거절해 복구 기록을 유지한다. 원곡과 사본의 ID 중복·콘티 사이 사본 공유·없는 사본 참조·현재 콘티와 순서 불일치를 거절한다. 작업 공간 최대 24MB, 원곡 최대 5000개, 사본 최대 5000개, 보관함/휴지통 합계 최대 1000개를 기존 Zod/Repository 크기 검사에 연결한다.

휴지통은 메타데이터만 표시에서 제외하며 사본·미디어를 보존한다. 복원 후 다시 열 수 있다. 영구 삭제/휴지통 비우기는 이번 범위에 없다. 사본 및 휴지통에서 참조하는 미디어는 정리 대상에서 제외한다. 새 작업 공간도 최근 다섯 저장본과 손상 원본을 보관한다. 이전 앱은 해당 버전의 보존 파일을 읽으므로 v4에서 새로 한 편집은 이전 앱에 자동 반영되지 않는다.

## API와 편집 연결

Control 전용 manage-setlist/create/open/duplicate/rename/delete/restore와 publish-setlist-song을 추가한다. setlist 명령의 revision과 열기/생성의 현재 ID를 트랜잭션 안에서 비교한다. Store의 순서 대기열과 편집 flush를 공유한다. Main은 native 원곡 반영 확인 전/후 버전을 비교하고 저장한다. Output/Stage에는 변경 API를 노출하지 않는다.

Renderer bootstrap은 원곡·사본·보관함·현재 ID를 별도로 받는다. journal/currentDocument/자동 저장/AI 수정은 사본을 찾아 해당 사본에만 쓰고, 현재 곡·Undo·송출을 자동으로 바꾸지 않는다. 조회 get_presentation/get_preview는 get_playlist가 반환한 사본 ID를 지원하며 get_playlist는 sourcePresentationId도 반환한다. AI set_playlist는 원곡 또는 조회한 사본 ID에서 현재 콘티의 사본을 구성한다. 원곡 갱신은 이 AI 도구의 암묵적 부수 효과가 아니다.

## 파일과 백업 호환

플레이리스트 `.ppros`의 schemaVersion 1을 유지하고 선택 playlistName/playlistDate를 추가한다. 파일은 현재 사본과 반복 순서를 담고, 불러오기는 각 곡을 찬양 목록에 등록/재사용한 다음 독립된 **새 콘티**로 보관·활성화한다. 같은 파일 재불러오기는 원곡/미디어를 재사용하며 콘티 사본은 독립된 새 콘티를 만든다. 기존 활성 콘티도 보관함에 남는다.

전체 백업은 setlists/setlistSongs/activeSetlistId와 포함 미디어를 함께 담아 복원한다. 이전 전체 백업은 원곡과 순서에서 사본을 만들어 복원한다. 개별 자료 파일은 기존 경로를 유지한다. 검증은 [실행 기록](../quality/2026-10-06-콘티-보관함-검증-기록.md), 사용은 [운영 안내](../operations/예배별-콘티-보관-편집.md)를 따른다.

전체 계획·비곡 자료·템플릿·휴대용 형식 3은 [예배 공통 계약](../design/worship/예배-운영-기능-공통-계약.md)을 따른다. 곡 파일과 예배 전체 파일의 포함 범위는 [예배 사용 안내](../operations/예배-전체-순서-사용-안내.md)에서 구분한다.
