# PDF와 이미지로 찬양 슬라이드와 플레이리스트 준비

2026-10-07 Asia/Seoul · 구현 및 격리 검증 완료 · 실제 API 품질 평가 대기 · REQ-037 / TASK-032 / TC-037 / ADR-014 / FLOW-011

PDF 악보·가사집과 이미지 파일을 ProPre에 넣으면 선택한 AI가 MCP 도구로 가사·파트·송폼을 준비한다. 운영자는 가사와 순서를 수정한 뒤 현재 콘티 순서를 새로 구성하거나 기존 순서 끝에 추가한다. 처음에 자동 적용을 선택했다면 명시적인 송폼과 확인 항목이 없는 결과를 자동으로 저장한다. 송출 시작은 운영자가 기존 화면에서 수행한다.

## 곡과 콘티 저장 정책

| 상황                             | 찬양 목록                                                          | 현재 콘티                                     |
| -------------------------------- | ------------------------------------------------------------------ | --------------------------------------------- |
| 기존 곡이 없는 새 찬양           | 자동 등록                                                          | 이번 예배의 독립 곡 사본 저장                 |
| 같은 곡이 이미 존재              | 원곡 보존. `기존 원곡도 이번 구성으로 갱신`을 선택한 경우에만 반영 | 이번 예배의 가사·순서·반복·스타일을 독립 보존 |
| 같은 제목이지만 곡 판단이 불확실 | 후보를 표시하고 운영자가 원곡 연결 또는 별개의 새 곡을 선택        | 확인 전 자동 적용 중지                        |

곡의 원문 파트와 유한 송폼을 보관하고, 송폼을 펼친 Slide 배열을 실제 편집·송출에 사용한다. 같은 곡의 반복 항목은 별개 콘티 항목 ID로 보존한다. 과거 콘티나 기존 곡 사본을 암묵적으로 갱신하지 않는다. 원곡이 현재 편집본이면 준비 화면에서 원곡 갱신을 거절하고 콘티의 별도 원곡 반영 흐름을 이용하게 한다.

## 사용 흐름

1. 오른쪽 아래 도구 모음에서 **AI로 찬양 준비**를 연다.
2. **AI 연결 추가**에서 Gemini/OpenAI/Claude 중 제공자, 이름·모델 ID·API 키를 등록한다. 제공자를 바꿔 저장하면 새 연결을 이 작업에서 바로 선택한다.
3. 사용할 연결, 기존 콘티 끝에 추가 또는 순서 새 구성, 확인 후 적용 또는 명확한 결과 자동 적용을 선택한다. 송폼과 추가 지시를 입력한다.
4. PDF·PNG·JPG·WEBP를 선택하거나 준비 화면에 끌어 놓는다. 파일·페이지·제공자를 확인하고 **분석 시작**을 누른다.
5. 원본 페이지, 곡 제목·파트 가사, 송폼 순서와 반복, 펼친 슬라이드, 원곡 연결과 콘티 곡 순서를 확인한다. 가사와 송폼 확인 완료를 표시한다. 빈 줄은 슬라이드 경계이며 빈 간주 본문은 `content: ''`로 저장한다.
6. **플레이리스트에 적용**한다. 새 곡 등록·원곡의 선택적 갱신·콘티 사본·순서·적용 기록은 함께 저장된다. 기존 곡 편집과 송출은 유지된다.
7. 준비 창을 닫고 콘티에서 곡을 선택한다. **이번 순서 적용 되돌리기**는 이후 콘티 변경이 없을 때 직전 순서만 복원한다. 등록 또는 갱신한 원곡은 유지한다.

유효한 검토 수정은 창을 닫을 때에도 저장한다. 잘못된 송폼이나 저장 실패는 창에 남아 수정·재시도할 수 있다. 최근 작업에서 중단된 분석과 초안을 다시 연다. 다른 AI로 재시도하면 버튼에 명시된 제공자로 같은 파일을 다시 전송하며 초안은 로컬에 보존한다. 다른 제공자로 자동 전환하지 않는다. 선택한 원본과 현재 작업의 지시·곡 초안이 선택한 AI에 전달되며 전체 찬양 목록을 전송하지 않는다.

작업의 AI 연결과 모델은 생성 시 고정한다. 기본 연결 변경은 진행 중인 작업에 영향을 주지 않는다. 연결의 제공자가 나중에 바뀌었으면 해당 제공자 키를 재사용하지 않는다. 키는 Main에서 OS 보호 저장소로 암호화하고 Renderer·MCP·내보내기·로그에는 반환하지 않는다. 이전 Gemini 단일 이미지 추출 버튼과 그 전용 분석 경로는 제거했으며 기존 암호화된 키는 Gemini 연결을 위한 호환 경로로 보존한다. 외부 MCP 연결은 별도 기능으로 유지한다.

## 송폼과 표시

`SongForm.parts`는 파트 ID·표시 이름·슬라이드별 가사·sourceId·sourcePage를 가진다. `sequence`는 partId와 1~20의 repeat 배열이다. 알 수 없는 참조, 중복 파트 ID, 빈 순서, 곡당 200장 초과는 거절한다. D.C./D.S./Coda처럼 해석이 필요한 악보 표기는 AI가 유한 순서로 해석하고 불확실하면 확인 항목으로 남긴다.

A가 2장, B가 2장, C와 TAG가 각각 1장일 때 `A B A B×2 C B TAG`는 14장이다. 각 반복·페이지에 고유 slide ID와 원래 파트·진행 단계·반복·페이지 매핑을 부여하며 같은 파트 색상은 유지한다. 기본 찬양 프리셋은 작업을 만들 때 캡처하고 콘티 사본의 저장된 스타일을 사용한다. 자동 추출 이후의 수동 슬라이드 수정은 기존 편집 경로로 보존하며 송폼에서 자동 재생성하지 않는다.

AI는 명시된 송폼을 `formEvidence: explicit`, 추정 순서를 `inferred`로 기록한다. inferred는 앱에서도 자동 적용을 중지한다. 사용자 지시를 우선하며 없는 가사를 만들어 넣지 않도록 요청한다. 원문 대조와 가사 품질 자체는 실제 자료에 대한 운영자 수용 검사가 필요하다.

## 실제 MCP 실행과 권한

Main에 공식 MCP SDK의 McpServer와 Client를 InMemoryTransport로 연결한다. 초기화·도구 발견·호출·결과 회신을 실제 SDK로 수행한다. AI의 제공자 도구 호출을 내부 MCP로 전달한다. 로컬 파일 경로를 클라우드 MCP 주소로 공개하지 않는다.

| 도구                    | 역할                                                             |
| ----------------------- | ---------------------------------------------------------------- |
| `get_song_job`          | 선택 파일 메타데이터·지시·현재 초안·초안 revision 조회           |
| `stage_song_drafts`     | 원문·송폼·곡 목록·순서의 작업본 저장, expectedDraftRevision 검사 |
| `stage_setlist`         | 준비된 곡의 순서 및 반복 항목 설정                               |
| `validate_prepared_set` | 참조·출처·한도·확인 상태 검사, planHash 반환                     |
| `get_prepared_preview`  | 공통 렌더러로 준비 슬라이드 PNG 생성                             |
| `apply_prepared_set`    | 검토/자동 적용이 승인한 계획에만 원자 적용                       |
| `get_apply_receipt`     | 저장 결과 조회                                                   |

분석 모델에 노출되는 도구에는 최종 apply·미리보기·영수증을 포함하지 않는다. 모델은 작업본 준비와 검증을 담당하고 앱 실행기가 승인된 계획에 대해 동일 MCP의 apply를 호출해 완료한다. 모델이 보낸 originalId·originalRevision·updateOriginal·confirmed는 앱이 재설정한다. 원곡 후보는 제목 정규화와 전체 고유 가사 일치로 연결하며 제목만 같거나 가사 분할이 다르면 검토에서 선택한다.

최종 적용 세션은 해당 job의 planHash·draftRevision·적용 방식·대상 콘티 ID/revision·원문 hash·원곡 revision에 묶인다. 파일 내용이나 모델 인자로 권한을 만들 수 없다. 분석 세션에는 원본 파일 읽기 경로·외부 URL 방문·기존 자료 삭제·송출 명령 도구가 없다. 외부 MCP의 기존 read/prepare 권한은 변경하지 않는다.

## 원자 적용과 복구

검토 화면은 적용 전에 기존 편집을 flush하고 공통 playlist 대기열을 사용한다. 이 준비 화면 하나가 열려 있을 때만 좁은 모달 예외를 허용하고 저장 구간에 컨트롤 입력을 잠근다. F2 긴급 중단은 유지한다. 분석 중에는 전체 편집 잠금을 유지하지 않는다.

Repository transaction 안에서 현재 콘티 ID/revision과 선택 원곡 revision을 다시 확인한다. 새 곡과 연결할 원곡이 분석 후 새로 등록된 경우 재검토한다. append는 기존 항목 ID와 순서를 그대로 두고 새 항목만 붙인다. replace도 사전에 순서를 지우지 않는다. 하나라도 저장 실패하면 곡·사본·순서·영수증 전체 미적용이다.

`workspace-v2.json`의 선택적 `songReceipts`에 requestId·planHash·이전/최종 순서·최종 revision·추가/갱신 수를 함께 저장한다. 같은 requestId/planHash는 앱 재시작 후에도 기존 결과를 반환하며 같은 요청 ID로 다른 계획을 적용하면 거절한다. 응답 유실 후 영수증을 조회한다. 취소가 저장에 앞서면 미적용이며 committing 이후에는 영수증으로 결론낸다.

콘티나 원곡이 변경되면 초안을 남기고 **최신 콘티에 맞춰 다시 확인**한다. 원곡이 바뀌면 확인 완료도 해제한다. undo는 최종 콘티 revision과 순서가 기록과 같을 때에만 순서를 복원한다. 기존 편집 Undo·현재 선택·송출을 소비하지 않는다.

## 파일·작업 수명과 제한

Main의 파일 선택과 preload의 실제 File 드롭 경로로 파일을 복사한다. Renderer와 MCP는 sourceId로만 선택된 복사본에 접근한다. 파일당 20MB, 작업당 40MB, 20파일/50페이지, 20곡, 곡당 200장/총 1,000장을 제한한다. 확장자·매직 바이트·실제 이미지 디코딩·4천만 화소 한도·PDF 해독/암호화·페이지 수를 확인하고 hash 변경을 거절한다. PDF 원문은 로컬 파서/워커로 표시하며 원문의 링크·스크립트를 실행하지 않는다.

파일 묶음은 제공자 요청 크기에 맞춰 나눈다. Gemini는 인코딩된 요청 19MiB, OpenAI/Claude는 30MiB를 앱 상한으로 두며 도구 정의·본문·이력을 포함해 검사한다. 단일 큰 파일은 시작/분석 단계에서 크기를 줄이거나 나누도록 안내하며 자동으로 잘라 버리지 않는다. 묶음별 초안을 합치고 모든 입력 파일의 곡 출처가 반영됐는지 확인한다. 일부만 준비됐으면 전체 자동 적용하지 않고 준비된 곡만 쓰는 명시적 검토 흐름으로 돌아온다.

각 API 요청 120초, 작업 10분, 모델 왕복 12회, 도구 호출 40회, API 응답 및 durable 작업본 4MiB를 제한한다. API usage 숫자는 작업에 기록하며 검증되지 않은 가격은 표시하지 않는다. 원문·가사·개인 경로·인증 값을 진단에 기록하지 않는다.

원문과 상세 작업본은 `userData/song-jobs/<jobId>/`에 보관한다. 완료/취소 작업은 생성 후 7일이 지나면 다음 시작 시 정리하며 미확정/중단/부분 실패 초안은 보호한다. **원본과 작업본 계속 보관**으로 보존하거나 **원본·작업본 삭제**로 즉시 정리한다. 곡·콘티·영수증은 원본 정리 뒤에도 유지된다. 원본은 일반 송출 미디어·발표/백업 내보내기에 자동 포함하지 않는다.

PDF 원문 뷰어의 파서와 워커는 준비 원본을 표시할 때 불러온다. 기존 컨트롤/송출 JavaScript 총 예산 700KB는 유지하며 선택적 PDF 파서 500KB·워커 1.2MB를 별도 검사한다. 관련 라이선스 원문을 앱 패키지에 포함한다.

## 검증과 남은 수용 확인

[검증 기록](../quality/verification-2026-10-07-ai-song-preparation.md)은 합성 파일·합성 API 응답의 실행 증거와 실제 계정 API 평가를 구분한다. 기존 송출·성경 삽입·자동 저장·MCP·파일 이동·콘티 보관함 회귀를 포함한다. 실제 Electron 검사는 실제 userData 경로가 임시 경로인지 먼저 확인한다.

실제 API 키·모델 접근과 실제 한국어 스캔 악보의 OCR/파트/반복 정확성은 아직 수용 평가하지 않았다. API 호출 성공이나 합성 응답 검사로 가사 정확성을 보증하지 않는다. 설치된 AI 클라이언트의 앱 내 실행, 로컬 모델, 클라우드 MCP 직접 연결은 후속 어댑터 범위다. 정확한 원문 영역 bbox와 자동 PDF 재분할은 현재 구현하지 않고 페이지 번호와 전체 페이지 비교를 제공한다.
