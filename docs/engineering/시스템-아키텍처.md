# 시스템 아키텍처

갱신: 2026-10-16 · 제품 0.1.0 로컬 구현 기준 · [검증](../quality/2026-10-04-운영-개선-후속-검증.md)

Electron·React·Zustand를 유지하며 저장·창·키·AI의 책임을 Main 서비스로 분리했다. 컨트롤만 편집 Store를 초기화하고 메인/모니터는 자신의 검증된 최신 상태를 수신한다.

```mermaid
flowchart LR
    C[컨트롤 UI] --> D[편집 Store와 자료 ID]
    D --> R[중앙 구독과 자동 저장]
    R --> P[역할별 preload]
    P --> M[Main IPC 권한과 입력 검증]
    M --> S[자료 저장소와 에셋]
    M --> W[창 관리자와 최신 상태 버전]
    W --> O[메인: 공통 합성]
    W --> T[모니터: 현재와 다음]
    O --> A[ready와 applied]
    T --> A
    A --> W
    M --> K[OS 보호 키]
    M --> G[AI 요청과 취소]
```

## 자료와 송출

자료 ID·제목·본문·요소·자료별 스타일·revision을 작업본으로 저장한다. 변경된 작업본은 라이브러리의 같은 ID에 자동 저장하며 이전 디스크 상태 5개를 보관한다. 수동 확정 버전과 별도의 장기 편집 분기를 추가한 것은 아니다.

기존 클릭 송출을 유지한다. 활성 슬라이드의 편집·삭제·정렬·Undo는 중앙 발행 구독에서 메인/모니터로 보낸다. 새 자료 전환은 활성 슬라이드를 해제한다. 새로 열거나 생성한 자료는 다른 자료의 ID를 상속하지 않는다.

Main은 화면별 최신 전체 상태와 증가하는 버전을 보관한다. Renderer가 ready를 보내면 캐시를 전달하고 실제 DOM 반영 후 applied를 보고한다. 구버전은 무시한다. 적용 상태는 소프트웨어 화면의 상태이며 실제 HDMI·프로젝터·스피커의 확인을 대신하지 않는다.

## 저장과 복구

작업본 변경은 즉시 로컬 journal에 복구 기록을 남기고 마지막 변경 뒤 400ms에 검증된 Main 저장을 요청한다. ID별 대기열이 자료 전환의 수정본을 보존한다. 저장이 진행 중이어도 새 변경은 대기열의 최신 revision으로 남는다.

Repository는 검증 → 임시 파일 쓰기·fsync → 최종 rename·디렉터리 sync → 메모리 상태 확정 순서를 따른다. 실패하면 현재 디스크/메모리의 이전 확정 상태와 Renderer 편집본을 보존한다. 손상 파일은 별도 보관하고 유효 직전 상태를 읽으며 복구 불가능할 때 덮는 저장을 중지한다.

정상 종료는 열린 편집창을 먼저 반영하고 자료·설정·미디어 기록을 기다린다. 컨트롤만 닫으면 시각 출력은 유지하되 오디오를 중단한다. 화면 프로세스 중단은 창을 다시 만들고 준비 뒤 상태를 재전달한다. 재실행 자료 복원과 마지막 본문/오디오 자동 송출은 구분한다.

## 미디어와 보안

`app://propre`는 앱 번들 안의 파일만, `media://asset/<id>/<name>`는 등록 목록과 실제 미디어 루트 안의 파일만 제공한다. 심볼릭 링크와 경로 탈출을 거절하며 URL 인코딩 이름을 지원한다. 외부 legacy 경로는 임의로 읽지 않고 등록 누락으로 유지해 명시적으로 재연결한다.

모든 창은 sandbox·contextIsolation·webSecurity를 켠다. Main이 실제 BrowserWindow/webContents·main frame·origin을 검사하며 컨트롤만 변경 권한을 갖는다. CSP·권한 요청 거절·탐색/새 창 차단을 적용한다. 키는 Main에서만 사용하고 Renderer에는 configured 여부만 반환한다.

Audio는 컨트롤 루트 한 곳에서 재생한다. 시각 출력 창에 audio를 만들지 않으며 Look의 audio 숨김·전체 중단이 같은 Store 상태를 사용한다. 영상 요소는 muted video로 재생한다.

## 빌드와 지원 범위

화면 역할별 코드와 성경 JSON을 지연 로드한다. 성경 데이터는 한 번 색인하고 장별 조회를 사용하며 UI는 필요한 상태만 구독한다. 공통 Renderer JS는 합계·개별 청크 700,000바이트, 선택 예배 상세 화면은 합계 180,000바이트·개별 100,000바이트를 검사한다. 선택 PDF 파서는 500,000바이트, 워커는 1,200,000바이트가 별도 상한이다. 실제 기준은 `scripts/check-bundle.mjs`다. 합성 시험의 시작 시간과 working-set 숫자는 원문 없이 기록한다.

검사·번들·로컬 앱 패키징·공개 릴리즈 명령을 구분한다. 현재 검증 대상은 macOS arm64다. Windows/Linux·모든 장비·서명 설치/갱신·장시간 현장 부하를 확인한 것으로 표시하지 않는다. 자세한 파일 계약은 [데이터·IPC](데이터-저장-IPC-계약.md), 정책 근거는 [ADR-008](../governance/결정-기록.md), 배포 경계는 [릴리즈 기준](../operations/릴리즈-운영-투입-기준.md)에 있다.

변경 전 구조는 [초기 운영 검토](../../프로프리-프로젝트-구조와-운영-개선-목록.md)와 [초기 구현 목록의 검토](../review/프로프리-전체-검토-보고서.md)에 보존한다. 공식 적용 근거: [Electron 보안](https://www.electronjs.org/docs/latest/tutorial/security), [safeStorage](https://www.electronjs.org/docs/latest/api/safe-storage), [protocol](https://www.electronjs.org/docs/latest/api/protocol).

## 확장 서비스와 현재 저장 기준

현재 작업 공간은 `workspace-v4.json`이다. 전체 예배 계획과 곡 투영·비곡 자료 사본·템플릿을 Repository에서 함께 검증한다. 전체 백업·예배·템플릿 파일은 휴대용 형식 3이며 이전 작업 공간 1/2/3과 백업 1/2 읽기를 유지한다. [데이터 계약](데이터-저장-IPC-계약.md)과 [예배 공통 계약](../design/worship/예배-운영-기능-공통-계약.md)이 상세 기준이다.

| 서비스 | 책임과 경계 |

웹은 앱 브릿지가 없는 별도 세션이고, PDF·인쇄 보조 화면은 요청별로 제한된 접근만 갖는다. 외부 웹 소리와 컨트롤의 오디오 파일 재생은 각각의 정책을 사용한다. [최종 로컬 회귀 기록](../quality/2026-10-16-큐시트-PDF-인쇄와-최종-회귀.md)은 실장비·서명 설치 증거와 구분한다.

## 음악·송출 작업 공간 통합 (2026-10-17)

중앙 편집 상단에 현재 송출 미리보기를 배치하고 음악 설정/목록은 우측 미디어에 통합했다. 미디어 음악 상세와 성경 추가 dialog는 실제로 열 때 동적 로드하며 기본 공유 renderer 700KB 한도는 유지한다. 음악 엔진은 inspector와 독립이며 준비/저장/탭 이동이 재생을 바꾸지 않는다. 로컬 엔진/전환 의도는 Control, 외부 native socket·인증·대상/명령 세대는 Main MusicBridge가 소유한다.
