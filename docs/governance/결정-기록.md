## ADR-001 Markdown 중심의 프로젝트 산출물 관리

상태: 확정 · 근거: 이번 사용자 요청 · 날짜: 2026-10-04

결정: `docs/README.md`를 문서 진입점으로 두고 검토·기획·설계·작업·검증·운영·결정·위험·양식을 Markdown으로 관리한다. 기존 루트 문서에는 기록의 시점과 현행 문서 위치를 표시한다.

이유: 요구사항→작업→검증 관계와 현재 구현·제안·실행 증거를 한 저장소에서 관리하기 위해서다. 외부 문서 서비스가 없어도 파일과 Git으로 변경을 추적할 수 있다.

결과: REQ-030 / TASK-025 / TC-030. 제품 기능을 구현하거나 배포하는 결정은 포함하지 않는다.

## ADR-002 준비 자료와 라이브 상태의 경계

상태: 제안 · 관련: Q-005, REQ-001, REQ-002, REQ-006, REQ-010

문제: slides 교체가 기존 발표 ID를 유지하고 일부 편집 액션이 화면을 갱신하지 않아 자료와 라이브가 어긋난다.

| 선택 | 동작 | 장점·영향 |
| --- | --- | --- |
| A. 직접 클릭 송출 유지 + 상태 분리 | 일반 클릭은 송출, 편집·검색·가져오기는 준비 상태. 라이브 편집 적용은 별도 규칙 | 현재 숙련 흐름을 유지하면서 전환·저장 안전성 개선; 적용 정책 결정 필요 |
| B. 준비 후 명시적 Take | 먼저 선택·미리보기 후 송출 버튼·키 | 잘못된 클릭 송출을 줄일 수 있음; 기존 빠른 운영 동작 변경 |

권고: 첫 안정화에서는 A를 기반으로 자료 ID·dirty·LiveSnapshot을 구분한다. 라이브 수정의 즉시 적용/명시 적용은 구현 전에 확정한다. B는 비교 가능한 후속 모드로 검토한다.

영향: TASK-001, TASK-002, TASK-004, TASK-008, TASK-019의 명령과 검사 기준.

## ADR-003 요소 텍스트의 단일 원본과 좌표 단위

상태: 제안 · 관련: REQ-005, REQ-028

결정안: elements를 새 형식의 내용 원본으로 두고 content는 호환·표시용 파생 값으로 관리한다. 새 좌표는 명시된 percent 단위를 사용하고 캔버스 기준 크기를 기록한다.

대안: content를 일반 가사 원본으로 유지하고 복잡 요소 슬라이드를 별도 타입으로 나누는 방법도 가능하다. 이 경우 두 모드의 변환·일괄 편집 의미를 더 명확히 해야 한다.

권고 이유: 현재 캔버스·인라인·일괄·Stage가 다른 값을 읽는 문제가 있으므로 먼저 동일한 텍스트 의미를 보장해야 한다. 기존 단위 추측은 변환 시 원래 표시를 보존한다. 빈 요소·여러 텍스트의 읽기 순서는 별도 규칙이 필요하다.

영향: TASK-006, TASK-008, TASK-011, TASK-019, TASK-023.

## ADR-004 버전 있는 JSON과 이동 미디어

상태: 제안 · 관련: Q-006, REQ-003, REQ-016, REQ-017

결정안: 기존 `.ppros` JSON을 계속 읽고 새 문서에는 format·schemaVersion·발표 스타일·assetId·참조를 기록한다. 공유·다른 PC 이동에 필요한 미디어 포함 산출물은 식별 가능한 별도 형식으로 제공하는 방향을 검토한다.

대안: 프로젝트 폴더(문서+media)를 직접 이동하거나, 문서와 바이너리를 하나의 압축 패키지로 묶는다. 폴더는 구조가 보이고 부분 복원이 쉽지만 이동 관리가 필요하다. 압축은 단일 파일 이동이 쉽지만 추출 제한·호환·용량 검증이 추가된다.

확정 필요: 휴대용 파일 요구, 최대 용량, 프리셋·순서 포함 범위, backward 호환, extension. 기존 파일을 다른 형식으로 무음 변경하지 않는다.

영향: TASK-011, TASK-012, TASK-014 및 백업·복원 기준.

## ADR-005 지우기 범위와 오디오 재생 책임

상태: 제안 · 관련: Q-003, REQ-011, REQ-012

문제: 현재 모두 지우기는 props를 남기고 UI audio는 독립 재생한다.

| 선택 | 지우기·중단 | 운영 영향 |
| --- | --- | --- |
| A. 모두 지우기를 전체 중단으로 정의 | 모든 시각 레이어와 지정 오디오 중단 | 단순한 의미, 기존 고정 로고 유지 기대 변경 |
| B. 일반 지우기와 긴급 전체 중단 분리 | 일반 지우기 범위 명시, 긴급 중단은 전체 | 기존 로고 유지 가능, 버튼·키 구분 필요 |

권고: B를 비교안으로 제시하되 긴급 중단은 화면·소리를 함께 검사한다. Audio 재생 주체는 1개로 정한다. Control의 전용 재생 서비스 또는 Main이 관리하는 별도 역할을 선택하며 출력 창마다 재생하지 않는다.

영향: TASK-003, TASK-014, TASK-020. 실제 버튼·F2·Escape 정책은 선택 후 확정한다.

## ADR-006 시작·종료·복구 정책

상태: 제안 · 관련: Q-004, REQ-002, REQ-013, REQ-014, REQ-025

결정안: 자료·순서·장비 설정 복원과 라이브 재개를 구분한다. Control 종료에 따른 출력·Stage·오디오 처리와 미저장 확인을 명시한다.

대안: 이전 출력 창을 자동 복원하거나 운영자 확인 뒤 켠다. 어느 방식에서도 창 ready 후 최신 상태를 보내고 누락 장비·실제 표시를 확인해야 한다. 마지막 콘텐츠 자동 재송출은 별도 결정이다.

권고: 안전한 대기·운영자 재개를 기본 제안으로 두되 실제 반복 운영 요구를 확인한다. 현재 활성 플래그를 복구 완료 증거로 쓰지 않는다.

영향: TASK-001, TASK-004, TASK-005, TASK-021.

## ADR-007 키 보호와 선택 AI 기능

상태: 제안 · 관련: Q-007, REQ-020, REQ-021

결정안: 키는 보호 저장 또는 세션 사용으로 관리하고 출력 창에서 조회하지 않는다. AI는 명시적 이미지 전송·취소 가능한 요청·결과 검토로 제공한다. 기본 오프라인 송출은 외부 AI 상태와 독립적이다.

대안: 기능을 사용하지 않거나, 사용자가 자신의 키를 입력하는 현재 형태를 보호 경계와 함께 유지한다. 별도 서버·공용 키·결제 서비스는 이번 범위에 도입하지 않는다.

확정 필요: 실제 공급자·모델·자료 처리 안내·비용 표시와 보호 저장 불가 정책. 모델 가용성은 실제 API 검사 시 다시 확인한다.

영향: TASK-010, TASK-015. 실제 API 호출·키 입력·외부 전송을 이번 문서 작업이 수행한 것은 아니다.

확정할 때 결정자·날짜·근거·선택한 대안·영향받는 REQ·TASK·TC를 추가한다. 기존 결정은 삭제하지 않고 대체 ADR을 연결한다. 코드가 이미 일부 존재하더라도 제품 정책 확정의 증거로 대체하지 않는다.

## ADR-008 운영 개선·자동 저장·창 구분의 구현 기준

상태: 구현 적용 · 날짜: 2026-10-04 · 근거: 전체 검토 개선 및 추가 자동 저장/창 구분 요청 · 구현 판단: Codex

초기 ADR-002~007의 비교안을 보존하고 이번 버전의 동작을 기록한다. 사용자가 각 비교안을 개별 선택했다고 해석하지 않으며 승인된 개선 범위에서 적용한 기본 정책을 명시한다.

- 자료: 새 찬양·성경·파일은 새 ID. 같은 자료는 자동 저장하고 ID별 대기·중단 journal로 전환/실패를 보호한다. 수동 저장 확인 반복 대신 상태·마지막 시각·재시도·직전 기록 제공.
- 송출: 기존 클릭 송출 유지. 활성 슬라이드의 편집/삭제/정렬/Undo는 메인·모니터에 반영. 자료 전환은 활성 본문 해제. Take 모드는 추가하지 않음.
- 모델: elements가 있으면 텍스트 원본, content는 파생 값. 요소 없는 legacy는 content 사용. 인라인/일괄 편집은 첫 text에 합치고 다른 시각 요소 유지. 새 좌표는 명시 percent, 명시 pixel도 지원.
- 파일: .ppros JSON 유지, format/schemaVersion/kind와 스타일·등록 미디어 포함. 전체 백업은 작업본·순서·설정 포함, API 키 제외. 기존 JSON은 원본 보존하며 읽음.
- 중단/오디오: 모두 지우기와 F2/모달 밖 Escape는 모든 시각 레이어·오디오 중단. 컨트롤 루트의 단일 audio. 모달 Escape는 변경 반영 후 닫기, Tab은 모달 안에서 이동.
- 창: 세 제목과 Dock 메뉴 고정. 컨트롤만 닫으면 시각 출력 유지·오디오 중단, 다시 열기 가능. 전체 재시작은 자료/설정/창 활성 복원과 마지막 본문/소리 자동 송출을 분리.
- 키/AI: Main OS 암호화만 영구 저장, 보호 불가 시 평문 대체 거절. 설정 진입·Google 전송 안내·모델·취소·45초 제한·오래된 결과 적용 방지.
- 환경: 0.1.0 / com.propre.presenter, 현재 macOS arm64 로컬 검증, 개발/CI Node 24. 권리·실장비·서명 증거는 별도 릴리즈 조건.

영향: REQ-001~029, REQ-031 / TASK-001~024, TASK-026. [후속 검증](../quality/2026-10-04-운영-개선-후속-검증.md)과 [구현 결과](../operations/2026-10-04-운영-개선-구현-결과.md)를 따른다.

## ADR-009 모니터의 본문 스타일 연동과 읽기 구성 유지

상태: 확정 · 날짜: 2026-10-05 · 근거: 사용자가 "본문 스타일만 연동하고 모니터 구성 유지"를 선택함.

결정: 현재·다음·시계를 유지하며 메인 자료/요소의 본문 스타일과 성경 구절 표기를 연동한다. 모니터 글자 크기는 별도 설정을 최대값으로 사용한다. 검정 배경의 읽기 구성에서 본문을 맞추고 구절의 방향을 별도 줄로 표현한다. 텍스트 요소의 읽기 순서와 메인/모니터 공통 스타일 해석을 유지한다.

성경 구절 표기의 글꼴·색상·크기는 기존의 별도 설정을 유지한다. 본문 스타일 변경 시 구절 표기도 함께 바꾸는 추가 요청은 사용자가 철회했으며, 해당 연동은 적용하지 않는다.

이유: 메인의 자료별 차이를 모니터에서도 알아볼 수 있도록 하면서 진행자가 현재·다음 본문을 읽는 흐름을 유지한다.

결과: REQ-032 / TASK-027 / TC-032. [검증](../quality/2026-10-05-모니터-찬양-성경-스타일-연동.md), [계약](../engineering/데이터-저장-IPC-계약.md), [운영 안내](../operations/준비-진행-종료-장애-대응.md)를 함께 갱신한다.

## ADR-010 기본 프리셋 자동 적용 복구

상태: 확정 · 날짜: 2026-10-05 · 근거: 사용자가 지정한 찬양 프리셋이 찬양 송출에 적용되지 않는 문제의 수정 요청.

결정: 기본 프리셋이 지정되어 있으면 기존·새·가져온 자료를 열 때 해당 종류의 프리셋을 적용한다. 다시 시작한 자료의 첫 송출과 찬양↔성경 종류 전환에도 적용한다. 설정에서 현재 종류의 기본 프리셋을 바꾸면 즉시 적용한다. 송출 본문·스타일·배경을 한 번의 상태 변경으로 반영한다.

같은 종류의 슬라이드 진행 중에는 사용자가 직접 조정한 스타일을 유지한다. 기본값 지정 없음 또는 없는 ID는 자료의 저장 스타일을 유지하며, 삭제 시 기본값/선택 ID를 정리하되 현재 스타일은 남긴다. 개별 텍스트 사용자 스타일이 전역 스타일보다 우선하는 기존 규칙과 독립 성경 구절 설정을 유지한다.

이유: 자료별 스타일 복원 보완 때 빠진 기존 자동 적용 경로를 복구하고, 한 찬양을 진행하는 동안의 직접 조정이 매 슬라이드마다 덮이지 않도록 한다. 기본 프리셋이 선택된 경우에는 자동 적용이 저장된 전역 스타일보다 우선한다.

결과: REQ-033 / TASK-028 / TC-033. 적용된 전역 스타일과 기본값은 기존 자동 저장으로 기록한다. [검증](../quality/2026-10-05-기본-프리셋-자동-적용-복구.md)과 [운영 안내](../operations/준비-진행-종료-장애-대응.md)를 연결한다.

## ADR-011 외부 AI의 로컬 자료 준비

상태: 구현 적용 · 날짜: 2026-10-05 · 근거: 사용자가 AI에서 앱을 사용할 구현을 질문한 뒤 설계부터 구현·검증까지 진행하도록 요청함. 첫 범위의 세부 구현 판단: Codex.

결정: 같은 컴퓨터의 MCP 클라이언트에 자료 검색/조회·성경 위치 조회·새 자료 생성·본문/스타일/추가 슬라이드 일괄 수정·진행 순서 구성·PNG 준비 미리보기를 제공한다. Main의 세션 인증·조회/준비 권한을 거쳐 컨트롤 명령과 Store/직렬 Repository를 사용한다. 기존 창의 IPC 권한을 외부에 확대하지 않는다. 준비 작업은 현재 선택/송출을 유지하고 송출에 영향을 줄 수 있는 현재 자료 수정을 거절한다. 실시간 송출·외부 파일 접근·삭제·웹 공개 연결은 후속 범위로 둔다.

기본 꺼짐과 재시작 후 재허용, 0600 연결 파일과 127.0.0.1 바인딩, Host/Origin/인증/크기/동시 요청 검사. 패키지의 Electron Node 모드로 stdio를 실행하고 클라이언트 설정에 토큰을 넣지 않는다. expectedRevision과 동일 세션 requestId 결과 재사용으로 동시 편집/중복 작업을 보호한다. 결과 불명은 재실행하지 않으며 세션을 바꾼 뒤에는 재조회가 필요하다. 현재 자료는 한 번의 Undo와 journal·자동 저장, 다른 자료/순서는 저장 성공 후 UI 반영을 따른다.

기본 프리셋 우선과 종류 전환 규칙을 준비 미리보기에도 적용한다. 미리보기 역할에는 변경 API를 주지 않고 이미지/영상 오류를 실패로 반환한다. 자료 생성·준비는 실제 장비 송출 완료로 표현하지 않는다.

이유: 외부 AI가 기존 자동 저장·Undo·창 상태를 우회하면 앱의 현재 편집과 결과가 어긋난다. 공통 준비 경로와 제한된 세션 권한으로 준비와 현장 진행을 함께 유지한다.

결과: REQ-034 / TASK-029 / TC-034 / FLOW-009. [설계](../engineering/AI-연결-설계와-계약.md), [사용·복구](../operations/AI에서-ProPre-사용하기.md), [검증](../quality/2026-10-05-AI-로컬-연결-자료-준비-구현과-검증.md)을 연결한다. 실제 사용자의 Codex 계정 설정을 변경하거나 공개 플러그인을 배포한 것은 아니다.

## ADR-012 찬양 자료에 말씀 슬라이드 삽입

상태: 구현 적용 · 날짜: 2026-10-05 · 근거: 사용자 요청 "찬양 슬라이드에 성경 구절을 추가할 수 있는 기능을 만들어줘" · 세부 동작 판단: Codex

결정: 찬양 편집 화면에서 별도 검색·선택 모달로 개역개정 구절을 현재 자료에 삽입한다. 선택한 항목은 본문·bibleReference를 가진 bible 슬라이드로 결과 순서대로 추가한다. 원본에서 묶인 절은 분리하지 않는다. 위치는 맨 앞/맨 뒤/지정 슬라이드 뒤이며 다중 선택 시 문서 순서상 마지막 선택 슬라이드 뒤를 기본으로 한다. 선택이 없으면 맨 뒤다.

자료 ID·제목·기존 슬라이드·현재 라이브 본문·스타일·배경을 보존한다. 추가는 단일 편집 이력이며 자동 저장/Undo/Redo/모니터 다음 본문에 기존 경로로 반영한다. 송출은 추가 후 슬라이드 클릭으로 수행하며 기존의 종류별 기본 프리셋과 독립 출처 스타일을 사용한다. 검색은 공통 장·절 검증을 재사용한다. 취소·검색 실패·선택 없음·검색 변경의 늦은 결과는 추가하지 않는다. 대상 자료 변경과 삭제된 삽입 위치도 거절한다.

이유: 성경 탭의 새 자료 열기 동작만으로는 찬양의 가사 사이에 말씀을 배치하기 어렵다. 현재 자료에 추가하는 명시적 동작을 제공하고 기존 자료 저장·송출·스타일 모델을 사용한다. 새 데이터 형식이나 IPC를 추가하지 않는다.

결과: REQ-035 / TASK-030 / TC-035. [검증](../quality/2026-10-05-찬양-자료에-성경-구절-추가.md), [FLOW-008](../product/사용자-흐름-명세.md#flow-008-찬양-자료에-성경-구절-추가), [운영 안내](../operations/준비-진행-종료-장애-대응.md)를 연결한다.

## ADR-013 플레이리스트 파일로 콘티 이동

상태: 구현 적용 · 날짜: 2026-10-05 · 근거: 사용자 요청과 “파일 저장·불러오기부터” 선택 · 세부 동작 판단: Codex

결정: 기존 단일 진행 순서에 파일 저장·불러오기를 추가한다. 앱 안의 여러 플레이리스트 보관함은 후속 범위다. 파일에는 순서 참조와 해당 자료의 본문·스타일·태그 색상·참조 미디어를 포함한다. 반복 곡은 자료를 한 번 포함하고 순서 참조를 반복한다. 확인창에서 곡 순서를 보여주고 교체를 명시한다.

불러오기는 동일 제목·본문·슬라이드 구성·스타일을 재사용하며 문서/슬라이드/요소 ID와 수정 시각·revision은 비교에서 제외한다. 다른 내용은 새 문서 ID로 보관한다. 곡과 순서는 한 Repository 트랜잭션으로 저장하며 시작 시 참조를 최종 트랜잭션에서 다시 비교한다. 실패 시 생성한 미디어를 정리하고 기존 자료·순서를 유지한다. 기존 선택·draft·송출·설정을 바꾸지 않는다. 스타일 선택은 ADR-010의 기본 프리셋 정책을 유지한다.

이유: 콘티 파일에 순서만 있으면 다른 컴퓨터에서 개별 찬양을 찾지 못한다. 전체 백업을 복원하면 관련 없는 자료·설정까지 교체되므로 콘티에 필요한 곡을 함께 이동하는 파일 단위를 제공한다. 제목만으로 일치시키면 수정한 가사를 잃을 수 있으므로 실제 내용을 비교한다.

결과: REQ-036 / TASK-031 / TC-036 / FLOW-010. [사용 안내](../operations/플레이리스트-파일-저장-불러오기.md), [검증](../quality/2026-10-05-플레이리스트-파일-저장-불러오기-검증.md), [데이터 계약](../engineering/데이터-저장-IPC-계약.md)을 연결한다.

## ADR-014 파일에서 AI 찬양과 플레이리스트 준비

상태: 승인·구현·격리 검증 완료 / 실제 API 평가 대기 · 날짜: 2026-10-06 · 근거: 사용자가 PDF/이미지를 앱에 넣어 AI가 MCP로 송폼·반복 슬라이드와 플레이리스트를 구성하도록 설계를 요청함. 후속 요청으로 여러 AI 등록·작업별 선택과 새 곡의 찬양 목록 등록, 기존 곡에 한한 원곡 갱신 선택을 범위에 반영함.

설계안: Main의 제공자 어댑터/작업 실행기와 내부 MCP 클라이언트가 공통 도구를 사용한다. 첫 API 대상은 Gemini/OpenAI/Claude다. 파트 원문과 유한 진행 순서를 별도로 저장하고 기존 Slide 배열로 펼친다. 임시 작업본에서 검토하거나 명시적 자동 적용으로 진행하며, 가사/순서 불확실성은 운영자에게 돌아온다.

플레이리스트는 새 구성(replace)과 끝에 추가(append)를 제공한다. 곡·순서·durable receipt를 한 트랜잭션으로 저장하고 추가 시 기존 항목 ID를 유지한다. 교체도 라이브러리·현재 곡·편집본·Undo·송출을 유지하고 직전 순서 복원을 제공한다. 사용자 선택 없이 다른 제공자로 자료를 전송하지 않는다. 내부 작업이 외부 MCP 권한을 승격하지 않는다.

대안: 곡별 create_presentation 후 set_playlist는 부분 저장과 기존 항목 ID 손실 때문에 최종 적용에 사용하지 않는다. 클라우드 직접 MCP/터널, 설치된 AI 클라이언트·로컬 모델 연결은 같은 파일·송폼·적용 계약 위에서 별도 어댑터로 검토한다.

결과: REQ-037 / TASK-032 / TC-037 / FLOW-011. [설계](../engineering/PDF와-이미지로-찬양-슬라이드와-플레이리스트-준비.md)에 화면·권한·데이터 호환·실패 복구·개발 순서·검증 조건을 기록한다. 여러 AI 선택 방향은 사용자 요청이고, 초기 지원 대상·UI 기본값·제품 한도·보존 기간은 설계 제안이다. 기능 구현과 합성 자료의 격리 검증을 완료했다. [검증 기록](../quality/2026-10-07-AI-찬양-준비-구현-검증.md)을 따른다. 실제 API 가사·송폼 품질 및 장비 수용 검사는 대기다.

## ADR-015 예배별 콘티 사본과 명시적 원곡 반영

상태: 구현 적용 · 날짜: 2026-10-06 · 근거: 사용자가 “각 콘티에 그때의 곡 구성을 보존하고, 찬양 목록의 원곡 갱신은 별도 선택” 방향으로 진행을 승인함.

결정: 콘티 보관함을 추가하고 각 콘티의 곡을 원곡과 다른 ID로 저장한다. 콘티 편집은 해당 사본에만 자동 저장하며 다른 콘티나 원곡 변경을 전파하지 않는다. 원곡 반영은 본문 확인과 버전 비교를 거친 별도 동작이다. 곡/콘티를 삭제해도 사본은 보존하며 콘티는 휴지통에서 복원한다. 열기·복제·생성은 현재 선택/송출을 바꾸지 않는다. 콘티 사본은 저장한 스타일을 사용하고 원곡의 기본 프리셋 정책은 유지한다.

기존 현재 순서는 현재 콘티로 보관한다. workspace-v2.json에 원곡/보관함/사본/현재 순서를 저장하며 v1 원본은 보존한다. 사본과 활성 순서의 참조 일관성 및 원자 저장을 검사한다. 파일은 선택 이름/날짜를 포함하고 불러오기를 새 콘티로 보관한다. 전체 백업에는 보관함·사본·휴지통을 포함한다. ADR-013의 파일 우선 범위를 확장하며 원곡 참조만으로 과거 콘티를 표시하던 정책을 대체한다.

결과: REQ-038 / TASK-033 / TC-038 / FLOW-012. [설계](../engineering/콘티-보관함과-예배별-곡-사본.md), [운영 안내](../operations/예배별-콘티-보관-편집.md), [검증](../quality/2026-10-06-콘티-보관함-검증-기록.md)을 연결한다. AI 파일 준비 TASK-032의 설계·기능 완료를 대신하지 않는다.

## ADR-019 무료 다운로드와 수동 앱 교체

2026-10-16 · 사용자 요청으로 ADR-017 자동 설치 결정을 대체한다. Apple 유료 멤버십 없이 HTTPS JSON으로 정식 버전을 확인하고 Main이 검증한 DMG URL을 기본 브라우저로 연다. 자동 설치/재시작과 Squirrel 의존성을 제거하고 다운로드 전달만 표시한다. 공개 GitHub Releases를 기본 feed로 쓰고 unsigned 파일 준비와 실제 게시를 구분한다. [설계](../engineering/프로프리-앱-업데이트-설계.md).
