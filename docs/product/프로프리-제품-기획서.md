# 프로프리 제품 기획서


작성일: 2026-10-04 · 갱신: 2026-10-16 · 상태: 현행 구현 기준 / 현장 수용 대기 · 현황 근거: [전체 검토](../review/프로프리-전체-검토-보고서.md)

## 제품 정의

ProPre는 예배와 강연을 준비하는 운영자가 가사·성경·미디어를 한 순서로 구성하고, 청중 화면과 무대 모니터를 제어하는 데스크톱 앱이다. 핵심 목표는 **오프라인 현장에서 준비한 내용을 잃지 않고, 운영자가 의도한 내용과 화면 상태를 일관되게 송출하는 것**이다.

현재 Electron·React 기반 기능이 상당 부분 구현되어 있다. 초기 안정화에 이어 콘티 보관함·AI 파일 준비·웹/PDF·업데이트·예배 운영 7개 기능을 로컬 구현했다. 제품 범위와 미검증 영역을 아래에서 구분한다.

## 대상 사용자와 해결할 문제

| 사용자 가설 | 수행하는 일 | 현재 어려움 | 제공할 가치 |
| --- | --- | --- | --- |
| 예배 송출 운영자 | 순서대로 가사·말씀·배경 전환 | 편집 상태와 실제 송출 상태를 구분하기 어려움 | 현재 송출과 다음 행동을 계속 확인 |
| 자료 준비 담당자 | 기존 곡 재사용, 내용 수정, 성경 추가 | 검색·가져오기 시 다른 발표와 내용이 섞일 위험 | 자료의 정체성, 저장 상태, 복구 보장 |
| 찬양 인도자·강연자 | 현재·다음 내용 확인 | 무대 화면이 편집·재정렬을 즉시 반영하지 않을 수 있음 | 청중 화면과 일치하는 현재·다음 안내 |
| 장비 관리 담당자 | 화면 연결, 설치, 백업·복구 | 설치·이동·모니터 재연결 검증이 없음 | 반복 가능한 사전 점검과 복원 절차 |

사용자 가설은 인터뷰로 검증하지 않았다. 실제 장비, 운영 규모, 초보자·숙련자 비율은 [미결 질문](../governance/위험-가정-미결-질문.md)에 기록한다.

## 초기 개발 방향 비교 (선택 배경)

| 방향 | 주요 투자 | 장점 | 제약 | 권고 |
| --- | --- | --- | --- | --- |
| A. 기존 흐름 안정화 | 저장·복구, 송출 동기화, 화면 상태, 기본 QA | 현재 사용 흐름의 실패를 먼저 줄임 | 고급 기능 확장은 뒤로 감 | 우선 추진 제안 |
| B. 편집 엔진 중심 재구성 | 요소 모델, 캔버스, 스타일 통합 | 편집·렌더링의 일관성 개선 | 마이그레이션 동안 데이터·라이브 위험 관리 필요 | A의 기반 위에서 단계 적용 |
| C. 출력 기능 확대 | 동시 여러 출력, 화면별 스타일, 타이머 | 다양한 방송 환경 대응 | 검증할 상태·장비 조합이 크게 증가 | 첫 안정화 범위 이후 별도 결정 |

클라우드 협업, 계정·권한 서비스, 결제, 원격 조종, 방송 장치 연동을 이번 안정화 범위에 새로 넣지 않는다. 이러한 기능의 부재를 현재 제품의 결함으로 판단하지 않는다.

## 초기 안정화 범위와 현재 확장

- **자료 관리:** 발표별 ID·제목·콘텐츠를 일관되게 유지하고 미저장 상태·저장 실패·복구를 제공한다.
- **현장 송출:** Main Output과 Stage를 대상으로 명시적인 송출, 레이어 지우기, 창 재연결·초기 상태 전달을 안정화한다.
- **가사·성경:** 기존 내용과 요소 기반 내용을 하나의 편집 의미로 통합하고 검색 오류가 현재 자료를 덮지 않게 한다.
- **미디어:** 이미지·영상·오디오를 구분하고 누락 파일을 찾고 다시 연결할 수 있게 한다.
- **준비 보조 AI:** 선택 기능으로 유지한다. 전송 안내, 검토, 취소, 실패 복귀를 갖추며 네트워크 실패가 기본 송출을 막지 않게 한다.
- **품질·릴리즈:** 반복 가능한 테스트, 안전한 IPC·미디어 접근, 설치·복원·실장비 리허설 증거를 갖춘다.

macOS를 먼저 검증하고 Windows를 후속 검증하는 계획을 제안한다. 지원 OS·CPU·해상도는 아직 확정하지 않았고 현재 코드의 크로스 플랫폼 지향을 실제 지원 보증으로 표현하지 않는다.

## 현재 사용자 행동 정책

| 행동 | 현재 정책 | 근거 |
| --- | --- | --- |
| 슬라이드 클릭·편집 | 일반 클릭은 즉시 송출, 활성 본문 편집은 메인·무대에 함께 반영 | ADR-008 |
| 새 자료·성경 탭 검색 | 새 ID로 이전 자료 보존, 활성 본문 해제 후 운영자가 검토·송출 | REQ-006 |
| 전체 중지 | 화면 레이어·웹/PDF·오디오·일시 무대 안내·타이머를 중지 | ADR-008, WSP 공통 계약 |
| 저장·종료 | 자료는 자동 저장, 전체 순서의 상세 입력은 명시 저장, 실패 시 입력과 복구 기록 유지 | 데이터 계약·예배 사용 안내 |
| 재시작 | 자료·설정 복원, 본문/소리 자동 재생 없음, 예배 실행은 중단 상태 복구 | ADR-008, WSP 공통 계약 |
| 콘티와 원곡 | 독립 사본, 원곡 반영은 별도 확인 | ADR-015 |
| 전체 순서·구간 | 선택·준비와 실제 송출 구분, 순서 진행과 무대 안내는 명시 실행 | 예배 상세 설계 |

[결정 기록](../governance/결정-기록.md), [데이터 계약](../engineering/데이터-저장-IPC-계약.md), [예배 운영 안내](../operations/예배-전체-순서-사용-안내.md)가 상세 기준이다. 초기 개발 방향 비교는 당시 선택의 배경이며, 동시 다중 출력·원격 제어·클라우드 협업은 별도 범위다.

## 성공 기준과 측정 계획

| 목표 | 수용 기준안 | 측정 방식 | 현재 기준값 |
| --- | --- | --- | --- |
| 자료 보존 | 발표 전환·가져오기·실패·재시작 시 원본이 의도 없이 덮이지 않음 | 합성 자료 저장·재열기 비교 | 당시 결함 수정·로컬 회귀 기록 있음 / 실제 자료 수용 별도 |
| 상태 일치 | 같은 송출 버전에 대해 Output·Stage·미리보기 내용과 지우기 범위 일치 | 상태 수신 기록 + 네이티브·실장비 확인 | 중앙 발행·ready/applied 로컬 회귀 기록 있음 / 물리 장비 별도 |
| 기본 오프라인 운영 | AI를 사용하지 않는 전체 예배 흐름을 네트워크 없이 완료 | 비행기 모드 리허설 | 미실행 |
| 장비 복구 | 모니터 제거·재연결 시 상태가 명확하고 의도한 화면으로 복구 | 실제 2·3화면 장비 검사 | 미실행 |
| 사용성 | 준비·현재 송출·다음 슬라이드·미저장 상태를 문구로 구분 | 운영자 과제 수행 관찰 | 사용자 검사 미실행 |
| 반응성 | 슬라이드 변경부터 실제 표시까지 지연을 기록하고 허용치 결정 | 지정 장비에서 반복 측정 | 측정 장비·허용치 미정 |

사용성 수치, 시장 규모, 가격, 개발 소요 기간은 조사하지 않았다. 수익화·구매 효과를 가정한 목표를 이번 문서에 확정 값으로 넣지 않는다.

## 산출물과 완료 정의

기획 완료는 목표·범위·대안·수용 기준이 기록된 상태다. 개발 완료는 [백로그](../delivery/개발-작업-백로그.md)의 해당 작업 완료 조건을 충족한 상태다. 운영 투입 가능 여부는 [릴리즈 기준](../operations/릴리즈-운영-투입-기준.md)의 별도 증거로 판단한다.

다음 실행 단위는 [로드맵의 M2](../delivery/개발-로드맵.md) 실제 장비·운영자·서명 설치·백업 복원·인쇄·장시간 수용이다. 로컬 구현 상태와 증거는 [구현 현황](../review/구현-자산-문서-현황.md)에서 확인한다.
